# 바람의 항로 · Windward

실제 세계지도에서 항해하고 특산물을 거래하며 지리를 익히는 한국어 게임. 각자의 진행을 유지하면서 다른 선장의 배를 실시간으로 볼 수 있습니다.

## 실행

Node.js가 설치된 환경에서 이 폴더를 열고 `npm run dev`를 실행한 뒤, http://127.0.0.1:4173 에 접속하세요. `dist/index.html`을 파일로 바로 열면 지도 데이터 fetch가 차단되므로 HTTP 서버가 필요합니다. 별도 npm 패키지 설치는 필요하지 않습니다. 함께 항해·채팅은 인터넷 연결과 공식 Firebase SDK를 사용합니다.

배포용 단일 파일은 `node tools/make-offline.mjs <절대경로.html>`로 생성합니다. 생성한 HTML은 지도와 프로그램을 모두 포함하므로 브라우저에서 파일을 열어 바로 플레이할 수 있습니다. 별도 설치나 네트워크 연결이 필요하지 않습니다.

## 플레이

- 리스본에서 와인을 구매 → 지도에서 세비야 선택 → 출항 → 도착 후 판매.
- 자동 항해: 항구 또는 바다 클릭으로 항로 지정 → 출항. 육지를 피해 목적지로 이동합니다.
- 직접 조종: 바다 클릭으로 그 지점을 향해 이동하거나, 키보드 방향키 / 화면 방향 버튼을 누르는 동안 조종합니다. 해안에 닿으면 멈추고 항구 가까이 접근하면 입항합니다. 방향키를 놓으면 멈추며, 클릭 이동은 ■ / 스페이스로 정지합니다.
- 기본 화면은 배 주변의 **고정 배율 평면 해도**입니다. 확대·축소 기능이 없으며, 드래그로 주변을 둘러볼 수 있습니다.
- 지구본 미니맵에 배와 현재 해도 영역이 표시됩니다. 지구본 드래그로 회전, 클릭으로 해당 지역 해도 보기, ‘내 배 ↗’로 배 추적 화면에 복귀합니다. 지구본에 키보드 초점이 있을 때 방향키는 지구본 회전, Enter는 내 배 보기입니다.
- 스페이스: 자동 항해 일시 정지 / 직접 조종 정지. 1 / 2 / 4: 배속. 창을 벗어나거나 대화창을 열면 항해가 멈춥니다. 강에서는 애니메이션과 직접 조종 이동을 천천히 진행하여 좁은 수로를 따라가기 쉽게 했습니다. 식량은 실제 이동 거리와 게임 내 날짜를 기준으로 소모됩니다.
- ‘선박 · 보급’ 탭에서 식량 보충과 선박 개량. 식량은 바다에서만 소모됩니다.
- 새 항구 보상, 항구별 지리 퀴즈, 네 가지 의뢰. 전 세계 **64개 항구**, 그중 강 항구 **18개**. ‘발견 도감’에서 항구·국가·강 이름을 검색하거나 강 항구만 표시할 수 있습니다.
- 자동 저장은 현재 브라우저의 localStorage에 보관됩니다. 기기 간 동기화는 하지 않습니다.
- 웹에서는 Firebase에 자동 게스트 접속하여 다른 선장의 배와 이름을 해도·지구본에 표시합니다. 오른쪽 위 ‘함께 항해’에서 선장 이름을 바꾸거나 ‘혼자 항해하기’를 선택할 수 있습니다. 별도 회원가입은 필요하지 않습니다.
- ‘?’의 새 항해 메뉴에서 확인 후 초기화할 수 있습니다.

## 검증

`npm test`: 교역 수익, 비용 기준, 부정 수량 차단, 저장 복구, 전체 항구 연결, 아프리카 우회 항로, 날짜변경선 항로, 직접 조종 방향과 속도, 해안 충돌, 조종 모드 저장 검증.

추가로 64개 항구의 연결, 내륙 항구 왕복, 강 굴곡과 강둑 충돌, 기존 세비야 저장의 부두 위치 이관, 지구본 투영·날짜변경선·뒷면 처리를 검사합니다. 기존 저장의 돈·화물·발견 기록을 유지하며, 정박 중인 세비야·런던은 같은 도시의 갱신된 강 선착장으로 위치를 맞춥니다. 항해 중 저장은 기존 경로를 이어갑니다.

## 함께 항해 / Firebase

- 프로젝트 `windward-voyage`, Spark 무료 요금제, Realtime Database 싱가포르 지역. 유료 요금제·결제 계정·Google 애널리틱스는 사용하지 않습니다. 웹 호스팅 주소는 기존 공개 Sites 주소를 유지합니다.
- `dist/firebase-config.js`는 공개 웹 앱 설정입니다. 관리자 키·서비스 계정·비밀 토큰을 넣지 않습니다. Firebase JS SDK 12.4.0을 공식 CDN에서 필요할 때만 읽습니다. 인터넷 연결이 안 되면 개인 항해는 계속할 수 있습니다. 단일 HTML을 파일로 열면 기본적으로 혼자 항해합니다.
- 게스트 인증은 탭마다 메모리에만 보관하여 두 창을 열어도 각자 다른 배가 됩니다. 게임 저장은 기존 localStorage 그대로이며, 같은 브라우저의 두 탭은 개인 저장을 공유하므로 별도 플레이 기록을 유지하려면 다른 브라우저·기기를 쓰세요.
- `fleet/v1/<게스트 uid>`에 선장 이름(최대 16자), 게임 속 경도·위도, 방향, 색상, 정박·항해·멈춤 상태와 서버 시각을 기록합니다. 이름에 실명이나 연락처를 넣을 필요가 없습니다. 순위용 보유 금액·무역 이익·발견 항구 수를 함께 전송하며, 화물·의뢰·발견한 항구 목록 등 상세 진행은 전송하지 않습니다.
- 움직이는 배는 약 1.5초마다 갱신하고 그 사이를 부드럽게 연결합니다. 정박·정지는 30초마다 접속을 확인합니다. 90초 넘게 갱신되지 않은 배는 숨기며, 접속 종료 시 Firebase의 `onDisconnect`로 배 기록을 지웁니다. 자신을 포함하여 최대 30척을 표시합니다. 실제 무료 이용 규모는 접속 시간과 전송량에 따라 달라집니다.
- `firebase.database.rules.json`은 콘솔에 게시한 규칙 원본입니다. 인증된 게스트는 갱신 시각 기준 최대 100개 조회만 가능하며 자기 uid의 배만 수정할 수 있습니다. 좌표·이름·필드·서버 시각을 검증합니다. 클라이언트 위치와 기록을 공유하는 초기 버전이므로 치트 방지·서버 판정·공유 경제는 구현하지 않았습니다. 순위에 따른 보상이나 승패는 없으며, 접속 중인 선장의 기록을 비교하는 표시입니다.
- `npm test`는 공유 위치 유효성·오래된 배 숨기기·날짜변경선 보간을 포함한 규칙 검증입니다. `npm run test:firebase`는 실제 Firebase에 임시 게스트 두 명을 만들고 자기 배 쓰기, 상대 배 조회, 타인 덮어쓰기 거부, 좌표 검증, 비인증·무제한 조회 차단을 검사한 뒤 그 테스트 배와 게스트만 정리합니다.
- [Firebase 웹 설정](https://firebase.google.com/docs/web/setup), [게스트 인증](https://firebase.google.com/docs/auth/web/anonymous-auth), [접속 상태와 자동 정리](https://firebase.google.com/docs/database/web/offline-capabilities), [보안 규칙](https://firebase.google.com/docs/database/security), [무료 요금 한도](https://firebase.google.com/pricing).

## 채팅과 현재 랭킹

- 화면 아래 ‘선장 채팅’으로 창을 열고 닫습니다. 휴대폰에서는 버튼을 화면 왼쪽 아래에 고정합니다. Enter로 전송, Shift+Enter로 줄바꿈, Escape로 닫습니다. 입력 중 방향키·숫자·스페이스는 배를 조종하지 않습니다. 새 메시지 수를 버튼에 표시합니다.
- 최근 **50개**만 보관합니다. `chat/v1/messages/0..49`의 고정된 자리를 순환하여 가장 오래된 글의 본문을 새 글로 덮어씁니다. 화면에서만 숨기거나 별도 전체 기록을 보관하지 않습니다. 처음에는 최근 50개, 이후에는 바뀐 메시지만 실시간 수신합니다. 사진·파일 첨부는 지원하지 않습니다.
- 글은 **200자**, 같은 게스트는 **3초에 한 번** 전송할 수 있습니다. 서버 규칙도 길이·작성자 uid·서버 시각·전송 간격을 검증합니다. 동시에 보내면 순번을 비교해 충돌한 쪽이 최신 순번으로 다시 시도합니다. 실패하면 입력 글을 유지합니다.
- 전송 간격 확인용 uid별 시각은 본문과 별도이며, 하루가 지난 항목만 정리할 수 있습니다. 실제 클라이언트는 이틀 지난 항목을 최대 20개 찾아 다음 정상 전송과 함께 정리합니다. Cloud Functions나 유료 서버는 추가하지 않습니다.
- 왼쪽 순위판에서 **무역 이익 / 지금 가진 돈 / 발견 항구**를 누르면 각 기준 상위 5명과 내 순위가 나옵니다. 현재 접속 중인 선장만 비교하며 동점은 공동 순위입니다. 이름은 동점 표시 순서를 정하는 데만 사용합니다. 최대 100명의 접속 정보를 비교하고, 해도의 배는 기존처럼 최대 30척을 표시합니다.
- 예전 화면을 계속 열어 둔 선장은 순위 숫자를 아직 보내지 않으므로 새로고침 후 참여합니다. 게임 저장·돈·화물·발견 기록은 초기화하지 않습니다. 순위는 클라이언트가 보낸 수치를 표시하며 서버 판정이나 치트 방지 경쟁 시스템은 아닙니다.
- 채팅과 배 위치는 같은 Spark 무료 한도를 공유합니다. 50개 제한은 보관량을 제한하며, 이미 사용한 전송량은 되돌리지 않습니다. 유료 전환이나 결제 정보 등록은 하지 않습니다.

### 격리 검증

`npm test`: 기존 게임 검증과 채팅 최근 50개·문자 제한·순위 3종·동점 처리를 검사합니다.

`npm run test:rules`: 127.0.0.1:9000의 공식 Realtime Database 에뮬레이터에서 50개 실물 보관, 200자 제한, 3초 서버 제한, 타인 사칭·삭제 차단, 동시 전송 충돌과 재시도, 순위 필드 소유권을 검사합니다. 외부 서버 주소는 거부하며 실제 게임 대화를 건드리지 않습니다.

개발 화면에서만 `http://127.0.0.1:4173/?localTest=1`로 접속하면 같은 격리 서버를 씁니다. 로컬 호스트에서만 동작하고 Firebase 가입·실제 데이터 변경을 하지 않습니다. 일반 접속과 공개 주소는 실제 Firebase를 사용합니다.

이 작업의 검증 환경은 Temurin JRE 21과 공식 Firebase Database Emulator 4.11.2입니다. [Firebase 에뮬레이터 안내](https://firebase.google.com/docs/emulator-suite/install_and_configure)에 따라 Java와 에뮬레이터를 준비한 뒤 실행합니다. 현재 PC에는 `C:/Users/codex/.cache/windward-firebase-tests/`에 체크섬을 확인한 실행 파일이 있습니다. 예: `java -jar firebase-database-emulator-v4.11.2.jar --host 127.0.0.1 --port 9000`.

## 내륙 항해

| 강 / 수계 | 게임에 연결된 대표 구간 |
| --- | --- |
| 과달키비르강 | 대서양 → 산루카르 → 세비야 |
| 템스강 | 북해 → 런던 |
| 가론강·지롱드강 하구 | 비스케이만 → 보르도 |
| 라인강 하구 수계 | 북해 → 로테르담 → 쾰른 |
| 다뉴브강 | 흑해 → 루세 → 베오그라드 |
| 나일강 | 지중해 → 카이로 → 룩소르 |
| 아마존강 수계 | 대서양 → 마카파 → 산타렝 → 마나우스 부근 |
| 미시시피강 | 멕시코만 → 뉴올리언스 → 멤피스 |
| 양쯔강 | 동중국해 → 상하이 → 난징 → 우한 |

자동 항해는 강 중심선을 따라 굴곡을 통과합니다. 직접 조종에서 같은 강의 지점을 클릭하면 굽이를 따라 이동하고, 방향키로는 선장이 직접 조종합니다. 강 주변 육지는 통과할 수 없습니다. 강 전체의 현실적인 가항 구간·수심·수문·역사적 제한을 재현하지 않으며, 위 표의 대표 구간을 게임 항로로 제공합니다.

## 지도 / 설정

[Natural Earth](https://www.naturalearthdata.com/) 퍼블릭 도메인 1:110m 해안선·국가 경계. 원본은 [Natural Earth vector](https://github.com/nvkelso/natural-earth-vector)의 GeoJSON입니다. `python tools/build-map.py`로 0.5도 간격의 항해용 육지 마스크를 재생성합니다. A* 바다 항로와 시야선 평활화를 사용합니다. 항구 입출항 연결과 좁은 해협은 단순화되어 있어 실제 항해에 사용할 수 없습니다.

강 중심선은 [Natural Earth 1:10m rivers + lake centerlines](https://www.naturalearthdata.com/downloads/10m-physical-vectors/10m-rivers-lake-centerlines/), 도시 좌표는 [Natural Earth 1:10m populated places](https://www.naturalearthdata.com/downloads/10m-cultural-vectors/10m-populated-places/)를 사용합니다. `python tools/build-waterways.py`로 `dist/assets/rivers.json`과 `dist/harbors.js`를 재생성합니다. 필요한 원본 GeoJSON은 `tools/source-data/`에 캐시하며 Git에는 포함하지 않습니다.

강이 넓어 중심선 자료가 끊긴 하구는 생성 도구에 기록한 대표 지점으로 연결합니다. 강폭은 조작 편의를 위해 넓혔으며, 강 항구의 선착장은 도시 좌표에서 가까운 게임용 강 중심선에 배치합니다. 원래 도시 좌표도 `city` 필드로 보관합니다. 아테네는 피레아스, 퍼스는 프리맨틀 해안의 선착장을 사용합니다. 항구 상품과 가격은 게임 설정입니다.

세비야의 내륙 항구와 과달키비르강 접근은 [세비야 항만청의 항로 안내](https://www.puertodesevilla.com/via-navegable/navegacion)를 참고했습니다. 지구본은 동일 지리 자료를 정사영으로 표시하며, 외부 지도·3D 서비스에 의존하지 않습니다.

1522년이라는 가상 항해 배경에 현재 국가명을 함께 사용합니다. 무역품, 가격, 보급량, 배 속도는 게임용 설정입니다. 실제 역사 시뮬레이션은 아닙니다. 글꼴은 Google Fonts의 Noto Sans KR / Gowun Batang을 사용하며, 연결되지 않으면 시스템 글꼴로 표시됩니다.
