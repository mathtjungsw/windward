# 바람의 항로 · Windward

실제 세계지도에서 항해하고, 항구를 발견하고, 특산물을 거래하는 한국어 게임입니다.

## 실행과 배포

- `npm run dev` → http://127.0.0.1:4173 . 별도 npm 패키지 설치가 필요하지 않습니다.
- 공개 주소: https://windward-traders-atlas-kr.jsw890122.chatgpt.site
- 원본 소스는 `dist/`입니다. Sites의 기존 프로젝트와 공개 대상을 유지합니다.
- 단일 HTML: `node tools/make-offline.mjs <출력 HTML 절대경로>`. 지도·프로그램·스타일이 포함되어 파일로 열어 개인 항해를 할 수 있습니다. 이름+숫자 계정의 서버 저장과 함께 항해·채팅은 인터넷이 필요합니다.

## 시작과 저장

- 테스트 기간에는 **선장 이름 + 숫자 6자리 비밀번호**로 새로하기/이어하기를 제공합니다. 앞자리 0도 유지합니다. 이름은 1~16자로, 공백 앞뒤 제거·유니코드 NFKC 정규화·대소문자 구분 없는 중복 검사를 적용합니다.
- 화면에서 실제 이메일·Google 가입을 요구하지 않습니다. 내부적으로 정규화한 이름의 SHA-256으로 합성 식별 주소를 만들고, Firebase의 기존 비밀번호 인증 기능에 연결합니다. 비밀번호의 원문이나 검증 해시를 데이터베이스·브라우저 저장소에 저장하지 않습니다. 이름 식별 해시는 비밀번호 해시가 아닙니다. 정식 서비스의 Google/이메일 인증 화면과 복구 정책은 추후 전환 대상입니다.
- 숫자 6자리는 테스트용입니다. 분실 시 현재는 복구 기능이 없으며 새 이름으로 시작할 수 있습니다. Firebase의 서버 검증과 시도 제한을 사용하지만 정식 서비스 수준의 계정 보호를 보장하지 않습니다.
- 계정은 두 세계에 공통이며, **진행·채팅·랭킹은 세계마다 별도**입니다. 평화서버는 1·2·4배속, 현실서버는 현재 게임의 1배속으로 고정합니다. 현실의 24시간과 게임 하루를 같게 만든 기능이나 오프라인 자동 항해는 아닙니다.
- 계정 진행은 해당 uid만 읽고 수정할 수 있는 서버 경로와 현재 기기에 저장됩니다. 기기 저장은 약 1.5~1.8초 간격 및 거래·입항 등에 갱신하며, 서버에는 약 15~20초 간격으로 묶어 저장합니다. 접속 화면으로 돌아갈 때도 저장합니다.
- 저장 버전과 활성 세션을 확인합니다. 다른 기기에서 사용 중이면 명시적으로 여기서 이어하기를 선택해야 하며, 이전 화면은 항해·저장을 멈춥니다. 미전송 기기 기록과 서버 기록이 다르면 조용히 덮어쓰지 않고 기기 기록을 별도 백업한 뒤 서버 기록을 선택할 수 있습니다.
- 기존 `windward-save-v1`은 `windward-legacy-backup-v2`에도 보존합니다. 계정으로 처음 시작할 때 기존 기록을 평화서버로 가져올 수 있습니다. 현실서버는 별도의 새 항해입니다. 방문·돈·화물·의뢰·항해 중 목적지를 유지하며, 과거 방문 항구와 현재 목적지는 개방 목록에 포함합니다. 저장되지 않은 과거 이동 궤적은 복원할 수 없어 방문한 항구와 현재 위치 주변부터 탐험 지도를 구성합니다.
- ‘계정 없이 혼자 항해’는 기존 브라우저 저장을 사용합니다. ‘함께 항해 연결’을 선택한 계정은 위치와 순위 요약을 공유합니다. 공유를 끈 계정도 비공개 진행은 서버에 저장하며, 함께 항해를 켜면 공개 순위에 참여합니다.

## 항해와 탐험

- 고정 배율의 **평면 해도**를 사용하며 확대·축소하지 않습니다. 드래그로 둘러보고 내 배 버튼으로 돌아옵니다. 별도의 **지구본 미니맵**은 드래그·방향키로 회전하고, 클릭한 지역의 해도를 볼 수 있습니다.
- 자동 항해: 알고 있는 항구 또는 바다를 선택 → 출항. 육지를 피해 항로를 찾고 강에서는 중심선을 따라갑니다.
- 직접 조종: 바다 클릭 또는 방향키 / 화면 방향 버튼. 방향키를 놓으면 정지하고 클릭 이동은 ■/스페이스로 정지합니다. 좁은 강에서는 천천히 움직입니다. 배 그림은 똑바로 유지하고 화살표로 진행 방향을 나타냅니다.
- **지도의 북쪽 끝과 남쪽 끝을 연결합니다.** 직접 조종으로 북위 80도 경계를 넘으면 남위 60도 쪽에서 이어지고, 반대 방향도 같습니다. 지도 드래그도 경계에서 막히지 않고 이어집니다. 바다 구간을 통과할 때 연결되며 실제 육지 충돌 검사는 유지합니다. 자동 항해의 항구 간 경로는 기존 해양·강 항로를 사용합니다.
- 경계 이동은 실제 움직인 거리만 시간·식량에 반영합니다. 통과 구간을 둘로 나누어 대륙을 가로지른 발견·입항으로 처리하지 않습니다. 시야·탐험 기록·주변 배 수신·다른 배의 이동 표시도 연결된 경계를 반영합니다. 이 연결은 게임 규칙이며 실제 지리의 극지방 연결을 재현한 것은 아닙니다.
- 직접 조종 입항은 이동 전후 **구간**과 부두까지의 최단 거리를 검사합니다. 해상 6해리/강 3해리 이내에서 같은 수로·육지 충돌을 확인하며, 출항 직후 같은 항구로 즉시 재입항하지 않도록 제외합니다.
- 초기 개방 항구: 리스본·포르투·산루카르·세비야. 미개방 항구에 **40해리 이내**로 접근하면 정보를 얻습니다. 개방은 실제 방문과 구분하며 방문 보상·의뢰·탐험 순위는 입항 기준입니다.
- 입항한 항구의 **주점 → 정보 얻기**에서 **100 D**를 내고 **600해리 이내**의 가장 가까운 미개방 항구 1곳을 개방합니다. 후보가 없거나 돈이 부족하면 차감하지 않습니다. 개방한 항구만 도감·지도·자동 항해 목적지에 나타납니다.
- 내 배 중심 **180해리**가 현재 시야입니다. 미탐험은 청회색 안개, 탐험했지만 시야 밖은 연한 회색, 현재 시야는 밝게 표시합니다. 평면 지도와 지구본은 같은 탐험 기록을 사용합니다. 다른 선장의 배는 현재 시야 안에서만 최대 29척 표시합니다.
- 전체 64개 항구, 그중 18개 강 항구와 9개 수계는 아래 표를 참고하세요. 퀴즈·교역·보급·선박 개량·네 가지 의뢰를 유지합니다.

## 화면·채팅·랭킹

- 항해 조작·내 항해 정보·랭킹·의뢰·항구 정보·지구본·채팅은 **기본으로 열린 상태**입니다. 제목줄 ‘− 접기’는 본문을 숨기며 ‘+ 펼치기’로 다시 엽니다. 모바일에서는 지도 아래에 펼쳐진 창들을 배치하고 세로로 스크롤합니다.
- 위쪽 **접속 선장 · N명**은 같은 세계에서 함께 항해에 연결된 전체 선장 수이며 나를 포함합니다. 버튼을 누르면 거리에 관계없이 모든 이름과 항해 상태가 나옵니다. 명단은 스크롤할 수 있고 29척의 지도 표시 제한을 적용하지 않습니다. 지도·지구본에 보이는 다른 배만 **내 시야 180해리**로 제한합니다. 혼자 항해를 선택해 공유를 끈 선장은 명단에 참여하지 않습니다.
- 채팅을 펼치면 최근 **50개**, 접으면 별도 미리보기로 최근 **최대 5개**를 표시합니다. 최신 글은 아래쪽, 목록은 스크롤할 수 있습니다. Enter 전송/Shift+Enter 줄바꿈/Escape 접기. 입력 중에는 배를 조종하지 않습니다.
- 세계마다 `messages/0..49`의 고정 자리를 순환하며 가장 오래된 본문을 덮어씁니다. 별도 전체 대화 이력은 남기지 않습니다. 200자·3초 간격을 화면과 서버에서 검사합니다. 동시 전송 충돌은 순번을 다시 확인해 재시도하며 실패 시 입력을 유지합니다.
- 공개 순위는 **무역 이익 / 지금 가진 돈 / 방문한 항구**의 세 기준이며 각 상위 5명만 구독합니다. 계정이 접속을 종료해도 기록이 남습니다. 동점은 공동 순위입니다. 상위 밖의 정확한 내 순위는 ‘내 순위 조회’를 눌렀을 때 1,000명씩 제한 조회해 계산합니다. 조회 중 다른 사람 기록이 변하면 순위가 바뀔 수 있습니다.
- 업데이트마다 `dist/app.js`의 `RELEASE`와 안내 내용을 갱신합니다. 계정에서 확인을 누른 버전은 서버에 기록해 다시 표시하지 않습니다. 나중에/닫기는 읽음으로 기록하지 않습니다.

## Firebase와 무료 운영

프로젝트 `windward-voyage`, Realtime Database 싱가포르, **Spark 무료 요금제**를 유지합니다. 결제 정보·유료 서버·Cloud Functions·애널리틱스를 추가하지 않습니다. `dist/firebase-config.js`는 공개 웹 설정이며 관리자 키를 넣지 않습니다. SDK는 공식 CDN의 12.4.0을 필요할 때 로드합니다.

```text
accounts/{uid}                            이름, 업데이트 확인 버전
privateSaves/{uid}/{peace|real}            비공개 진행 JSON, 저장 버전, 활성 세션
worlds/{peace|real}/sectors/{sector}/{boat} 주변 해역의 접속 배 (종료 시 삭제)
worlds/{peace|real}/captains/{session}     전체 접속 이름·상태 (좌표 없음, 종료 시 삭제)
worlds/{peace|real}/rankings/{uid}          종료 후에도 남는 공개 순위 요약
worlds/{peace|real}/chat/...                해당 세계의 최근 대화 50개
```

- 진행은 JSON 문자열로 보관해 Firebase에서 빈 화물창 등의 빈 객체가 사라지는 문제를 방지합니다. 게임의 돈·화물·탐험 지도는 다른 uid에게 읽기를 허용하지 않습니다.
- 위치는 항해 중 약 1.5초, 변화 없는 정박·정지는 30초 간격입니다. 10도 해역 중 현재 시야와 겹치는 주변 구역만 구독합니다. 구역당 갱신 시각 기준 최대 100개로 제한하며 90초 이상 갱신되지 않은 배는 숨깁니다. 여러 기기의 같은 계정은 서로 다른 배 접속 키를 사용해 이전 창 종료가 새 창의 배를 지우지 않습니다.
- 전체 선장 명단은 좌표와 별도로 uid·이름·색상·항해 상태·갱신 시각만 공유합니다. 상태가 바뀔 때와 30초마다 갱신하며 종료 시 `onDisconnect`로 제거합니다. 갱신이 끊긴 기록은 90초 후 숨기고 같은 uid의 중복 세션은 하나로 합칩니다. Spark의 동시 연결 범위에 맞춰 명단은 최대 100개의 최근 접속 기록을 조회합니다. 이전 버전을 열어 둔 이용자는 새로고침 후 새 명단에 참여합니다.
- 시야 밖 표시 제한은 클라이언트 표현 규칙입니다. 변조 프로그램의 인접 해역 조회까지 거리별 서버 판정으로 차단하지는 않습니다. 순위 점수도 클라이언트 요약이며 치트 방지 경쟁 서버가 아닙니다.
- 이전 공개 버전이 사용하는 `fleet/v1`, `chat/v1` 규칙과 대화는 보존합니다. 업데이트 후 새 계정·두 세계는 새 경로를 사용합니다. 이미 종료해 삭제된 옛 게스트의 순위는 복원하지 못합니다.
- 채팅 50개 제한은 보관량을 줄이며 이미 쓴 전송량을 없애지 않습니다. 무료 한도는 배 위치·채팅·저장이 함께 사용합니다. 소규모 테스트를 시작할 수 있으나, 실제 이용 인원·시간에 따른 월 전송량을 측정해야 합니다. 동시 100개 연결 한도가 한 달 100명 무료 운영을 보장하지 않습니다.
- [Firebase 인증](https://firebase.google.com/docs/auth/web/password-auth), [저장·트랜잭션](https://firebase.google.com/docs/database/web/read-and-write), [보안 규칙](https://firebase.google.com/docs/database/security), [요금제](https://firebase.google.com/pricing).

## 검증

- `npm test`: 게임 규칙·저장 이관·항로·강 항해·시야/탐험 복원·주점 정보·숫자 6자리·세션/기기 충돌·통신 실패 기록 보존·구역 조회·채팅·랭킹 검증.
- `npm run test:rules`: 127.0.0.1:9000의 공식 Database Emulator에만 연결해 채팅 보관·동시 전송·간격, 소유권·비공개 저장·저장 버전·세계 분리·접속 종료 후 순위 유지·해역 조회 제한을 검증합니다. 실제 게임 대화를 읽거나 바꾸지 않습니다.
- 에뮬레이터: Temurin JRE 21 + Firebase Database Emulator 4.11.2. 이 PC의 검증 실행 파일은 `C:/Users/codex/.cache/windward-firebase-tests/`에 있습니다. `java -jar firebase-database-emulator-v4.11.2.jar --host 127.0.0.1 --port 9000`으로 실행한 후 규칙 검증을 진행합니다.
- `http://127.0.0.1:4173/__qa/mobile`은 개발 서버에만 있는 너비 390px의 실제 게임 iframe입니다. 공개 배포 파일에는 이 검증 페이지가 포함되지 않습니다. 실제 휴대폰 기기 시험과는 구분합니다.
- `http://127.0.0.1:4173/__qa/wrap`과 `?edge=south`는 각각 경계 근처에서 시작하는 격리 화면입니다. 브라우저 저장을 메모리 대역으로 바꾸어 기존 저장·계정·실제 서버를 건드리지 않고 이동을 시험합니다. 개발 서버 전용이며 배포물에 포함하지 않습니다.
- `npm run test:firebase`는 이전 v1 게스트 위치 공유 규칙의 실제 연결 검증용입니다. 새 계정·세계의 규칙 검증은 에뮬레이터 시험을 사용합니다.

| 라인강 하구 수계 | 북해 → 로테르담 → 쾰른 |
| 다뉴브강 | 흑해 → 루세 → 베오그라드 |
| 나일강 | 지중해 → 카이로 → 룩소르 |
| 아마존강 수계 | 대서양 → 마카파 → 산타렝 → 마나우스 부근 |
| 미시시피강 | 멕시코만 → 뉴올리언스 → 멤피스 |
| 양쯔강 | 동중국해 → 상하이 → 난징 → 우한 |

자동 항해는 강 중심선을 따라 굴곡을 통과합니다. 직접 조종에서 같은 강의 지점을 클릭하면 굽이를 따라 이동하고, 방향키로는 선장이 직접 조종합니다. 강 주변 육지는 통과할 수 없습니다. 강 전체의 현실적인 가항 구간·수심·수문·역사적 제한을 재현하지 않으며, 위 표의 대표 구간을 게임 항로로 제공합니다.

## 지도 / 설정

[Natural Earth](https://www.naturalearthdata.com/) 퍼블릭 도메인 1:110m 해안선·국가 경계. 원본은 [Natural Earth vector](https://github.com/nvkelso/natural-earth-vector)의 GeoJSON입니다. `python tools/build-map.py`로 0.5도 간격의 항해용 육지 마스크를 재생성합니다. A* 바다 항로와 시야선 평활화를 사용합니다. 항구 입출항 연결과 좁은 해협은 단순화되어 있어 실제 항해에 사용할 수 없습니다.

강 중심선은 [Natural Earth 1:10m rivers + lake centerlines](https://www.naturalearthdata.com/downloads/10m-physical-vectors/10m-rivers-lake-centerlines/), 도시 좌표는 [Natural Earth 1:10m populated places](https://www.naturalearthdata.com/downloads/10m-cultural-vectors/10m-populated-places/)를 사용합니다. `python tools/build-waterways.py`로 `dist/assets/rivers.json`과 `dist/harbors.js`를 재생성합니다. 필요한 원본 GeoJSON은 `tools/source-data/`에 캐시하며 Git에는 포함하지 않습니다.

강이 넓어 중심선 자료가 끊긴 하구는 생성 도구에 기록한 대표 지점으로 연결합니다. 강폭은 조작 편의를 위해 넓혔으며, 강 항구의 선착장은 도시 좌표에서 가까운 게임용 강 중심선에 배치합니다. 원래 도시 좌표도 `city` 필드로 보관합니다. 아테네는 피레아스, 퍼스는 프리맨틀 해안의 선착장을 사용합니다. 항구 상품과 가격은 게임 설정입니다.

세비야의 내륙 항구와 과달키비르강 접근은 [세비야 항만청의 항로 안내](https://www.puertodesevilla.com/via-navegable/navegacion)를 참고했습니다. 지구본은 동일 지리 자료를 정사영으로 표시하며, 외부 지도·3D 서비스에 의존하지 않습니다.

1522년이라는 가상 항해 배경에 현재 국가명을 함께 사용합니다. 무역품, 가격, 보급량, 배 속도는 게임용 설정입니다. 실제 역사 시뮬레이션은 아닙니다. 글꼴은 Google Fonts의 Noto Sans KR / Gowun Batang을 사용하며, 연결되지 않으면 시스템 글꼴로 표시됩니다.
