# 바람의 항로 · Windward

실제 세계지도에서 항해하고, 항구를 발견하고, 특산물을 거래하는 한국어 게임입니다.

## 2026-11-12 · 로컬 개발

- PC 상단과 모바일 더보기의 **메뉴 찾기**, **선장 목록 → 선장 상세 → 발견 도감·부선장**, **내 배 보기 → 역사 선박 조선소**에서 신규 화면을 확인합니다. 지도는 소유 항구에 `항구(선장)`을 표시합니다.
- 수집 그림은 `dist/assets/collection/`의 정적 WebP 248개입니다. 필요할 때 Chrome이 있는 개발 환경에서 `node tools/build-collection-art.mjs`로 다시 생성합니다.
- 순위·카드 이관·버튼 통계는 `node tools/update-collection-operations.mjs <ranking|backfill|usage> --emulator`로 격리 환경에서 확인합니다. 기본 실행은 변경 건수만 계산합니다. `--apply`를 추가하면 선택한 환경에 결과를 저장합니다. 이관 작업은 기존 개인 저장을 읽어 공개 요약만 보완합니다.
- 예약 작업은 한국 시각 09:17·21:17에 종합 랭킹과 버튼 사용 합계를 처리합니다. GitHub Actions는 저장소와 메인 브랜치의 집계 워크플로로 제한된 단기 인증을 사용합니다. 집계 계정의 Firebase 권한은 공개 랭킹 읽기, 종합 결과 쓰기, 버튼 통계 관리에 한정됩니다. 원본 버튼 집계는 30일, 일별 합계는 90일 보관합니다. [Google Cloud 연결 설정](https://docs.cloud.google.com/iam/docs/workload-identity-federation-with-deployment-pipelines)
- 이번 배포에서 최소 저장 형식은 8입니다. 기존 저장은 새 버전에서 접속할 때 이어지며, 오래 열린 탭에서 저장 오류가 나면 새로고침해야 합니다.

- 항구의 **내 배 보기**에서 배를 매각할 수 있습니다. 새 유적 6곳·동물 6종·보물 6곳·유물 3곳을 더해 현재 로컬 도감은 60종입니다.
- 공동 수송·보급소·운하, 아이템 64종, 부선장 24명, 항구·해변 상륙을 로컬에서 체험할 수 있습니다. [로컬 실행과 검증 기록](docs/LOCAL_PREVIEW_2026-11-11_RUMORS.md)

## 2026-11-10 · 모바일 지명 가독성

- 메인 지도에서 가까운 지명을 화면 안으로 조정하고, 넓은 바다·지역은 실제 지역 범위 안에 이름을 배치합니다. 안개 위의 진한 14~16px 글자와 밝은 테두리로 표시하며 배·항구와의 겹침을 피합니다.
- 모바일 더보기 → 조작·화면 설정 → 지도 지명 표시에서 켜고 끕니다. 지명 자체는 지리 안내이며, 발견 항구·탐험 점수·시야를 바꾸지 않습니다. 지명 배치의 180ms 간격과 노드 재사용을 유지합니다.
- 지역 범위는 기존 Natural Earth v5.1.2 원본에서 단순화한 장식용 폴리곤입니다. `runpy.run_path('tools/build-chart-assets.py')['build_labels']()`로 이름/지역 범위만 다시 만들 수 있습니다. [검증·배포 기록](docs/UPDATE_2026-11-10_VISIBLE_PLACE_NAMES.md).

## 2026-11-10 · 항해 성능 개선

- 다른 선단의 SVG 노드를 재사용하며 정지 상태의 불필요한 재생성을 줄입니다.

- 선박 성능, 지도 정밀도, 일반 위치 전송 주기와 기존 저장 기록은 유지합니다. [검증·배포 기록](docs/UPDATE_2026-11-10_PERFORMANCE.md).

## 2026-11-10 · 지역 무역·최고가 검색·오프라인 선단

- 화물창 물품의 ‘최고가 판매처 찾기’ 또는 모바일 더보기에서 검색합니다. 전체 항구/알고 있는 항구를 고르고, 보유 수량의 세후 예상 수령액 상위 5곳을 비교합니다. 검색 시각과 **검색 시점의 조회 가격이며 실제 판매 시 바뀔 수 있다는 안내**를 표시합니다. 일부 실패는 전체 최고가로 단정하지 않습니다.
- 조회는 사용자가 검색할 때만 한 번 실행합니다. 선택 상품과 필요한 소유·개별 세율·제한만 읽으며, 캐시를 사용한 과거 가격을 현재 조회처럼 표시하지 않습니다. 미발견 항구의 가격을 봐도 발견·방문·안개 점수는 변하지 않습니다.
- 일반 상품 31종(+한정 4종·호환 향신료), 78개 주요 항구와 개발 후보의 공급·수요를 분리했습니다. 한정 공유 재고는 30상자/현실 2시간당 1상자, 투자 시작 20만/60만 D와 개발 40만/20만/30만 D입니다. 기존 원가·투자·개발 자산은 보존합니다.
- 직접 조종 중 항구를 선택하면 현재 위치에서 자동 출항합니다. 모바일 조종부의 글자 선택·취소·다중 입력을 정리하고, 해적 24곳은 시야 안 지도에서 발견합니다. 토벌 뒤 HP/조작을 지웁니다.
- 오프라인 선단은 UID별 마지막 확인 위치에 남습니다. 모든 실제 정박 항구는 공격 금지입니다. 해상에서는 공격받을 때만 장착 대포의 원래 성능·재장전으로 자동 반격하며, 180초 미격파는 피해를 유지한 무승부입니다.
- 새 전투는 양쪽 장부·보관금·슬롯·본인 영수증을 원자 갱신하고, 본인 재접속 때 결과를 한 번 반영합니다. 저장 봉투 6을 사용하며 게임 데이터는 기존 v4에 선택 필드를 확장했습니다. 구버전의 쓰기는 전환 뒤 차단합니다.
- 정밀 해안선·육상 음영과 한국어 지명 60개를 정적 자료로 제공합니다. 메인 해도의 고정 평면과 두 미니맵은 유지합니다. 지명 표시를 기기 설정에서 끌 수 있습니다.

## 이전 이력: 2026-11-06 전체 선장 뗏목 전환

사용자 최신 결정으로 서버의 기존 선장도 **뗏목 1척으로 한 번 전환**하고 선박 차액을 지급합니다. 차액은 새 20단계 가격표의 누적 개량비 + 현재 단계에서 동행 배를 구입하는 견적(대수별 기본가 + 누적 개량비의 25%)이며, 과거 실제 결제 이력을 복원한 금액은 아닙니다. 이전 시작 배(새 5단계)는 5,200 D입니다. 무역 이익에는 더하지 않습니다. 이후에 새로 개량한 배는 유지됩니다.

기존 화물·방문·지도·수집 기록은 보존합니다. 초과 화물은 삭제하지 않고 판매할 수 있으며, 10일분을 넘는 식량 총량은 전환 전 가격의 보급 크레딧으로 남깁니다. 항해 중 낮아지는 배는 방문했던 항구로 무료 귀환하고 탐험 보상을 차단합니다. 저장 봉투는 v4(게임 데이터 v3)를 사용해 구버전 쓰기를 막습니다. 전환 전 원본은 공개 저장소에 넣지 않는 로컬 백업에 보관했습니다.

실행 도구: `tools/apply-raft-start.mjs --project=windward-voyage --apply`. Firebase CLI 모듈 위치는 `WINDWARD_FIREBASE_TOOLS`로 지정합니다. 적용 생략 시 미리보기만 수행하며, ETag로 동시 저장을 보호하고 전환 표식으로 중복 지급을 막습니다. 이번 변경은 앞선 ‘기존 배 보존’ 결정을 대체하는 사용자 지시입니다.

## 실행과 배포

- `npm run dev` → http://127.0.0.1:4173 . 게임은 정적 파일로 실행합니다. 검증 도구 준비는 `npm ci`를 사용합니다.
- 공개 주소: https://mathtjungsw.github.io/windward/
- 저장소: https://github.com/mathtjungsw/windward
- 원본 소스는 이 저장소의 `dist/`입니다. `main`에 변경을 push하면 `.github/workflows/pages.yml`이 `npm test`를 통과한 후 `dist/`만 GitHub Pages에 자동 배포합니다. GitHub 저장소 Settings → Pages의 Source는 **GitHub Actions**입니다. Node 24와 `npm ci`로 검증 의존성을 설치합니다. 게임 파일을 새로 번들하는 단계는 없습니다.
- 데이터베이스 규칙 배포는 `npx firebase-tools deploy --only database --project windward-voyage`를 사용합니다. GitHub Pages 배포와는 별도입니다.

### 운영 업데이트 점검 절차

1. 배포 전 새 버전을 검증하고, 운영 Firebase 규칙과 점검 설정을 복구할 수 있도록 보관합니다. `dist/maintenance.html`의 안내문을 이번 업데이트에 맞게 갱신합니다. 제목은 ‘업데이트를 위해 서버를 잠시 닫습니다’로 두고, 이번에 개선한 기능과 사용자가 체감할 변경점을 적습니다.
2. 같은 안내문을 `.github/maintenance.html`에 두고 GitHub Pages로 게시합니다. 배포 작업이 게임 소스를 검증한 뒤 안내문을 대문으로 올립니다. 공개 대문에서 안내문이 보이는 것을 확인한 후 Firebase의 `releaseStatus.maintenance`를 켜고, 점검 중에는 운영 게임 접속을 막습니다. 이전에 열어 둔 탭도 게임 데이터를 계속 읽거나 쓰지 못하도록 서버에서 접속을 차단합니다.
3. 점검 중 새 버전과 필요한 데이터 변경을 적용합니다. 새 버전에서는 `.github/maintenance.html`을 제거해 정상 대문을 게시하며, 서버가 점검 중일 때는 게임이 점검 안내를 표시합니다. 공개 주소에서 새 버전 파일과 적용 대상 변경을 확인합니다.
4. 운영 Firebase 규칙을 적용하고 `releaseStatus.maintenance`를 끕니다. 공개 대문에서 게임 입장 화면이 다시 표시되는지와 서버 접속이 열린 상태인지 확인합니다. 배포 실패를 바로 해결할 수 없으면 이전 정상 버전과 운영 설정으로 복구하고 서버를 다시 엽니다.
- Firebase Authentication에서 Google 제공자를 사용하고 `mathtjungsw.github.io`를 허용 도메인에 등록합니다.

## 시작과 저장

- **Google로 로그인**한 뒤 처음 접속할 때 1~16자의 선장 이름을 정하면 리스본에서 시작합니다. 이후에는 서버 선택 없이 현실서버에 자동 입장해 기록을 이어갑니다. 현실서버는 1배속입니다.
- 기존 현실서버의 돈·화물·선박·발견 기록을 유지합니다. 이전 저장은 접속할 때 새 보급 규칙으로 전환하고 한도를 넘는 보급은 항구에서 쓸 수 있는 보급 크레딧으로 남깁니다. 새 규칙으로 복귀가 어려운 바다의 구버전 저장에는 무료 안전 귀환을 제공합니다.
- 기기 저장은 이동 중 약 1.5~1.8초 간격과 거래·입항 시 갱신하며, 서버에는 약 15~20초 간격으로 저장합니다. 계정 메뉴의 ‘저장하고 로그아웃’으로 연결을 종료할 수 있습니다.
- 같은 탭의 새로고침은 Google 세션을 복원합니다. 다른 탭이나 기기에서 항해 중이면 새 화면에서 인계를 선택해야 합니다. 미전송 기기 기록이 서버와 충돌하면 별도 백업을 만든 뒤 서버 기록을 열 수 있습니다.
- 함께 항해에는 자동 연결됩니다. 게임용 선장 이름과 접속 상태, 주변 배 위치, 랭킹을 공유합니다. Google 이메일이나 실명은 게임 프로필에 저장하지 않습니다.

## 항해와 탐험

- 고정 배율의 **평면 해도**를 사용하며 확대·축소하지 않습니다. 드래그로 둘러보고 내 배 버튼으로 돌아옵니다. 미니맵은 **지구본(원형 1:1) / 평면 세계지도(직사각형 2:1)** 중 선택합니다. 지구본은 드래그·방향키로 회전하며, 두 보기에서 클릭·터치한 곳의 해도를 볼 수 있습니다. 미니맵 클릭으로 배가 출항하지는 않습니다.
- 자동 항해: 알고 있는 항구 또는 바다를 선택 → 출항. 육지를 피해 항로를 찾고 강에서는 중심선을 따라갑니다.
- 직접 조종: PC는 방향키 또는 **W 위 · S 아래 · A 왼쪽 · D 오른쪽**, 바다 클릭을 사용합니다. 모바일은 화면 방향 버튼을 누르는 동안 움직이고, 바다 터치 뒤 이동을 확정합니다. ■/스페이스로 정지할 수 있습니다. 채팅·검색·수량 입력 중에는 방향키와 WASD로 출항하지 않습니다.
- **지도의 북쪽 끝과 남쪽 끝을 연결합니다.** 직접 조종으로 북위 80도 경계를 넘으면 남위 60도 쪽에서 이어지고, 반대 방향도 같습니다. 지도 드래그도 경계에서 막히지 않고 이어집니다. 바다 구간을 통과할 때 연결되며 실제 육지 충돌 검사는 유지합니다. 자동 항해의 항구 간 경로는 기존 해양·강 항로를 사용합니다.
- 경계 이동은 실제 움직인 거리만 시간·식량에 반영합니다. 통과 구간을 둘로 나누어 대륙을 가로지른 발견·입항으로 처리하지 않습니다. 시야·탐험 기록·주변 배 수신·다른 배의 이동 표시도 연결된 경계를 반영합니다. 이 연결은 게임 규칙이며 실제 지리의 극지방 연결을 재현한 것은 아닙니다.
- 직접 조종 입항은 이동 전후 **구간**과 부두까지의 최단 거리를 검사합니다. 해상은 부두에서 최소 30해리, 강은 12해리 이내를 인식합니다. 해상 부두가 지도 표식보다 멀리 배치된 항구는 표식과의 간격+12해리까지 허용합니다. 정지 중에도 가까운 항구를 인식하되 같은 수로·육지 충돌을 확인하며, 육지 너머 입항은 막습니다. 출항한 항구는 인식 범위+8해리 밖으로 나간 뒤 돌아와야 재입항합니다.
- 초기 개방 항구: 리스본·포르투·세비야. 미개방 항구에 **80해리 이내**로 접근하면 정보를 얻습니다. 개방은 실제 방문과 구분하며 방문 보상·의뢰·탐험 순위는 입항 기준입니다.
- 입항한 항구의 **주점 → 정보 얻기**에서 **100 D**를 내고 **600해리 이내**의 가장 가까운 미개방 항구 1곳을 개방합니다. 후보가 없거나 돈이 부족하면 차감하지 않습니다. 개방한 항구만 도감·지도·자동 항해 목적지에 나타납니다.
- 내 배 중심 **180해리**가 현재 시야입니다. 미탐험은 청회색 안개, 탐험했지만 시야 밖은 연한 회색, 현재 시야는 밝게 표시합니다. 평면 지도와 지구본은 같은 탐험 기록을 사용합니다. 다른 선장의 배는 현재 시야 안에서만 최대 29척 표시합니다.
- 전 세계 **78개 주요 항구**를 배치했습니다. 밀집된 항구 34곳은 새 목적지에서 제외하고 과거 방문 기록·구버전 화물·항해를 보존합니다. 24개 새 항구와 섬 거점이 포함되며 일반·과거 항구 기록 사전은 112곳(개발 후보 12곳 별도)입니다. 새 선장은 통나무 뗏목(하루 80해리·적재 20칸·보급 10일분·해안 80해리 이내)으로 시작합니다. 보급 5칸을 쓰므로 처음 화물 여유는 15칸입니다.
- 사용자 속도 비교에서 선택한 **이전 대비 6배 속도**를 자동 항해·직접 조종에 함께 적용합니다. 게임 속 1일은 활성 항해 2초이며, 항로의 거리·게임 일수·보급 소모량은 그대로입니다. 정박·정지 중에는 보급을 소모하지 않습니다. 선박 개량 시 하루 이동 거리가 늘어 더 빨라집니다.
- 보급이 바닥나면 **이전에 실제 방문한 주요 항구** 중 실제 경로가 가까운 곳으로 자동 구조됩니다. 구조·안전 귀환 중과 도착 직후에는 안개 제거·항구 발견·발견물 수집·최초 방문 보상을 차단하며 정상 항해로 실제 이동한 뒤 탐험을 재개합니다. 가진 두카트 안에서 구조비를 내며 0 D여도 구조됩니다. 화물과 배를 보존하고 항구에서 보급 2일분을 지원합니다.

## 선박 성장과 발견 도감

- **내 배 보기**에서 현재·다음·전체 20단계를 비교하고 항구에서 개량합니다. 첫 개량은 600 D입니다. 개량은 보급 최대치를 늘리며 남은 보급을 자동으로 채우지는 않습니다. 지도와 상세 창에 같은 단계의 자체 제작 선박 그림을 표시합니다.
- 6·10·14·18단계에 선단 상한이 2·3·4·5척으로 늘어납니다. 기함 하나를 조종하면 동행 배도 함께 이동합니다. 한 척 적재 C, 대수 n일 때 선단 적재는 `floor(C × (1 + 0.6 × (n−1)))`, 보급 공간은 `ceil(남은 일수 × n / 2)`입니다. 배 추가 시 식량 총량을 보존하므로 남은 일수는 줄어듭니다. 개량 비용은 모든 배를 함께 개량하는 금액으로 표시합니다.
- 유적 10·유물 14·희귀 동물 8·보물 8, 총 **40종**의 수집 도감입니다. 단서가 필요한 항목은 주점의 무료 소문을 읽고 실제 조사 거리까지 접근해야 합니다. 최초 수집만 난도별 50·150·400·1,000점(총 15,600점)을 얻으며 명성을 돈으로 바꾸지 않습니다. 사실 설명·게임용 관찰 위치·창작 보물을 구분합니다.
- 지도 탐험은 위도별 면적을 반영한 고정 해양·강·해안 관찰 셀 영역의 비율입니다. `exploration-mask.js` 버전 1의 168,350개 대상 셀을 분모로 사용하고 같은 셀은 한 번만 점수에 반영합니다. 과거 탐험도 합산합니다.
- **전체 선장** 명부는 오프라인에도 남고 20명씩 조회합니다. 공개 요약(방문·지도 개방률/면적·발견 수/명성·선박 단계/대수)만 보여주며 다른 선장의 개인 화물·탐험 지도는 읽지 않습니다. 이전 선장의 부족한 정보는 본인 재접속 시 갱신합니다.
- 짧은 확인 창은 내용 크기로 열리고 큰 도감은 창 안에서 스크롤합니다. 게임 방법의 [설명 JPG 10장](https://mathtjungsw.github.io/windward/guide/)과 [전체 ZIP](https://mathtjungsw.github.io/windward/guide/windward-player-guide-10pages.zip)을 공유할 수 있습니다.
- 구현·검증 기록: [2026-11-06 업데이트](docs/UPDATE_2026-11-06_WORLD_FLEET.md). 새 항구·발견물 출처와 게임용 좌표 조정은 [세계 콘텐츠 검증](docs/WORLD_CONTENT_VERIFICATION_2026-11-06.md)에 기록합니다.

## 교역

- 23종의 전통 교역품을 생산·지역 공급·수입과 중계로 구분합니다. 혼합 향신료는 구버전 화물에서 이어 판매할 수 있습니다. 항구의 ‘항구와 상품 이야기’에서 실제 역사와 게임 속 배치를 구분해 읽을 수 있습니다.
- 수량은 1/5/10/최대로 선택합니다. 최대는 현재 적재 여유이며 다음 항해의 보급 공간·비용을 함께 확인합니다. 거래 완료 후 같은 목록에서 이어 거래할 수 있습니다.
- 화물 판매는 지도에서 선택한 항구와 별개로 **실제 정박한 항구**의 가격을 사용합니다. 다른 항구 시세를 조회해도 현재 정박지에서 판매할 수 있습니다. 구매는 선택한 항구에 정박해 있어야 가능합니다.
- 화물창에 입항 완료 여부와 판매 항구를 표시합니다. 다른 항구를 조회 중이면 정박 항구 교역소로 돌아가는 버튼을 제공합니다. 항해 중에는 판매를 막고 입항 안내를 표시합니다.
- 교역소 버튼에 키보드 초점이 있을 때 방향키로 배가 출항하지 않습니다. 지도에서 방향키를 사용하면 기존 직접 조종이 동작합니다.

## 화면·채팅·랭킹

- PC 메뉴의 **개선 제안 / 소유 항구**, 모바일 **더보기 → 개선 제안 게시판 / 소유 항구 현황**을 사용합니다. 제안은 로그인 선장 이름으로 공개하고 제목 50자·본문 1,200자, 서버 기준 1분 간격으로 등록합니다. 최근 20개씩 이전 글을 조회하며 채팅 50개와 별도로 보관합니다. 전송 확인이 끊기면 동일 글 ID를 조회해 중복 등록을 방지합니다.
- 소유 항구 목록은 현재 소유자가 있는 일반/개발 항구의 이름·소유 선장·지분·기본 세율을 표시합니다. 목록을 열거나 새로고침할 때 작은 공개 장부 `real/ownedPorts`만 최대 124개 읽습니다. 전체 항구의 시세·투자자·개인 저장을 내려받지 않습니다. 지도 보기는 발견·입항 점수를 주지 않습니다.
- 전투 장면은 지도에 남습니다. **지도 아래 접을 수 있는 대포 조작부**에서 포격·후퇴·정산하며 배 옆에 내구도 수치와 막대를 표시합니다. 서버 확인 뒤 포탄·명중/빗나감·해적 반격을 그리며 효과 재생만으로 피해·보상을 만들지 않습니다. 시야 밖 상대의 내구도 표식은 숨기고 재접속 때 현재 전투로 복원합니다. 후퇴는 패전 손실 안내 후 한 번 더 눌러 확정합니다.

- 모바일 출항·도착 등의 짧은 알림은 하단 바로가기 위에서 문구 높이로 표시합니다. 위·아래 위치 중복으로 세로로 늘어나던 문제를 수정했습니다.
- 정보창은 처음에 펼쳐집니다. 접은 상태는 해당 기기에 기억합니다. 모바일에서는 하단 ‘항해 / 항구·보급 / 화물 / 더보기’로 바로 접근합니다. 항구 찾기는 즐겨찾기·최근 입항·거리순을 지원합니다. PC의 조작·화면 설정에서 단축키와 정보 영역 폭을 바꿀 수 있습니다.
- 위쪽 **접속 선장 · N명**은 현실서버에 접속한 전체 선장 수이며 나를 포함합니다. 버튼을 누르면 거리에 관계없이 모든 이름과 항해 상태가 나옵니다. 명단은 스크롤할 수 있고 29척의 지도 표시 제한을 적용하지 않습니다. 지도·지구본에 보이는 다른 배만 **내 시야 180해리**로 제한합니다.
- 채팅을 펼치면 최근 **50개**, 접으면 별도 미리보기로 최근 **최대 5개**를 표시합니다. 최신 글은 아래쪽, 목록은 스크롤할 수 있습니다. Enter 전송/Shift+Enter 줄바꿈/Escape 접기. 입력 중에는 배를 조종하지 않습니다.
- 현실서버의 `messages/0..49`의 고정 자리를 순환하며 가장 오래된 본문을 덮어씁니다. 별도 전체 대화 이력은 남기지 않습니다. 200자·3초 간격을 화면과 서버에서 검사합니다. 동시 전송 충돌은 순번을 다시 확인해 재시도하며 실패 시 입력을 유지합니다.
- 공개 순위는 **4개 분야·14종**입니다. 교역(무역 이익·지금 가진 돈·교역품 수집왕·최고의 한 거래), 탐험(방문 도시·지도 탐험·명성·도감 수집왕·섬 탐험왕), 선단/경영(선단 성장왕·항구 경영왕), 전투(해적 토벌·선장 선단 격파·결투 승리)로 고릅니다. 선택한 기준의 상위 5명만 구독하고 패널을 접으면 구독을 해제합니다. 오프라인 기록을 유지하며 동점은 공동 순위입니다. 정확한 내 순위는 요청할 때만 1,000명씩 제한 조회해 계산합니다.
- 도감·섬 입항·선단 단계는 기존 저장을 합산합니다. 섬 판정은 [검증한 항구 목록](docs/ISLAND_PORTS_2026-11-09.md)을 사용합니다. 거래 종류·최고 단일 이익·전투 횟수는 새 행동부터 집계하고, 과거 명성에서 처치 횟수를 역산하지 않습니다. 기존 리스본 포도주 구매 표식처럼 명확한 증거는 이어 사용합니다. 최고의 한 거래는 판매분 원가와 거래세를 뺀 이익의 최고 정수값, 선단 성장은 각 배의 1~20단계 합입니다. 자유 PvP에서 상대 HP가 0일 때만 선단 격파로 세며, 결투 승리와 분리합니다.
- 항구 경영은 `real/portRankings/{uid}`의 현재 소유 수입니다. 지분 변동과 관련 선장들의 수를 같은 원자 요청에서 증감합니다. 오프라인 이전 소유자의 개인 저장은 읽거나 변경하지 않습니다. 서로 다른 항구에서 같은 소유자의 지분이 동시에 바뀌면 장부 revision 충돌을 거절해 한 번만 반영합니다.
- 방문한 항구와 완료한 항구 간 항로를 전체 채팅에 공유할 수 있습니다. 시야 안 선장에게 인사·감사·순항 기원을 보낼 수 있습니다. 정보 카드가 항구를 직접 해금하지는 않습니다.
- 상단 ‘업데이트’에서 현재·과거 공개 이력을 읽습니다. 계정에서 확인을 누른 최신 버전을 기록합니다. `docs/releases.json`을 갱신한 뒤 `node tools/build-release-notes.mjs`로 공개 이력과 CHANGELOG를 만듭니다.

## Firebase와 무료 운영

프로젝트 `windward-voyage`, Realtime Database 싱가포르, **Spark 무료 요금제**를 유지합니다. 결제 정보·유료 서버·Cloud Functions·애널리틱스를 추가하지 않습니다. `dist/firebase-config.js`는 공개 웹 설정이며 관리자 키를 넣지 않습니다. SDK는 공식 CDN의 12.4.0을 필요할 때 로드합니다.

```text
gameV2/accounts/{uid}              선장 이름과 공지 확인
gameV2/privateSaves/{uid}          본인만 접근하는 현실서버 저장
gameV2/real/sectors/{sector}/{boat} 주변 해역의 접속 배
gameV2/real/captains/{session}     전체 접속 이름·상태
gameV2/real/rankings/{uid}         공개 순위 요약
gameV2/real/portRankings/{uid}     현재 항구 소유 수·이름만 담은 공개 장부
gameV2/real/ownedPorts/{portId}    현재 소유 항구의 공개 목록
gameV2/real/suggestions/...       공개 제안 글·등록 간격 기록
gameV2/real/chat/...               최근 대화 50개
```

- 현재 저장 봉투는 v5, 게임 상태는 v4입니다. 버전 1·2는 돈·화물·선박·방문·탐험을 보존해 한 번 이관하며 기존 3종 선박은 새 5·10·16단계에 대응합니다. 이관 전 본인 기록을 기기에 백업하고 v5로 이관한 저장에 구버전 덮어쓰기를 차단합니다.
- 공용 `gameV2/shared/ports/{id}`는 선택한 항구의 시세·재고·지분·세금, `harborRegistry`는 개발 상태만 저장합니다. 전투는 두 참가자만 읽는 `shared/battles/{id}`와 슬롯·정산 보관 경로를 사용합니다. 오프라인 교전은 별도 `shared/raids/{id}`, `fleetStates/{uid}`, 개인 `privateNavigation/{uid}`와 영구 `real/fleetIndex/{sector}/{uid}`로 격리합니다. `tools/stamp-assets.mjs`로 공개 버전에 맞춰 모듈·CSS 캐시 주소를 갱신합니다.
- 랭킹/소유 목록의 기존 기록 보강은 [후속 업데이트의 운영 절차](docs/UPDATE_2026-11-09_RANKINGS_FIXES.md)를 따릅니다. `tools/refresh-ranking-summaries.mjs`는 명시한 Windward 프로젝트에서만 실행하고 공개 요약만 씁니다. 새 UI와 서버 규칙 배포 결과는 [2026-11-10 기록](docs/UPDATE_2026-11-10_COMMUNITY_MAP_COMBAT.md)에 남깁니다.
- 진행은 JSON 문자열로 보관해 Firebase에서 빈 화물창 등의 빈 객체가 사라지는 문제를 방지합니다. 게임의 돈·화물·탐험 지도는 다른 uid에게 읽기를 허용하지 않습니다.
- 위치는 항해 중 최소 2초, 변화 없는 정박·정지는 30초 간격입니다. 10도 해역 중 현재 시야와 겹치는 주변 구역만 구독합니다. 영구 선단은 UID 키로 구역당 100개씩 키 순서 페이지를 구독하고, 가득 찬 경우 다음 페이지도 읽어 오래된 오프라인 배를 누락시키지 않습니다. 지도에는 거리가 가까운 다른 선단 29개를 우선 표시합니다. 이전 세션의 종료 쓰기는 현재 저장 세션과 다르면 거절합니다. 정지/접속 유지는 30초이며 본인 이동 체크포인트는 개인 경로에 작게 저장합니다.
- 전체 선장 명단은 좌표와 별도로 uid·이름·색상·항해 상태·갱신 시각만 공유합니다. 상태가 바뀔 때와 30초마다 갱신하며 종료 시 `onDisconnect`로 제거합니다. 갱신이 끊긴 기록은 90초 후 숨기고 같은 uid의 중복 세션은 하나로 합칩니다. Spark의 동시 연결 범위에 맞춰 명단은 최대 100개의 최근 접속 기록을 조회합니다. 이전 버전을 열어 둔 이용자는 새로고침 후 새 명단에 참여합니다.
- 시야 밖 표시 제한은 클라이언트 표현 규칙입니다. 변조 프로그램의 인접 해역 조회까지 거리별 서버 판정으로 차단하지는 않습니다. 순위 점수도 클라이언트 요약이며 치트 방지 경쟁 서버가 아닙니다.
- 규칙은 Google 인증 이용자에게만 새 게임 경로를 허용합니다. 이전 버전이 사용하던 계정·저장·세계·위치·채팅 경로는 닫습니다.
- 채팅 50개 제한은 보관량을 줄이며 이미 쓴 전송량을 없애지 않습니다. 무료 한도는 배 위치·채팅·저장이 함께 사용합니다. 소규모 테스트를 시작할 수 있으나, 실제 이용 인원·시간에 따른 월 전송량을 측정해야 합니다. 동시 100개 연결 한도가 한 달 100명 무료 운영을 보장하지 않습니다.
- [Firebase 인증](https://firebase.google.com/docs/auth/web/google-signin), [저장·트랜잭션](https://firebase.google.com/docs/database/web/read-and-write), [보안 규칙](https://firebase.google.com/docs/database/security), [요금제](https://firebase.google.com/pricing).

## 검증

- `npm test`: 게임 규칙·연안 제한·적재/보급·자동 구조·저장 이관·조종 키·항로·공유 카드·시야·채팅·랭킹 검증. `npm run notes:check`는 공개 이력과 교역품 생성물을 확인합니다.
- `npm run test:rules`: 127.0.0.1:9000의 공식 Database Emulator에만 연결해 채팅 보관·동시 전송·간격, 소유권·비공개 저장·저장 버전·Google 인증 제한·구버전 쓰기 차단·접속 종료 후 순위 유지·해역 조회 제한을 검증합니다. 실제 게임 대화를 읽거나 바꾸지 않습니다. 시장·보관금·전투의 원자 반영과 재실행 차단도 검사합니다. DOM 테스트는 실제 브라우저의 그리기·배치 검증을 대체하지 않습니다.
- 에뮬레이터: Temurin JRE 21 + Firebase Database Emulator 4.11.2. 이 PC의 검증 실행 파일은 `C:/Users/codex/.cache/windward-firebase-tests/`에 있습니다. `java -jar firebase-database-emulator-v4.11.2.jar --host 127.0.0.1 --port 9000`으로 실행한 후 규칙 검증을 진행합니다.
- `http://127.0.0.1:4173/__qa/mobile`은 개발 서버에만 있는 너비 390px의 실제 게임 iframe입니다. 공개 배포 파일에는 이 검증 페이지가 포함되지 않습니다. 실제 휴대폰 기기 시험과는 구분합니다.
- `http://127.0.0.1:4173/__qa/wrap`과 `?edge=south`는 각각 경계 근처에서 시작하는 격리 화면입니다. 테스트 화면에서 실제 저장 서버를 사용하지 않고 이동을 시험합니다. 개발 서버 전용이며 배포물에 포함하지 않습니다.
- 로그인 화면 검증은 `npx firebase-tools emulators:start --only auth,database --project demo-windward-chat` 실행 후 `node tools/serve.mjs --emulators`로 시작합니다. `--fixture-login`을 함께 사용하면 에뮬레이터의 가상 Google 계정으로 로그인 흐름을 시험합니다. 두 옵션은 로컬 서버에서만 적용됩니다.

## 지도 / 설정

[Natural Earth](https://www.naturalearthdata.com/) 퍼블릭 도메인 1:110m 해안선·국가 경계. 원본은 [Natural Earth vector](https://github.com/nvkelso/natural-earth-vector)의 GeoJSON입니다. `python tools/build-map.py`로 0.5도 간격의 항해용 육지 마스크를 재생성합니다. A* 바다 항로와 시야선 평활화를 사용합니다. 항구 입출항 연결과 좁은 해협은 단순화되어 있어 실제 항해에 사용할 수 없습니다.

강 중심선은 [Natural Earth 1:10m rivers + lake centerlines](https://www.naturalearthdata.com/downloads/10m-physical-vectors/10m-rivers-lake-centerlines/), 도시 좌표는 [Natural Earth 1:10m populated places](https://www.naturalearthdata.com/downloads/10m-cultural-vectors/10m-populated-places/)를 사용합니다. `python tools/build-waterways.py`로 `dist/assets/rivers.json`과 `dist/harbors.js`를 재생성합니다. 필요한 원본 GeoJSON은 `tools/source-data/`에 캐시하며 Git에는 포함하지 않습니다.

강이 넓어 중심선 자료가 끊긴 하구는 생성 도구에 기록한 대표 지점으로 연결합니다. 강폭은 조작 편의를 위해 넓혔으며, 강 항구의 선착장은 도시 좌표에서 가까운 게임용 강 중심선에 배치합니다. 원래 도시 좌표도 `city` 필드로 보관합니다. 아테네는 피레아스, 퍼스는 프리맨틀 해안의 선착장을 사용합니다. 항구 상품과 가격은 게임 설정입니다.

세비야의 내륙 항구와 과달키비르강 접근은 [세비야 항만청의 항로 안내](https://www.puertodesevilla.com/via-navegable/navegacion)를 참고했습니다. 지구본은 동일 지리 자료를 정사영으로 표시하며, 외부 지도·3D 서비스에 의존하지 않습니다.

1522년부터 시작하는 가상 항해에 여러 시대의 항구와 전통 교역을 담았습니다. 날짜가 확인된 역사 이야기는 해당 출처와 함께 표시합니다. 항구 상품과 조작용 부두는 `tools/port-catalog.json`에서 관리합니다. `node tools/build-catalog.mjs`, `python tools/build-waterways.py`, `python tools/build-map.py`로 배포 자료를 갱신합니다.

섬 거점에는 Natural Earth 1:10m의 소형 섬 195개 폴리곤을 별도 표시합니다. `tools/build-island-coasts.py`로 생성하며 항해 해안 거리는 16비트로 저장해 원양 거리 제한의 255해리 포화를 방지합니다. JPG 안내 생성: `python tools/build-player-guide.py --final`(Pillow·PyMuPDF·qrcode 필요), 최종 이미지는 `dist/guide/`에 게시합니다.
