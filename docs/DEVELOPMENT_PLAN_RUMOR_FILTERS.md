# 소문 노트·항구 주점 필터와 제다 소문 수정

반영 버전 `2026.11.16-rumor-filters`

## 1. 표시 기준

| 탭 | 소문 노트 | 현재 항구의 주점 |
| --- | --- | --- |
| 전체 | 모든 항구에서 내가 읽은 소문 | 지금 이 주점에서 볼 수 있는 소문 |
| 미완료 | 내가 읽었고 관련 목표가 미완료인 소문 | 아직 읽지 않았거나 관련 목표가 미완료인 소문 |
| 완료 | 내가 읽었고 관련 목표까지 완료한 소문 | 지금 이 주점의 목록에 있고 관련 목표를 완료한 소문 |

- 소문 노트의 ‘숨기기’와 ‘숨긴 소문’을 제거한다. 예전에 숨긴 소문도 읽은 기록이 있으면 다시 표시한다. 기존 숨김 값은 불러오기 호환을 위해 둘 수 있으며, 새 화면의 표시 기준에는 사용하지 않는다. 읽음·획득·발견 기록은 보존한다. 이 변경에 별도 저장 이관이나 서버 조회를 추가할 필요가 없다.
- ‘미완료’ 판정에는 기존 규칙을 재사용한다. 유물·유적 등은 발견 완료, 부선장은 고용 완료, 장비는 획득 기록을 기준으로 한다. 사용한 일회용 아이템도 획득 기록이 남아 있으면 완료로 표시한다. 완료 표시와 필터는 같은 판정을 사용한다.
- 소문 노트는 이미 읽은 소문을 시대가 바뀌어도 다시 열 수 있다. 항구 주점은 현재 항구와 시대에 맞는 목록을 표시한다. 주점에서 처음 읽은 소문은 기존 저장 흐름으로 소문 노트에 추가된다.

## 2. 화면 동작

- 두 화면 모두 첫 진입 시 ‘전체’를 표시한다. 탭을 바꾸면 목록만 갱신한다. 주점에서는 같은 항구·같은 화면에 머무는 동안 선택한 탭을 유지하고, 다른 항구 주점에 들어가면 ‘전체’로 시작한다.
- 주점의 소문 번호는 필터 적용 전 목록 순서로 정한다. 전체의 ‘소문 5’는 미완료 탭에서도 ‘소문 5’로 표시한다. 소문을 누르면 본문이 같은 화면에서 펼쳐진다. 이미 펼친 소문은 새 탭에도 해당 소문이 있을 때 열린 상태를 유지한다.
- 세 필터 버튼은 PC와 모바일에 표시하고, 선택 상태를 시각적으로 구별한다. 키보드 사용자가 탭을 바꿔도 선택한 버튼에 초점을 유지한다. 결과가 없으면 ‘미완료 소문이 없어요’처럼 현재 목록에 맞는 문구를 보여 준다.
- 소문 목록의 분류·정렬·필터는 브라우저에서 처리한다. 소문 제목과 본문에 발견물·아이템·부선장 유형이나 정답을 미리 표시하지 않는 기존 형식을 유지한다.

## 3. 제다의 두 번째 소문 읽기 오류

- 정상 정박한 제다에서 탐험형 상주 부선장이 다른 시대의 추가 소문을 보여 준 상태를 재현했다. 기존 읽기 단계는 시대 조건을 검사하므로 눌렀을 때 실패한다.
- 상주 부선장 추가 소문을 고르는 단계에 현재 서버 시각의 시대 조건을 적용한다. 다른 시대 후보는 건너뛰고, 같은 지역에서 읽을 수 있는 후보가 있으면 그중 한 건을 표시한다. 후보가 없으면 추가 소문 행을 표시하지 않는다. 상주 역할, 정박 상태, 읽음·발견 여부, 기간제 운영권 등 기존 조건도 적용한다.
- 시대 전환 직전에 열린 화면을 나중에 누르는 경우는 클릭 시 조건을 다시 확인하고 목록을 갱신한다. 종료된 시대가 원인이면 정박 안내 대신 ‘시대가 바뀌어 이 소문을 지금은 읽을 수 없어요’라고 표시한다. 소문 노트에는 이미 읽은 기록이 그대로 보인다.

## 4. 개발 및 검증 순서

1. 추가 소문의 후보 선택과 읽기 조건을 맞추고, 제다에서 실제 제보와 같은 조건을 재현해 수정한다.
2. 소문 노트와 주점에 각각 필터를 연결한다. 같은 소문의 완료 판정은 공유하고, 읽지 않은 소문이 소문 노트에 표시되지 않는지 확인한다.
3. 예전에 숨긴 소문, 읽지 않은 소문, 읽은 미완료 소문, 완료 소문, 소모한 획득 아이템의 소문을 함께 준비해 세 탭을 확인한다. 주점에서 읽기, 완료 후 탭 이동, 예전 저장 불러오기, 시대 전환 뒤 다시 읽기를 포함한다.
4. 제다에서 시대 내 후보, 다른 시대만 있는 경우, 화면을 열어 둔 채 전환된 경우를 검증한다. PC·모바일에서 탭 전환, 번호, 본문 펼침, 빈 목록 안내를 확인하고 게임 테스트를 실행한다.
5. 구현 및 배포 요청이 오면 패치노트와 게임 설명서에 새 동작을 반영하고, 점검 안내 게시와 서버 재개까지 확인한다.
