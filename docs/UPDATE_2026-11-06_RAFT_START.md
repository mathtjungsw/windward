# 全 선장 뗏목 전환 · 2026-11-06

사용자가 기존 선장도 뗏목으로 시작하고 낮아지는 배의 차액을 지급하라고 즉시 적용을 지시했다. 따라서 앞선 ‘기존 배 보존’ 방침을 이번 한 번의 전환으로 대체한다. 이후 새로 개량한 배와 추가한 선단은 유지한다.

## 지급 기준과 보존

- 현행 20단계 가격표의 현재 단계까지 누적 개량비를 기본 선박 가치로 계산한다. 동행 배는 대수별 기본 구입비(6,000/15,000/35,000/75,000 D)와 현재 누적 개량비의 25%를 더한다. 뗏목 1척의 가치는 0 D다. 과거 실제 결제 이력이 없는 저장에 적용하는 현재 가격표 기준 평가액이며, 역사적 실지출을 복원했다고 주장하지 않는다.
- 이전 기본 배(새 5단계)는 600+900+1,500+2,200 = **5,200 D**다. 보상은 자금에 더하고 무역 이익에는 더하지 않는다.
- 화물·방문·안개 제거·발견물·소문·의뢰·퀴즈 기록을 보존한다. 초과 화물을 버리지 않는다. 식량은 선단 총량을 한 척 기준으로 환산하고 10일을 넘는 양의 가치를 전환 전 보급 단가로 크레딧에 보관한다.
- 항해 중 실제로 낮아지는 배는 마지막 방문했던 항구(출항 항구 우선)로 무료 귀환한다. 미방문 항구 선택, 탐험·발견 보상은 발생하지 않으며 정상 이동 뒤 탐험을 재개한다.

## 동시 저장과 중복 방지

`raft-start-2026-11-06` 표식을 게임 데이터에 저장한다. 신규 선장은 이미 적용된 뗏목으로 시작한다. 기존 선장은 서버 관리자 도구로 오프라인까지 처리하고 클라이언트 입장에도 빠진 기록의 보완 경로를 둔다. 표식이 있으면 새 개량을 되돌리거나 다시 보상하지 않는다.

저장 봉투는 4, 게임 데이터는 3이다. Firebase 규칙이 봉투 2·3의 새 저장과 덮어쓰기를 막는다. 각 서버 기록은 ETag 조건부 쓰기로 변경하고 revision을 올려 접속 중 세션을 갱신시킨다. 이전 기기 미전송 기록은 기존 충돌 보호 절차로 별도 보존한다. 공개 요약도 최신 revision보다 오래된 내용으로 덮어쓰지 않고 갱신한다.

도구 `tools/apply-raft-start.mjs`는 기본 미리보기, `--apply`에서만 쓰기다. 필요한 개인 저장과 관련 공개 요약만 읽으며 각 수정 전 원본과 지급 영수증은 Git에서 제외한 `.qa/raft-start-2026-11-06/`에 보관한다. 인증 토큰을 파일이나 출력에 넣지 않는다. 재실행은 중복 지급하지 않으며 미완료 공개 요약을 보완할 수 있다.

## 운영 적용

서버 기존 선장 **4명 모두 뗏목 1척으로 적용 완료**, 각 5,200 D씩 **총 20,800 D 지급**. 실패 0명. 수정 전·후 기록을 대조해 화물·방문·개방 항구·탐험 지도·수집·소문·무역 이익·거래·의뢰·퀴즈가 동일함을 확인했다. 공개 요약의 자금/선박과 새 v4 규칙도 운영 서버에서 다시 읽어 확인했다. 개인 원본과 UID별 영수증은 공개하지 않는 로컬 백업에 보관한다. Firebase 프로젝트는 기존 windward-voyage, 공개 주소는 기존 GitHub Pages를 사용한다.
