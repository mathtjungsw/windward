# 항해 성능 개선 · 2026-11-10

릴리스: `2026.11.10-performance`. 상태: 구현·로컬 검증 완료. GitHub Pages 배포 결과는 커밋 이후 공개 파일과 함께 확인한다.

## 적용 범위

사용자가 대화에서 선택한 1·2·4: 선단 SVG 재사용, 미니맵 캐시 및 접힌/화면 밖 그리기 중지, 프레임 지연 시 항해 시간 보존. 조사 문서의 내부 목록 번호와 구분한다. 정밀 해안선·지명은 유지하고 지형/라벨 최적화와 동일 명단/전투 UI 생략은 이번 범위에서 제외했다.

- 선박 ID별 노드와 클릭 대상을 유지한다. 위치·방향·상태는 변경된 속성만 갱신하고 선박 단계·선단 구성·이름·오프라인 표기 변경 때만 그림을 다시 만든다. 없어진 배는 제거한다. 해적도 가시 목록이 같으면 재생성하지 않는다.
- 미니맵은 위치·탐험 revision·탐험 인스턴스·구조 중 시야 제한·지구본 회전이 바뀔 때 배경을 다시 계산한다. 다른 배 위치만 바뀌면 배경은 재사용한다. 일반 갱신 간격은 최소 200ms다. 접힘/화면 밖/숨긴 탭에서는 계산하지 않으며 다시 보일 때 최신 그림을 그린다.
- 항해 시계를 분리해 경과 시간을 0.1초 이하로 나누고 최대 20단계/프레임을 실행한다. 그 이상은 다음 프레임에 보존한다. 입항·구조 전환·멈춤·숨김·거래 대기 등 경계에서 이전 시간을 새 행동에 섞지 않는다. 선박 설정 속도, 식량 규칙과 일반 위치 전송 주기는 변경하지 않았다.
- 서버 규칙·저장 형식·운영 데이터 변경과 신규 외부 서비스는 없다. 정상 항해가 빨라진 만큼 실제 이동·보급 소모가 함께 진행된다. 별도 DB 읽기 경로를 추가하지 않았다. 자동 항해 저장 1.8초·직접 조종 저장 1.5초의 기존 최소 간격도 유지했다.

## 검증

- 추가 회귀 검사: 정지/이동 배 노드 동일성·제거, 두 미니맵 배경 재사용/탐험 변경/접힘/화면 밖, 여러 프레임 간격의 자동 항해 거리·식량·시간, 긴 프레임 작업량 제한/시간 보존, 실제 앱 tick의 자동/직접 항해 및 숨김 복귀.
- 자동 항해는 수치 오차 1e-7 미만. 직접 조종은 구면 이동의 분할 간격 차이를 고려해 좌표 차이 0.0005도 이내, 시간·식량 차이는 1e-7 미만으로 검사한다.
- `npm test`: 153개 전체 통과. `npm run notes:check`: 릴리스 노트·카탈로그·아트·자산 버전 검사 통과. 서버 규칙 변경이 없어 이번 수정에서는 에뮬레이터 규칙 테스트를 추가 실행하지 않았다.

### 같은 상태 반복 호출의 제한된 CPU 비교

Node + Happy DOM, canvas no-op 조건이며 브라우저 실제 페인트/GPU·모바일 FPS가 아니다. 처음 생성하는 비용과 움직이는 지도 배경 비용은 아래 개선 비율로 해석하지 않는다.

| 반복 작업 | 이전 중앙값 / p95 (ms) | 이후 중앙값 / p95 (ms) |
| --- | ---: | ---: |
| 지구본 강제 그리기 | 5.22 / 11.20 | 0.02 / 0.04 |
| 평면 미니맵 강제 그리기 | 6.71 / 9.15 | 0.01 / 0.09 |
| 정박한 다른 배 9척 | 2.61 / 14.40 | 0.03 / 0.05 |

반복 배경 계산과 노드 생성을 피하는 효과다. 실제 사용자 휴대폰의 체감/FPS는 미측정이다. DOM 조작 검사와 실제 브라우저 화면 검증을 혼동하지 않는다.

## 배포 확인

기존 GitHub main → Pages 자동 배포를 사용한다. 운영 DB 변경은 없다. GitHub Actions 성공과 공개 index/app/atlas-view/globe/simulation-clock 파일의 버전·내용 일치를 확인한 후 사용자에게 완료를 알린다. 최종 실행 ID는 커밋 이후 생성되므로 작업 응답에 완료 여부를 명시한다.
