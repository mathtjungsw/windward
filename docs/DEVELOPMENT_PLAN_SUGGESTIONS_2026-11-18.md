## 1. 제다 추가 소문 재열람

### 1.1 원인과 목표

탐험형 상주 부선장의 추가 소문은 미열람·미발견 후보에서 선택된다. 현재는 읽은 소문 ID를 현재 방문의 임시 값으로만 유지하므로, 다른 항구에 다녀오거나 재접속하면 다시 표시할 근거가 사라진다. 소문 노트에 남은 열람 기록은 유실된 것이 아니다. 시대 전환으로 신규 후보가 바뀌는 현상과 구분한다.

### 1.2 표시와 읽기 규칙

1. 해당 항구에서 정상적으로 추가 소문을 처음 읽는 순간, 개인 저장에 ‘어느 항구에서 어떤 소문을 읽었는지’를 함께 기록한다.
2. 주점 목록은 현재 항구의 기본 소문, 이 주점에서 과거 읽은 추가 소문, 현재 새로 들을 수 있는 추가 후보를 합친다. 같은 ID는 한 번만 표시한다.
3. 과거 읽은 추가 소문은 부선장을 회수하거나 항구 소유자가 바뀌어도 개인 열람 기록으로 남는다. 새 추가 후보 획득에는 기존 상주 부선장·정박·시대 조건을 적용한다.
4. 시대가 바뀌어도 이미 읽은 본문은 다시 열 수 있다. 시대가 맞지 않으면 ‘이전에 들은 소문 · 현재는 해당 시대 아님’을 표시한다. 재열람으로 현재 시대의 발견·고용 조건을 우회하지 않는다.
5. 주점의 전체·미완료·완료와 소문노트의 읽은 소문 필터는 기존 판정을 재사용한다. 탐험·부선장·아이템이라는 분류나 보상 정체를 미리 드러내지 않는다.
6. 클릭하면 같은 목록에서 본문을 펼친다. 같은 버튼을 다시 누르면 접고, 상세를 열어도 주점·노트 자체를 닫지 않는다. 기본 소문 순서를 유지하고 기록된 추가 소문은 최초 열람 순서로 배치한다. ‘소문2’ 같은 표시 번호를 저장 ID로 사용하지 않는다.

### 1.3 저장과 호환

- 개인 저장에 `rumorProgress.tavernHistory[portId] = [rumorId, ...]`를 추가하는 안을 사용한다. 이미 읽은 유효 ID만 허용하며 항구·ID 중복을 제거한다. 크기는 실제 유효한 항구·소문 수로 제한하고 매 열람마다 전체 노트를 별도로 서버에 전송하지 않는다.
- 읽기와 출처 기록을 같은 개인 저장 작업으로 확정한다. 저장 실패 시 성공한 것처럼 기록을 새로 생성하지 않고 재시도를 안내한다.
- 기존 `rumors`, 계약 소문의 `read`, 완료·발견·고용 기록은 보존한다. 기존 저장에는 추가 소문을 들은 주점의 출처가 없으므로 특정 항구에서 들었다고 추정해 일괄 이관하지 않는다. 확인되지 않는 과거 소문은 기존처럼 소문노트에서 읽게 한다.
- 향후 같은 소문을 실제 주점에서 다시 정상적으로 읽었을 때만 출처를 보완한다. 출처 복원을 위해 발견 조건을 완화하거나 아직 듣지 않은 내용을 공개하지 않는다.

### 1.4 검증 기준

- 같은 시대에 읽기 → 다른 항구 이동 → 재방문, 브라우저 재실행, 시대 전환 후 재열람을 확인한다.
- 부선장 회수·타 항구 파견·소유권 변경 뒤 과거 기록은 남고 신규 소문 권한만 바뀌는지 확인한다.
- 전체·미완료·완료의 중복 방지, 완료 이동, 저장 실패 재시도, 구 저장 불러오기를 확인한다.
- 재현된 제다 조건을 회귀 검사에 추가한다. 운영 이용자가 실제 읽은 소문 ID가 불명확한 경우 특정 ID의 열람·완료를 임의 지급하지 않는다.

## 2. 교역 장비 효과와 상한 안내

### 2.1 유지할 계산

- 향료용 이중 상자는 후추·정향·육두구의 **세후 판매 수령액 +1.5%**다. 계피나 향료 전체로 넓히지 않는다.
- 현재 판매 효과는 활성 부선장과 장착 교역 장비를 합산한 뒤 최대 3%를 적용한다. 부선장 숙련으로 달라지는 수치도 실제 계산 결과를 표시한다.
- 총액 기준으로 보너스를 계산하고 정수 미만은 현행 방식대로 버린다. 상자별로 따로 반올림하거나 목록의 단가에 보너스를 중복 반영하지 않는다.
- 축복·일회용 거래 증서 등 기존에 별도 계산하는 효과는 별도 행에 표시한다. 3% 상한에 포함되는 것과 별도인 것을 명시한다. 이번 편의 개선만으로 보너스 상한·축복·시세·세율을 바꾸지 않는다.

### 2.2 판매 확인창

확인창에 `시세 × 상자 수`, `세금`, `세후 금액`, `장비·부선장 판매 보너스`, `기타 효과`, **최종 수령액**을 표시한다. ‘효과 자세히’는 기본 접힘으로 두고 모바일에서 필요한 총액과 확정 버튼을 먼저 보여준다.

효과 상세의 예시는 다음과 같다.

- `장보고 +현재 적용률`, `상인 인장 +1%`, `지역 상인 추천장 +1% · 유럽에서 적용`, `향료용 이중 상자 +1.5% · 해당 3품목에 적용`.
- `합산 4.5% → 적용 3% · 최대 효과에 도달했어요`처럼 합산 전과 실제 적용값을 함께 보여준다. 예시 4.5%를 고정값으로 쓰지 않고 현재 장비·숙련·상품·항구로 계산한다.
- 적용 대상이 아니면 `이 상품에는 적용되지 않아요`, 세후 총액이 작아 금액 증가가 0이면 `정수 미만 보너스는 버려져요`라고 설명한다.
- 개별 장비의 기여도는 ‘그 장비를 제외한 최종 효과와의 차이’로 계산한다. 상한에 걸린 장비를 무조건 고장이나 불필요 장비로 표시하지 않는다.
- 김부장 저장 사본의 유럽 사례는 상자를 제외해도 3%다. 상자 추가에 따른 증가분이 0인 이유를 상한으로 안내한다. 유럽 밖의 결과는 현재 실제 조건으로 다시 계산한다.

### 2.3 구현 연결과 검증

- 효과 상세와 실제 견적은 같은 공통 계산 함수를 사용한다. 클릭 시 별도의 임의 계산식으로 총액을 만드는 것을 금지한다.
- 5번의 개인 칭호 판매 효과가 들어오면 같은 상세와 합산 상한에 연결한다. 항구 블랙리스트·초보 면세·시대 전환·거래 압력 처리와 단일 시세 일괄 정산은 보존한다.
- 1·100·1,000상자, 대상·비대상 품목, 유럽·비유럽, 숙련별 부선장, 미장착·중복 장착 방지, 세율 0·30%, 보너스 합산 3% 미만·정확히 3%·초과를 검사한다.
- 실제 두카트 증가액과 최종 견적이 일치하고, 낡은 견적의 재확인 및 중복 확정 방지가 유지되는지 확인한다. 현재처럼 단독 정향 판매 기본 11,000 D에 165 D가 붙는 고정 시각 사례를 계산 회귀 검사로 사용한다.

## 3. 기존 수집자의 바다의 유산 조사 보고

### 3.1 유지할 보상과 조건

- 도감 25종을 모아 받는 ‘바다의 유산 조사’는 지정 유적 8종 중 **서로 다른 기존 발견 기록 3종 보고 → 500 D**로 유지한다. 수락 후 새로 발견해야 한다는 조건을 추가하지 않는다.
- 기존 대상은 아조레스, 카르타고, 킬와, 랑스 오 메도즈, 마하발리푸람, 라파누이, 포트 지저스, 스강 과이의 현행 도감 ID를 사용한다. 위치·개수·보상 금액을 이번에 새로 늘리지 않는다.
- 개인 도감 기록만 인정한다. 다른 선장의 도감 열람은 보고 조건이 아니다. 정상 정박 중 보고하며 항해·전투·상륙 탐사 등 진행 중인 상태에서는 필요한 종료 행동을 안내한다.

### 3.2 화면과 흐름

1. `수집 도감 → 수집 보상`의 25종 보상 영역에 수락 전·보고 중·완료를 바로 표시한다.
2. 수락 전은 `특별 탐사 받기`, 수락 후는 `기존 발견 기록 보고 · 0/3`, 완료 후는 `✓ 완료 · 500 D 수령`을 표시한다. 수락만 한 상태의 ‘수령함’을 완료 보수까지 받은 상태와 구분한다.
3. 보고 버튼을 누르면 작은 별도 보고 화면을 연다. 대상 중 본인이 발견한 항목만 이름과 체크박스로 표시하고 최대 남은 수량까지 선택한다. 보고 전 소유 도감 상세도 열어 볼 수 있다.
4. `선택한 기록 보고 · 3/3 완료 시 500 D`로 결과를 예고한다. 기존에 1건을 보고했다면 추가 2건만 선택한다. 정박하지 않은 경우 버튼 옆에 `항구에 정박하면 보고할 수 있어요`를 표시한다.
5. 대상 발견물이 부족하면 발견한 수와 추가로 필요한 수를 안내한다. 아직 찾지 못한 대상의 정확한 게임 좌표를 공개하지 않는다.
6. 세 번째 보고와 500 D 지급, 완료 상태 저장은 한 작업으로 처리한다. 완료 후 재열기·재접속·다중 클릭으로 보수가 재지급되지 않는다. 자동으로 이용자 대신 보상을 수령시키지는 않는다.

### 3.3 기존 기록 처리와 검증

- 이미 받은 칭호·깃발·의뢰 수락·개별 보고·완료 기록을 그대로 읽는다. 완료 표시가 이미 있는 계정에는 다시 지급하지 않는다.
- 도감 25종 이상이나 대상 유적이 3종 미만인 경우도 정상적인 진행 상태다. 사후 추가된 도감만으로 25종이 된 선장에게 특정 유적을 요구한다는 점을 명확히 안내한다.
- 기존 발견 8종을 가진 저장, 보고 0·1·2·3건, 완료 상태, 정박·항해·전투, 중복 제출·통신 응답 유실·재접속을 검증한다. 서버 반영 성공 전에 완료 안내를 띄우지 않는다.
- 실제 브라우저에서 보고 영역과 확정 버튼이 잘리지 않고 하나의 스크롤 영역으로 접근되는지 확인한다. 로컬 DOM 검사를 브라우저 화면 검증으로 대신 보고하지 않는다.

## 4. 승격·개발 항구의 일반 지분 투자 통일

| 직접 개발항 / 승격 항구 2·3단계 | 아래 통일 지분 규칙 적용 추천 |
| 운하 | 운하 투자·운항료 규칙 유지, 이번 항구 제도에 포함하지 않음 |

- 다른 선장도 해당 항구에 정박하면 10,000 D 단위로 추가 투자한다. 소유자의 거래 블랙리스트는 기존과 같이 교역·선박 서비스에 적용하며, 지분 경쟁 자체를 영구 차단하는 권한으로 확대하지 않는다.
- 소유자는 **실제 지분 50% 초과** 선장이다. 50:50이면 과반 소유자 없음이며 최대 투자자라는 이유만으로 소유를 주지 않는다. 지분이 여러 명에게 분산돼도 모두 비율에 맞는 세수를 받는다.
- 본인의 인출 가능한 원금은 10,000 D 단위 또는 남은 전액 인출할 수 있다. 받은 금액은 원금의 80%를 정수로 버림하고 나머지 20%는 손실 처리한다. 다른 투자자의 지갑에서 보전하지 않는다.
- 마지막 투자자가 전액 인출해도 완공된 항구와 시설을 삭제하거나 단계·방문·도감 기록을 낮추지 않는다. 무주항은 기본 세율 0%, 초보 보호·입항·필수 보급을 유지한다. 이후 첫 투자 최소금은 일반항구 기준 200,000 D를 적용하는 안을 추천한다.
- 시설 2·3단계와 특산품 개방은 이미 지불한 시설 공사를 기준으로 유지한다. 투자금 인출로 완공된 교역소가 사라지지 않는다. 기존 일반항구의 2배·5배 투자 성장 규칙은 유지한다.

### 4.2 최초 지분 원금 인정

**승격 공동보급항**은 개설 당시 확인 가능한 현금 투자액과 비율을 최초 지분으로 이어받는다. 자재 할인액은 현금 원금으로 만들지 않는다. 승격·확장 공사비는 시설 이용을 위한 비용으로 처리해 별도 지분을 자동 부여하지 않는다. 이는 기존 승격 동의·비용 규칙과 일치한다.

**직접 개발항**은 최초 개발자를 창립 투자자로 인정한다. 추천은 최초 개척 시 실제 차감한 두카트를 최초 원금으로 삼고, 후속 교역소·조선소·고급 보급 공사비는 시설 비용으로 구분하는 것이다. 최초 개척 기본 비용 400,000 D와 실제 할인 후 납부액을 혼동하지 않는다.

- 새로 개발하는 항구부터 최초 결제액·결제자·시각을 공용 장부의 검증 가능한 이력으로 남긴다.
- 기존 직접 개발항은 공유 원장·이관 전 저장·기존 거래 영수증 등 확인 가능한 자료로 최초 결제액을 복원한다. 확인되는 항구부터 이관한다. 자료가 없다고 정가 400,000 D를 실제 납부액으로 단정해 현금 인출 권리를 만들지 않는다.
- **증빙이 없는 기존 항구의 추천 보완안**은 최초 400,000 D를 창립 지분 평가액으로 인정하되, 확인되지 않은 금액은 현금 인출 가능한 원금과 분리하는 것이다. 개발자는 100% 지분과 기존 소유권을 시작점으로 보존하고 이후 새 현금 투자는 정상적으로 투자·인출한다. 이 예외와 초기 평가액은 사용자 검토 대상이다. 채택 전에는 해당 항구의 기존 권리를 보존하고 임의로 지분을 재배분하지 않는다.
- 장부가 불일치한 항구는 원본을 백업하고 그 항구만 기존 규칙으로 유지하며 이관 결과에 사유를 적는다. 다른 항구의 개설·교역을 함께 막거나 저장을 초기화하지 않는다.

### 4.3 원장과 세수의 기준

- 개설 당시 고정된 `registeredCapital`, `registeredOwner`, 기존 개발자 정보는 **개설 이력**으로 남긴다. 이관된 항구의 현재 소유자를 이 고정 필드로 다시 계산하지 않는다.
- 공통 지분 원장은 현재 지분 원금과 투자자 이름, 인출 가능 원금, 소유자, 버전·수정 시각을 가진다. 기존 일반항구와 같은 계산 함수를 사용하되, 공동보급항의 과거 투자 원장과 신규 경제 원장을 혼용하지 않는다. 항구별 공용 상태 한 곳을 기준으로 삼고 지도용 항구 등록은 요약값만 원자 갱신한다.
- 공동보급항의 기존 `dividends`, `activationDividends`, 미수령 보급 수입·세금·기본 세수·재고·소수점 이월을 보존한다. 전환 전 수입은 기존 권리자에게, 전환 후 새로 발생하는 보급 수입과 항구 세수는 새 지분율로 배분한다. 같은 수입을 기존 공동보급 메뉴와 신규 세금 메뉴에서 각각 다시 지급하지 않는다.
- 지분 변경 직전에 서버 시각 기준으로 경과한 기본 세수를 기존 비율로 정산하고, 발생 당시의 몫을 개인별 미수령액에 남긴다. 지분을 모두 인출해도 이전 미수령 수익은 받을 수 있다. 새 비율을 과거 기간에 소급하지 않는다.
- 지급 정수화는 기존 사용자 결정인 반올림·잔여분 이월을 사용한다. 지분 변화 전 미수령액과 분배 잔여값의 단위를 유지하며 새로운 분모로 과거 나머지를 재해석하지 않는다.
- 단계별 기존 기본 세수와 고급 보급 창고 가산은 보존한다. 추천은 2단계 이후 항구에도 투자잔액 / 기준액 200,000 D × 5%, 최대 +50%의 기존 금액 연동 증가율을 적용하는 것이다. 적용 전후의 시간 구간을 나눠 계산한다. 정확한 표시 금액은 부선장·시설 효과까지 반영한 공통 견적으로 제시한다.
- 세금 징수선은 기존 순회 간격·5% 수수료로 본인 몫을 걷는다. 신규 투자자는 순회 대상에 추가하고, 전액 인출자도 미수령액이 남으면 회수 대상에서 바로 빠지지 않는다. 영구 새 폴링이나 전체 항구 다운로드는 추가하지 않는다.

### 4.4 소유권·확장 동의·화면 연결

- 지분 변경 시 지도 `항구명(소유 선장)`, 소유 항구 현황, 선장별 보기, 항구 경영 랭킹, 투자 항구, 징수선, 상주 부선장·자동 교역 권한을 함께 갱신한다. 같은 항구가 경영 수에 중복 집계되지 않는다.
- 소유자가 바뀌면 기존 일반항구와 같이 기본 세율 0%, 개별 세율·블랙리스트 해제를 적용한다. 이전 소유자의 상주 부선장은 소유자에게 반환하고 자동 교역의 미집행 예산·화물은 기존 정산 방식으로 보존·취소한다. 남은 자산을 새 소유자에게 넘기지 않는다.
- 승격 항구의 후속 확장은 현 시점 지분 50% 초과 동의로 확정한다. 각 동의는 지분 원장 버전에 연결한다. 투자·인출로 지분이 바뀌면 미확정 공사 동의는 초기화하고 재동의를 받는다. 오래된 과반 합계로 결제할 수 없게 한다.
- 직접 개발항의 후속 확장도 현재 과반 소유자의 권한으로 연결한다. 과반 소유자가 없으면 투자자의 동의를 합산하는 동일한 절차를 사용한다. 이미 확정한 공사 비용·단계는 지분 변경으로 취소되지 않는다.
- 경합 항구의 기간제 운영권은 현행 만료 시각까지 유지하는 별도 권리다. 투자로 바뀌는 지분 소유와 공방 운영권을 혼동하지 않는다. 이번에 새 항구를 자동 경합 대상으로 추가하지 않는다.
- 투자창에는 내 투자·인출 가능 원금, 총투자, 지분율, 예상 소유자 변화, 세수 배분율, 인출 손실을 표시한다. 창립 평가액 예외가 있으면 평가 지분과 인출 가능한 현금을 나눠 표시한다.

### 4.5 저장 안전성과 검증

- 투자·인출은 개인 두카트, 지분 원장, 시점 정산, 현재 소유자, 등록 요약, 소유 랭킹 갱신을 기존 revision 비교·원자 변경 방식으로 확정한다. 화면 조작만으로 등록자나 소유자 필드를 임의 변경할 수 없도록 Firebase 규칙도 갱신한다.
- 구 클라이언트는 최신 저장·서비스 최소 버전으로 차단해 이전 고정 소유자를 다시 쓰거나 신규 지분을 제거하지 못하게 한다. 항구 이관은 재실행해도 원금·잔액·소유 수가 늘지 않아야 한다.
- 1인·2인 50:50·51:49·10인 분산, 동시 투자·인출, 마지막 전액 인출, 투자로 소유자가 된 초보의 보호 졸업, 승격 직전/직후, 소유권 변경 중 확장 동의, 지분 없음/미수령액 있음인 징수선을 검사한다.
- 시점별 총납부액·인출액·손실·잔액과 모든 미수령 수익의 보존을 대조한다. 운영 장부에서 시험 투자·인출·공사를 실행하지 않고 복제 데이터와 Firebase 에뮬레이터로 검증한다.

## 5. 개인 달성 칭호와 단일 선택 효과

### 5.1 획득·선택 방식

- 현재 랭킹 순위를 유지해야만 쓰는 권한이 아니라, 분야별 기준을 한 번 달성하면 영구 획득하는 개인 칭호다. 종합 1위의 전 서버 축복 권한은 기존대로 별개다.
- `내 배 보기 → 칭호`에서 획득·미획득 목록, 기준, 내 진행도와 실제 효과를 확인한다. 목록 상단에 현재 사용하는 칭호와 `사용 해제`를 둔다. 최초 버전은 아래 22종과 기존 ‘항해 기록가’를 제공하는 추천안이다.
- 동시 활성 칭호는 1개다. 표시용 이름과 효과를 따로 여러 개 장착하지 않는다. 항구 정상 정박 중 변경하며 진행 중 거래·전투·탐사를 끝낸 뒤 바꾼다. 획득은 보상 지급 버튼을 반복 누르지 않아도 안전한 저장 시 판정한다.
- 보유금·소유 항구 수·선단 성장처럼 감소 가능한 값은 이후 감소해도 획득을 회수하지 않는다. 배를 맡겨 선단 성장 수치가 낮아져도 이미 얻은 칭호는 남는다.

| 종합 순위 점수 | 팔방의 항해자 | 서버 집계 종합점수 60점 최초 달성 | 해상 항해 속도 +2% |

- 종합 조건은 1위나 상위 몇 명 조건이 아니라 점수 60.00점이다. 서버 요약의 정수값 6,000과 화면 60점의 단위를 일치시킨다. 다른 참가자에 따라 점수가 변하는 특성이 있으므로 확인 가능한 최신 서버 집계에서 달성한 기록만 남긴다.
- 전투·구조·공동 수송 등은 현재의 정식 집계 함수가 인정한 횟수를 사용한다. 구 저장의 없는 기록을 추정해 채우지 않으며, 시험전·구조 자동복귀·중복 정산을 새 실적으로 만들지 않는다.
- 기존 최고 기록이 저장되지 않은 보유금·항구 수 등은 현재 저장으로 확인 가능한 값부터 소급 인정한다. 과거 대화나 재산 추측으로 획득을 지급하지 않는다. 아이템 수집 조건은 이번에 새 ‘획득 종류’ 산식을 만들지 않고 기존 랭킹 산식과 일치시킨다.

### 5.3 기존 보상과 효과 상한

- ‘항해 기록가’는 기존 도감 10종·일반 상품 구매 1% 할인으로 목록에 편입한다. 이미 획득한 사람에게 재수집을 요구하지 않는다. 기존 활성 상태라면 최초 이관에서 해당 칭호를 선택 상태로 이어간다. 자동으로 더 높은 조건의 새 칭호를 선택하지 않는다.
- ‘수집 기념 깃발’의 기존 해상 속도 2%는 깃발 칸에서 유지한다. 개인 칭호는 깃발 기능과 별도며, 같은 옛 `titleActive`와 새 칭호가 동시에 두 번 계산되지 않게 이관한다.
- 판매는 부선장·교역 장비·판매 칭호를 합해 최대 3%. 구매 할인은 기존 수집 칭호와 같은 일반 교역품 대상이며, 칭호 구매 할인과 활성 부선장의 해당 할인을 합해 최대 3%를 추천한다. 한정·특산품, 선박·대포·투자·운하 사용료에는 일반 구매 할인 효과를 적용하지 않는다.
- 해상 속도 칭호는 기존 부선장·선박 장비의 일반 속도 합산 +20% 안에 넣는다. 기존 기념 깃발은 현행 계산 위치를 유지한다. 선단 최저 성능 기준과 보급 소비 산식이 미리보기·실제 항해에서 일치해야 한다. 자동 구조 이동에는 새 효과를 연결하지 않는다.
- 보급 할인은 실제 지불하는 보급비만 대상으로 부선장·칭호 합산 최대 10%를 추천한다. 환급·보급 크레딧·매각 가격을 늘리지 않는다. 할인해 샀다가 되팔아 수익이 생기지 않는지 확인한다.
- 조합 보수는 조합의 두카트 보수에 기존 부선장 보수 가산과 칭호를 합해 최대 10%를 추천한다. 공동 수송 보수, 퀴즈·발견 명성·탐사 보고 500 D·세수에는 적용하지 않는다.
- 흔적 관찰 거리는 칭호 +5해리만 더하고 실제 조사 가능 거리는 늘리지 않는다. 상륙 속도는 같은 종류의 가산 최대 30%, 수리비 칭호는 선체 수리비 최대 2%, NPC 포격 칭호는 NPC 해적 피해 최대 2%로 제한한다. 다른 종류의 기존 효과를 임의로 동일 상한에 넣지 않고 명세·계산 함수를 분리한다.
- NPC 피해 효과는 PvP·결투·항구 공방에 적용하지 않는다. 교체로 재장전·전투 결과·일일 한도를 초기화하지 않으며 소비품도 재생성하지 않는다. 효과는 포격·보상·구매가 확정되는 서버 기준 동작에서 다시 검증한다.

### 5.4 저장·공개 범위·비용

- 칭호 정의와 조건·문구·효과는 정적 카탈로그로 관리한다. 개인 저장에는 획득 ID·최초 확인 시각과 선택 ID만 추가한다. 획득하지 않은 칭호 선택이나 미등록 ID는 거절한다.
- 개인 실적은 기존 저장·랭킹 산식을 재사용한다. 거래·발견·고용·전투·투자 등 실적이 변한 뒤와 로그인 시 필요한 조건만 판정하고, 매 프레임·매 위치 전송마다 전체 칭호를 저장하지 않는다. 종합점수는 기존 요약 갱신에 연결하고 새 상시 조회를 만들지 않는다.
- 칭호 선택은 개인 저장과 함께 처리하며 다른 선장에게는 선택한 칭호 이름·ID만 기존 선장 상세 요약에 추가한다. 전체 획득 기록·자산·개인 노트는 공개하지 않는다. 실제 배 이름표의 가독성을 위해 지도에서 칭호까지 계속 붙이지 않고 선장 상세에 표시하는 안을 추천한다.
- 신규 칭호 전용 이미지는 최초 범위에 필수로 넣지 않는다. 기존 문양과 글자 배지로 목록을 구성해 추가 이미지 생성·다운로드 비용을 줄인다.

### 5.5 검증 기준

- 22개 항목 각각 기준 직전·정확히 달성·초과, 구 저장 소급 판정, 현재 값 감소 후 보존, 비정상 수치·동일 ID 중복 지급 방지를 검사한다.
- 기존 수집 칭호 활성·비활성, 기념 깃발 사용, 획득만 하고 미선택, 사용 해제, 다중 탭 교체, 저장 실패 복구를 확인한다.
- 표시한 효과와 견적·항해·포격·보수의 실제 계산을 대조한다. 판매 상한, 소액 정수 처리, 보급 크레딧 악용, PvP 미적용, 탐사 가능 거리 무변경을 확인한다.
- 소유 항구 3곳 달성은 최신 지분 원장과 기존 경영 랭킹의 2단계 집계 조건을 사용한다. 오래된 목록 캐시만으로 획득하지 않는다. 종합점수도 로컬 계산이나 다른 사람의 집계로 위조할 수 없게 한다.

## 6. 구현 순서와 연결 파일

1. **계산·저장 기반.** 소문 출처 구조, 통합 효과 상세, 칭호 카탈로그·판정기를 공통 모듈로 정리한다. 항구 이관 대상과 복원 가능한 창립 원금을 읽기 전용으로 점검해 이관 보고서를 만든다.
2. **소문·교역·도감 화면.** 1~3번을 구현하고 기존 계산·보상 호환을 먼저 검증한다. 5번 효과가 아직 없더라도 상세 항목을 추가할 수 있게 만든다.
3. **항구 지분·이관.** 사용자 승인된 4번 기준에 따라 신규 원장·세수·확장 동의·세금 징수선·랭킹·Firebase 규칙을 연결한다. 원본 스냅샷에서 이관을 두 번 실행해 결과가 같음을 확인한다.
4. **칭호.** 개인 판정과 구 수집 칭호 이관, 효과 계산, 선택 화면·공개 요약을 연결한다. 항구 소유·판매 효과가 앞선 기능과 같은 기준을 쓰는지 대조한다.
5. **최종 검증.** 관련 단위·회귀 테스트, 전체 `npm test`, 영향을 받는 Firebase 에뮬레이터 검사와 `npm run notes:check`를 실행한다. PC·모바일에서 소문 재열람, 보고 완료, 효과 상세, 지분 투자·인출, 칭호 선택을 실제 화면으로 확인한다.

주요 연결 대상은 `dist/harbor-officers.js`, `dist/rumor-progress.js`, `dist/rumor-ui.js`, `dist/commerce.js`, `dist/business-ui.js`, `dist/expansion-ui.js`, `dist/projects.js`, `dist/port-income.js`, `dist/tax-collector.js`, `dist/save-game.js`, `dist/public-stats.js`, `dist/ship-rules.js`, `dist/cannons.js`와 Firebase 규칙·랭킹 요약 도구다. 파일 경로는 구현 시 현행 모듈에 맞춰 조정하고 큰 재작성을 하지 않는다.

개인·항구 저장은 현행 스키마 19의 다음 버전을 기준으로 설계한다. 구현 시작 때 다른 변경으로 버전이 올라갔다면 그 최신 값 다음으로 조정한다. 새로운 필드를 모르는 구 클라이언트가 최신 기록을 덮어쓰지 못하도록 서비스 최소 버전과 함께 올린다.

## 7. 배포·문서·제안 완료 처리

- 이 문서 작성으로 서버를 닫거나 배포하지 않는다. 구현·배포 지시가 내려오면 공통 배포 지침을 따른다.
- 게임 설명서의 항구 경영, 교역, 부선장·장비, 발견 도감, 선장 상세 원고에 실제 반영된 규칙과 버튼 위치를 갱신한다. 계산·조건은 카탈로그를 기준으로 유지하고 수정할 곳을 불필요하게 늘리지 않는다.
- 공개 대문에 점검 문구와 개선 기능 설명을 먼저 게시해 확인한 뒤 운영 접속을 잠시 닫는다. 필요한 항구 이관과 코드·최소 버전·규칙을 적용하고 공개 버전과 새 저장 읽기를 검증한 뒤 다시 연다.
- 적용 후 문제가 생기면 잘못된 이관 위에 옛 장부를 덮어쓰지 않는다. 새 기능만 끄는 호환 복구안을 준비하고, 서버를 다시 열기 전에 전환 중 투자·수령이 있었는지 확인한다. 신버전 저장을 보존할 수 있는 정상 버전으로 복구한다.
- 게시판은 실제 반영 뒤에만 완료 처리한다. 제다 글은 재열람 검증 뒤, 상자 글은 효과 검증과 안내 개선 뒤, 수집 글은 기존 수집자의 보고 동선 검증 뒤 처리한다. 항구 투자 두 글은 새 투자·인출·이관이 실제 적용된 뒤 함께 처리한다. 칭호 글은 획득·선택·효과가 적용된 뒤 처리한다.
- 완료 글은 기존처럼 작은 비활성 완료 항목으로 남겨 접수·처리 이력을 보존한다. 이번 계획 단계에는 게시판 상태를 바꾸지 않는다.

## 사용자 검토가 필요한 추천 결정

1. 승격·직접 개발항의 **2단계부터** 일반 지분 투자·20% 손실 인출을 적용하는 안.
2. 직접 개발항의 최초 실제 개척 결제액만 창립 원금으로 인정하고, 후속 시설 공사비는 지분에서 제외하는 안. 증빙 없는 구 항구는 400,000 D 평가 지분과 확인된 인출 원금을 구분하는 예외안.
3. **새 칭호 22종**, 표의 달성 기준·효과와 단일 선택 방식. 기존 수집 칭호·기념 깃발의 권리를 보존하는 합산 상한안.

나머지 소문 기록 보존, 장비 효과 설명, 기존 도감 보고 개선은 검토 결과를 구체화한 구현·검증 명세다.
