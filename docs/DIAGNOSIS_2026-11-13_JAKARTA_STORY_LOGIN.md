# 자카르타 정향 미션·보상 부선장 접속 오류 확인 (2026-11-13)

사용자 요청은 자카르타에서 정향을 살 수 없는 이야기 단계와 철인보급대의 접속 실패 확인이다. 사용자의 후속 배포 지시에 따라 공개 버전 `2026.11.13-stories-harbors-tax.1`로 반영한다. 개인 항해 저장을 운영자 권한으로 변경하지 않고, 상품 명세와 서버 규칙을 수정한다.

## 자카르타 정향

`dist/story-catalog.js`의 말라카 중급 이야기 단계 `malacca-broker:9`는 자카르타 정향 3상자 구매를 요구한다. 실제 시장은 `tools/port-catalog.json`에서 생성되며 자카르타 판매 목록은 커피·설탕·생강·염료목·후추·면직물만 포함했다. 다섯 이야기의 구매 단계를 전체 대조한 결과 불일치는 이 한 건이었다.

원본 상품 명세에 정향을 `import`로 추가하고 `tools/build-catalog.mjs`로 `dist/port-economy.js`를 갱신했다. 기존 품목을 제거하지 않으므로 자카르타는 판매 품목 7종이다. 활성 항구의 상품 수 검증 상한도 7종으로 맞췄다. 기존 단계 ID·수량·납품 상품·완료 보상은 유지한다.

## 철인보급대 접속 실패

운영 `releaseStatus.maintenance=false`, 최소 저장 버전 9, 정상 게임 규칙을 확인했다. 선장 이름에 해당하는 계정 한 건을 찾고 해당 계정의 저장·선단·이동 체크포인트와 적용 규칙만 읽었다. Google 계정 인증 여부 자체를 운영 계정으로 대신 로그인해 시험한 것은 아니다.

해당 저장의 복사본을 `demo-windward-login-iron` 에뮬레이터에 넣고 실제 `CaptainAccount.enter()` 흐름을 실행했다. 개인 저장 이관은 성공하지만 선단 전투 상태 쓰기가 세 번 거절되어 최종 접속이 실패했다. 보상 부선장 아미나의 전투 요약 `skill`이 `OS01:…`인데, 선단 상태와 공개 전투 프로필 검증은 기존 `O001`~`O024`만 허용한 것이 원인이다. 공개 수집 카드만 새 ID를 허용하고 전투 요약 두 경로를 누락했다.

두 경로의 인물 ID 정규식에 `OS01`·`OS02`만 추가했다. 단계 1~5, 네 개의 0/1 표시, 본인만 변경, 타인 전투 상태 보존 등 기존 제한은 유지했다. 개인 저장의 schemaVersion이나 revision 규칙은 완화하지 않았다. 수정 규칙으로 원본과 같은 저장 복사본의 접속 성공을 확인했다.

## 검증과 운영 반영 시 유의점

- `npm test`: 226개 통과. 새 검증은 모든 이야기 구매 단계의 실제 판매 가능 여부를 확인한다.
- `npm run test:rules`: 전체 통과. 실제 계정 진입 흐름으로 두 보상 부선장 각각의 schema 8→9 이관, 접속, 후속 저장, 공개 전투 프로필 등록을 확인하고 미등록 `OS03`은 거절되는지 검사한다.
- `npm run notes:check`: 통과.
- 원인 확인 중 운영 사용자 저장을 변경하지 않았다. 운영 반영에는 새 상품 명세를 포함한 정적 파일과 수정 Firebase 규칙이 모두 필요하다. README의 점검 안내 게시·공개 확인·접속 중단·배포·접속 재개 절차를 따른다.
- 원본 운영 저장과 재현 자료는 무시 경로 `.qa/`에만 보관하며 배포물과 공개 문서에 사용자 UID·개인 저장 본문을 싣지 않는다.
