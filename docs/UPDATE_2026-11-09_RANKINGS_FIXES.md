# 14종 랭킹 · 평면 미니맵 · 해적전 후속 업데이트

사용자 지시: 앞서 개선안에 모은 내용을 합쳐 수정·배포한다. 기존 공동 시장·전투·선단 기능을 유지하며 신규 대기 4묶음(해적 연속 발사 오류, 평면 미니맵, 전투 랭킹 3종, 추가 랭킹 6종)을 처리한다.

## 구현

- 기존 5종 + 새 9종 = 14종. 교역·탐험·선단/경영·전투 분류와 기준 선택으로 모바일 폭을 확보한다. 기존처럼 선택 기준 top 5 하나만 구독하며 접으면 해제한다.
- 종류·방문은 중복 제거, 선단 성장은 배마다 단계+1 합계다. 실제 섬의 항구 여부는 확인한 명부를 사용한다. 최고의 한 거래는 한 건 판매분 원가·세금을 뺀 정수 이익의 최댓값이다.
- 해적 처치는 토벌 완료 때, 결투 승리는 본인 결과를 최초 정산할 때 집계한다. 자유 PvP 격파는 상대 HP 0일 때만 세고 항복·시간 종료는 침몰로 세지 않는다. 선박 영구 삭제를 추가하지 않는다.
- `rankProgress`는 기존 v4 게임/v5 저장에 선택 확장한다. 기존 돈·화물·배·안개·방문·소문을 보존하며 초기화를 하지 않는다. 과거 저장에 없는 횟수는 추정하지 않는다.
- 항구 소유 변화는 이전/새 소유자의 독립 공개 카운터를 같은 요청에 포함한다. 모든 카운터의 revision·항구 영수증·본인 저장 revision을 규칙에서 연결한다. 오프라인 개인 저장은 건드리지 않는다.
- 해적전에서는 필요한 슬롯 전환만 전송한다. 구버전의 동일 NPC 슬롯 쓰기와 빈 슬롯 삭제도 본인 원자 개인 저장에 한해 멱등 허용한다. PvP 슬롯 덮어쓰기는 차단한다. null 경로를 조회하던 한 방 토벌 규칙도 수정한다.
- 미니맵은 보기별 data 속성으로 CSS를 구분한다. 평면은 2:1·직사각형·자동 높이, 지구본은 1:1·원형이다. 평면 회전 안내를 제거하며 클릭은 카메라만 바꾼다.
- 보관함 미장착 안내·장착 방법 안내 버튼·전투 저장 거절 문구를 개선하고 공개 패치노트와 JPG 6쪽을 갱신한다.

## 검증

- 최종 통합 `npm test`: 119개 통과. 거래 집계, 저장 복원, 결투/격파 구분, 14종 순위, 기존 저장·게임 흐름과 추가 게시판·지도 전투를 포함한다.
- 최종 통합 `npm run test:rules`: 격리 Database Emulator 7묶음 통과. NPC 연속 발사·빗나감·반격·재접속·토벌·한 방 토벌·후퇴·재전송, 소유권 과반/동률·오프라인 선장·동시 투자·위조 거절, 공개 집계 이관·게시판을 검증한다.
- UI DOM 검사는 폭 1280/390/360에서 계산 스타일·메뉴·큰 조사 창을 확인한다. 실제 브라우저 제어 도구는 커널 자산 경로 오류로 초기화에 실패했다. DOM 검사를 실제 모바일 렌더링/기기 조작 검증으로 표현하지 않는다.
- JPG는 실제 규칙 수치와 대조하고 6쪽을 이미지로 점검한다. 배포 후 운영 게임에서 시험 포격·거래·보상을 발생시키지 않는다.

## 운영 순서와 기존 기록 보강

1. 새 이관 도구는 `--project=windward-voyage`를 명시해야 운영 접근하며 기본은 읽기/백업/예상 결과만 수행한다.
2. `WINDWARD_FIREBASE_TOOLS`에 인증된 Firebase CLI 패키지 경로를 설정한다. `node tools/refresh-ranking-summaries.mjs --project=windward-voyage`로 확인 후 `--apply`로 공개 요약만 보강한다.
3. 도구는 1회 서버 저장·공개 요약·항구 지분을 백업한다. 기존 소유 장부는 덮어쓰지 않고 새 장부만 만들며, 요약은 ETag와 saveRevision으로 더 최신 기록을 보호한다. 마지막 접속 시각은 보존한다. 개인 저장·항구·계정 경로 쓰기는 코드에서 금지한다.
4. 테스트한 DB 규칙 → 공개 집계 보강 → GitHub Pages 소스 push 순서로 배포한다. 새 규칙 이후 구버전은 카운터가 없는 소유권 변경이 거절될 수 있으므로 이관과 프런트 배포를 이어서 수행한다.
5. 공개 파일을 라이브 HTTP로 비교하고 Actions 성공을 확인한다. 새로운 비용 서비스·Cloud Functions·요금제 변경은 없다. 집계 시 1회 관리자 읽기와 작은 공개 쓰기가 추가되며 일상에서는 필요한 카운터만 읽는다.
