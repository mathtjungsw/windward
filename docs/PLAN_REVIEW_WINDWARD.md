# 바람의 항로 · 전체 상세계획 교차 검토

이 문서는 개선안 1~25번 중 삭제한 13번을 제외한 24개 항목을 대상으로 한다. [기존 상세계획](../DEVELOPMENT_PLAN.md)의 개별 화면과 수치를 참조한다. 이전 초안이 여러 의미로 읽히는 부분은 아래 규칙으로 통일한다. **확정**은 사용자 결정이고, **추천**은 구현 전에 검토할 기본값이다. 이번 작업은 설계와 시안 작성이다.

## 먼저 맞춰야 할 공통 규칙

- **시간.** 시장 행사, 공방, 서신, 항구 내정, 부선장 교역은 운영 서버 기준 시각을 쓴다. 날짜가 바뀌는 고용·일일 납품과 주간 운하 목표는 한국 시간 달력을 쓴다. 24시간 내정 변경과 4시간 교역은 마지막 처리 시각을 기준으로 한 경과 시간이다. 15번 수집품만 게임 속 실제 항해 진행량으로 소모하며 정박이나 일시정지 중에는 흐르지 않는다.
- **소유와 운영.** 과반은 정확히 50%를 초과해야 한다. 동일 항구에서 투자 지분, 기간제 운영권, 공개 공지, 거래 정책과 세금 귀속을 각각 판정한다. 운영권은 만료 시각부터 효력이 끝난다. 남아 있는 정리 작업이나 누군가의 접속 여부는 판정에 영향을 주지 않는다.
- **돈과 아이템.** 금액·재고·소유권 같은 저장 변경에는 작업 번호를 붙인다. 장부 기록과 지급을 함께 확정하며 재접속이나 응답 유실로 재시도할 때는 기존 결과를 반환한다. 기존 Firebase 거래 방식으로 안전하게 합칠 수 없는 다계정 지급은 신뢰할 수 있는 정산 설계를 별도로 검증한 뒤 연다. 작업별 최소 읽기 경로를 검토한다.
- **버전 호환.** 지형 표시와 보기 설정은 기기별 저장으로 관리한다. 화물 ID, 원가, 방문·발견 ID, 이미 확정한 의뢰와 운하 예약 금액은 유지한다. 저장 정책이 달라지는 기능만 이전 버전과의 쓰기 호환성을 검증한다.

## 항구 공방과 외교 · 1~6번

| 항목 | 구체화한 설계와 검증 |
| --- | --- |
| **1. 항구 공격·방어** | 모의전은 양쪽 수락과 동일 예산으로 시험한다. 본 공방은 공개된 시간에 운영 선장의 수락 없이 열리며, 방어에 참여하지 않으면 자동 포탑을 사용한다. 공방 1회에 항구 하나당 한 경기만 열고, 여러 도전자가 있으면 같은 기간의 신청자 중 사전에 고지된 순서로 한 명을 선정한다. 추천은 신청 순서에 따라 자격을 확인하고, 이미 보호 중이거나 운영권이 바뀌었으면 시작 전에 표기하는 방식이다. 승자의 지분은 바뀌지 않는다. 운영 기간에는 투자와 인출이 가능하며 만료 시점의 과반 선장이 운영을 이어받는다. 추천 세금 배분 범위는 해당 기간에 새로 발생한 교역세의 일부다. 세율 설정·거래 차단 권한은 과반 지분 소유자에게 둔다. 배분율과 운영 기간은 검토 항목이다. |
| **2. 사병·선원** | 호위와 주둔을 둘 다 허용한다. 기본 20초 점령 기준에서 공격 호위는 최대 2초 단축, 방어 주둔은 최대 2초 연장을 추천한다. 인원과 훈련 효과는 해당 상한 안에서 계산한다. 최대 손실은 참가 인원의 20%를 내림한 값이며 준비 화면에 표시한다. 자동 방어 때 보유 사병 손실은 적용하지 않는 추천안이다. |
| **3. 부재 중 보호** | 개인별 8시간 예약 대신 공개 공방 시간 밖에서 공격을 막는다. 방어 선장이 없으면 사전에 정한 자동 배치, 배치가 없으면 기본 포탑을 사용한다. 자동 방어 경기에서 공격자 이탈은 60초 유예 뒤 기권을 추천한다. 직접 방어 경기의 동시 이탈은 무효 처리한다. 패배 후 24시간 재도전 제한과 다음 도전 시각은 시범안이며, 기간제 운영권과 지분 승계 시각은 예정대로 처리한다. |
| **4. 거래 재개 요청** | 자유 문구는 공백 제거 후 1~300자를 추천한다. 항구·신청자당 진행 중 한 건, 48시간 만료, 거절·만료 후 24시간 재요청을 유지한다. 권한자가 바뀌면 기존 요청을 종료하고 대기를 부과하지 않는다. 승인 처리 직전에 제한 목록에서 해당 선장만 해제한다. |
| **5. 입항 공지·외교 서신** | 공지는 운영 선장, 거래 제한은 정책 권한자가 관리한다. 서신의 첨부금은 발송 시 출금 후 보류, 수락 시 지급, 취소·거절·48시간 만료 시 원래 발신자에게 반환하는 추천안이다. 수신 차단 상태면 새 보류가 생기기 전에 발송을 막는다. 두카트 수락과 거래 재개는 별도 행동이다. 권한 전환, 동시 수락·취소와 만료 경계를 검증한다. |
| **6. 세율 상한** | 기본·개별 각각 0~30%, 개별 설정 우선, 개별 0%는 유효, 삭제 시 기본값으로 복귀. 면세와 기존 세율 데이터는 유지한다. 정책 변경 직후 이전 견적을 확정할 수 없게 하고, 검색·구매·판매·정산과 저장 검증을 함께 바꾼다. |

## 경제·지역 성장 · 7~11번, 18~19번

| 항목 | 구체화한 설계와 검증 |
| --- | --- |
| **7. 특산품** | 성장 판정은 현재 투자원금 합계 + 해당 기준의 20%까지 인정한 납품 기여다. 단계 기준은 최초 투자 기준의 2배·5배, 재고 50·100상자. 결제 직전 재고가 30이면 구매 가능하고 29면 대기한다. 30은 구매 자격의 문턱이며 한 거래에서 그 아래로 내려갈 수 있다. 전환할 품목마다 기존 판매처·의뢰·수량·마지막 보충 시각을 기록한다. |
| **8. 조합 납품** | 완료 보수와 성장 기여를 분리하고 지분에는 영향을 주지 않는다. 동일 납품 완료는 한 번만 인정한다. 시범 검증 예시는 일반항 1단계에 투자 32만·기여 8만, 2단계에 투자 80만·기여 20만이다. 2단계 기준을 계산할 때 1단계 기여를 다시 차감하지 않는다. |
| **9. 도시 내정** | 성장 2단계에서 관광·생산·무역 하나를 고르는 추천안이다. 24시간 뒤에 다시 변경하고, 직접 변경 전까지 선택은 남는다. 투자 부족으로 2단계 아래로 내려가면 선택을 저장한 채 효과가 멈추고, 복구하면 다시 적용하는 방식을 추천한다. 과반이 없는 동안에도 새 효과는 멈춘다. 이미 수락한 의뢰의 보수와 이전 수입은 보호한다. |
| **10. 운하 수익 장부** | 척당 300 D 상한과 5척 1,500 D의 할인 전 결제를 예약·실제 진입·저장 검증에 함께 반영한다. 장부는 입구 정산을 선단 1회로 세고, 11번은 출구까지 통과한 별도 기록을 쓴다. 7일 통계와 회수 전망은 집계 시작일을 보여주며, 과거 미확인 배당을 0으로 단정하지 않는다. |
| **11. 운하 공동 보상** | 지정 운하 완주 후 기한 내 납품해야 인정한다. 의뢰가 주를 넘기면 완료 주에 기여를 기록하는 안을 추천한다. 동일 운하에서 한 계정의 첫 완료만 집계한다. 목표 달성 때의 지분으로 공동 보상을 한 번 배분하고, 일반 통행료와 분리한다. 3명·3,000 D·추가 보수 500 D는 검토용이다. |
| **18. 수요·공급 행사** | 8시간 예고, 24시간 진행. 구간은 시작 시각 포함·종료 시각 제외로 판정한다. 예상 시세와 결제는 같은 규칙으로 계산하며, 거래 중 행사 경계를 넘으면 다시 확인받는다. 품목·항구가 겹치는 중복 행사를 먼저 막고 장비·칭호 등의 효과가 겹칠 때 같은 항구에서 즉시 되팔아 이익이 생기는 경우를 검증한다. |
| **19. 투자금 인출** | 인출액의 80% 지급, 20% 손실과 성장 단계 재계산 확정. 견적에 지급액, 손실액, 인출 후 소유자·단계와 함께 특산품 구매 중단·재고 한도 축소를 보여준다. 100→50 전환 때 이미 남은 초과 물량은 즉시 없애지 않고 50 이하가 될 때까지 보충을 멈추는 안을 추천한다. 1단계 미달이면 신규 구매 잠금, 기존 화물 판매 유지. 단계 복구 시 재고 보충에는 잠긴 기간을 소급 적용하지 않는 안이다. |

## 탐험과 부선장 · 12번, 14~17번, 23번

| 항목 | 구체화한 설계와 검증 |
| --- | --- |
| **12. 도감 이정표** | 10종 칭호, 25종 특별 의뢰, 40종 깃발 보상 유지. 1% 구매 할인과 2% 선단 해상 속도는 추천값이다. 칭호·깃발은 정박 중 선택하며, 속도 효과는 가장 느린 배 기준으로 산출한 선단 속도에 한 번 적용한다. 지급은 이정표별 한 번이고 새 도감 항목을 추가해도 기존 수령 기록을 유지한다. |
| **14. 해적 의뢰** | 밀수선 회수와 표류 화물 수색 두 종류를 주점에서 제공한다. 지정 NPC나 표류물을 의뢰 ID에 연결해 같은 회수 기록으로 보수를 두 번 받을 수 없게 한다. 돌발 사건은 참여 의뢰에서만 최대 한 번을 추천한다. 포기·구조·기한 만료의 화물과 보수 처리를 의뢰 UI에 표시한다. |
| **15. 희귀 수집품** | 사용 후 가방에서 소모, 다시 획득 가능, 도감 기록 보존. 같은 품목을 미리 쌓아두지 않도록 효과형은 품목당 한 개 보유를 추천한다. 능동 효과가 없는 기념품은 도감형이다. 재획득은 효과 종료 뒤 단서와 조사 조건을 다시 충족하게 하는 추천안이다. 배속·일시정지·재접속에도 게임 속 항해일 기준으로 검증한다. |
| **16. 상주 배치** | 과반 지분 보유자의 항구에 고용 부선장을 배치하고 승선 효과는 멈춘다. 항구당 한 명, 부선장당 한 곳. 과반 지분을 잃으면 명부 복귀, 다른 선장이 기간제로 운영하면 배치를 유지하고 효과만 일시 정지하는 안이다. 중지 직전까지의 세수는 원래 귀속에 남긴다. |
| **17. 가상 교역** | 계정당 한 항로, 현실 4시간당 1회, 최대 100상자, 순수익 상한 없음, 이익 수수료 10%. 두 항구가 연결되고 유효한 다른 항구인지와 교역 권한을 실행 전에 확인한다. 가상 시세 거래는 실제 재고·시세 압력·본선 화물·상대 항구 세금 장부를 바꾸지 않는 추천안이다. 과거 시세가 없으면 첫 유효 장부 조회 시점에 양쪽 견적을 한 번 확정한다. 미수령 한 건만 보관하며 밀린 회차를 한꺼번에 만들지 않는다. |
| **23. 발견물 확대** | 12종 시범을 유적·흔적 5, 서책·비문·기록물 5, 해저 유물 2로 나눈다. 각 후보표에 지역·시대·출처·조사 위치 유형·획득 조건·명성·삽화를 기록한다. 직지 등 역사 실물과 게임 속 조사 기록을 구분하고, 실제 발견 위치는 내 도감만 표시한다. 최종 품목과 위치는 기존 목록·실제 접근성 검증 후 확정한다. |

## 지도·항구 명부·화면 편의 · 20~22번, 24~25번

| 항목 | 구체화한 설계와 검증 |
| --- | --- |
| **20. 지도 확대·축소** | 현재 배율 최대 100%, 최소 25%. 버튼은 정해진 단계로, 휠·핀치는 조작점 기준으로 이동하는 안이다. 배 추적 중에는 배를 기준으로 하고 ‘내 배 위치’는 배율을 유지한다. 축소 상태에서도 시야 밖 배가 나타나거나 핀치 종료가 해역 출항 명령으로 이어지지 않아야 한다. |
| **21. 소유 항구 보기** | 항구별 기본, 선장별은 항구 수 내림차순, 마지막 선택은 기기에 저장. 지분 소유자와 기간제 운영자는 따로 표시하고, 두 목록은 동일한 공개 현황의 화면 변환으로 작성한다. 보기를 바꿔도 서버를 새로 읽지 않는다. |
| **22. 버튼 사용 분석** | 최근 최대 7일의 실제 집계부터 확인한다. 하단 화물과 정박 시 가능한 주점은 동일한 기회에 노출되는지 별도 검토한다. 통계에 조작 경로나 개인별 편차가 없으면 판단 유보라고 쓴다. 낮은 사용률이 확인되면 기본 바로가기 교체·더보기 중복 제거를 추천하고, 차이가 크거나 개인별 선호를 파악할 수 없으면 맞춤 설정 시안을 검토한다. 시안 수치는 실제 이용 현황으로 인용하지 않는다. |
| **24. 신규 항구** | 첫 4~6곳 추천. 후보마다 두 방향 자동 항로, 직접 입항 위치, 인접 항구 거리와 단계별 보급, 지역 상품·설명, 관련 소문을 표에 넣는다. 기존 대양 난이도를 무너뜨리는 연결은 후보 교체를 먼저 검토한다. |
| **25. 지도 표현과 복귀** | 클래식과 정밀 자산의 경로·버전을 별도로 관리한다. 플레이어 전환과 운영 복구를 각각 시험한다. 운영 복구가 켜져 있으면 개인 정밀 선택보다 우선하며, 해제 시 개인 선택을 복원한다. 정밀 타일이 실패하면 약도 또는 클래식을 즉시 표시하고 다른 화면 기능을 계속 이용할 수 있게 한다. 축소는 세계 약도 중심, 확대는 근처 타일만 요구한다. |

## 순서와 통과 조건

1. **독립 기능을 먼저 검증한다.** 22번 운영 집계 읽기와 보고서, 21번 명부 표시, 4번 요청 흐름, 20번 카메라 좌표와 25번 클래식 전환을 병행할 수 있다.
2. **경제 변경의 공통 장부를 먼저 구성한다.** 6번 시세 계산, 7·8·19번 성장과 인출, 9번 내정, 16·17번 상주·가상 교역, 18번 행사 순서로 결제·권한 경계를 확인한다. 5번 첨부금은 두 계정 정산 검증을 통과한 뒤 켠다. 10번 운하 집계와 결제 경계를 검증한 뒤 11번 공동 보상을 연다.
3. **공방은 모의전에서 검증한 다음 경합 항구로 옮긴다.** 1·2·3번의 경기 종료, 자동 방어, 부재, 운영권 승계, 보상 귀속을 함께 시험한다. 12·14·15·23·24번 콘텐츠는 테스트용 항로에서 기존 기록·시나리오와 함께 확인한다.
4. **지도 기본값은 실측 뒤 정한다.** 같은 기기와 항로에서 클래식·정밀을 각각 반복 측정하고 차가운 캐시와 재방문을 구분한다. 추천 기준은 첫 지도 표시 중앙값이 클래식 대비 20% 넘게 악화되지 않고, 항해 중 긴 프레임이 지속적으로 증가하지 않는 것이다. 모바일에서 두 조건을 반복해 넘으면 클래식을 기본값으로 둔다. 기능 승인은 게임 상태를 보존한 채 수동·운영 양쪽 전환이 모두 성공하는 경우에만 진행한다.
5. **배포는 공지 → 접속 중단 → 새 버전 검증 → 재개.** 여러 영역을 한 번에 올리기보다 이미 검증한 묶음으로 배포한다. 데이터 전환을 함께하는 릴리스는 이전 코드·자산과 저장 호환 여부, 영향받은 거래의 복구 경로를 확인한다.
