## 3. 모바일 메뉴와 공통 화면

### 3.1 상단 메뉴

브랜드 행, 접속 상태·업데이트·도움말 행, 주요 메뉴 행을 각각 안정적인 줄로 배치한다. 모바일 주요 메뉴는 독립된 너비를 갖는 2열 또는 4열 그리드로 두고 긴 문구는 자연스럽게 줄바꿈한다. PC에서는 이용 가능한 폭에 따라 메뉴 간격을 조정한다.

버튼의 최소 터치 높이는 44px다. 320/360/390/414px, 큰 글자 설정, 가로 화면에서 글자와 밑줄, 접속자 수와 업데이트 버튼의 겹침을 확인한다. 메뉴가 더보기에 들어가면 같은 이름과 실행 위치를 제공한다. 팝업은 내용에 맞는 크기와 내부 스크롤, 접기·닫기를 제공한다.

### 3.2 유용한 기능

모바일 더보기와 PC 조작·화면 설정에서 ‘유용한 기능’을 연다. 첫 항목 ‘항구 도착 시 자동 보급’을 체크박스로 제공하고 항구·보급 화면에도 켜짐 상태와 목표 보급량을 표시한다. 설정은 계정에 저장하고 로컬 캐시를 함께 사용한다.

새 메뉴는 조합, 진행 중 의뢰, 아이템 가방, 부선장 명부, 소문노트, 상륙 탐사, 운하·공동 거점으로 구성한다. 상단에는 현재 즉시 필요한 행동을 두고 상세 목록은 더보기와 항구 화면으로 연결한다. 배 이동을 가리는 고정 팝업은 콘텐츠 크기를 제한하고 접을 수 있게 한다.

### 3.3 반복 갱신 감소

전투 표시의 전투 ID·포격 sequence·내구도·재장전 초, 명단의 ID·접속 상태, 랭킹의 순위·점수·표시 항목을 비교해 바뀐 행만 갱신한다. 새로 생성하는 HTML 수와 화면 갱신 CPU를 비교한다. 이동 중 선박 보간과 포탄 효과는 해당 프레임에 필요한 상태로 갱신한다.

### 3.4 주점과 소문노트

주점은 모든 소문을 하나의 목록에 섞어 같은 ‘소문’ 버튼으로 제공한다. 이야기 속 항구, 인물의 행동, 물건의 흔적을 읽고 선장이 목적을 짐작한다. 각 소문은 들을 수 있는 항구, 등장 조건, 다음에 갈 항구나 해역, 준비물 또는 추천 선단을 정한다. 조건을 충족하면 해당 주점에서 열 수 있도록 하고, 읽을 때 안정적인 소문 ID를 계정에 등록한다. 미발견 장소는 해역과 방향으로 안내하고 발견 조건이 충족되면 지도 연결을 제공한다.

항구 화면에서 주점 옆의 ‘소문노트’ 탭을 연다. 항해 중에도 열 수 있다. 노트는 읽은 소문의 첫머리·본문·출처 항구를 보여준다. ‘읽은 소문’과 ‘숨긴 소문’ 사이를 전환할 수 있다. 인물이나 물건의 정체와 의뢰는 단서를 따라 해당 항구의 사람을 만날 때 드러난다. 같은 소문을 다시 눌러도 목록에 중복 추가되지 않는다. 소문 열람에는 재방문이나 재결제가 필요 없다.

소문 카드의 ‘숨기기’를 누르면 기본 목록에서 빠지고 ‘숨긴 소문’에 남는다. 바로 실행 취소하거나 ‘다시 표시’로 복원할 수 있다. 숨기기는 표시 설정이며, 이미 얻은 단서와 의뢰 진행은 그대로 사용할 수 있다. 완료한 소문도 선장이 숨길 수 있다. 새 기기에서도 같은 계정의 숨김 상태를 불러온다.

현재 저장의 읽은 탐험 소문 ID를 기존 카탈로그와 연결해 노트에 표시한다. 과거 열람 시각이 없는 항목은 날짜를 생략한다. 소문 본문과 조건은 게임 파일에서 읽고, 계정에는 읽은 ID와 숨김 ID, 새로 읽은 시각이 필요한 경우 그 시각만 저장한다. 읽기·숨기기·복원은 행동 시점에 저장한다.

## 4. 지도·이동·항구 좌표 정합성

### 4.1 현재 코드에서 확인한 점

장식용 지도는 정밀 Natural Earth 해안선과 섬을 사용한다. 이동 판정 `Navigator`는 0.5도 격자를 쓰며, 판정 셀을 가장 가까운 격자 중심으로 반올림한다. 위도 방향으로 한 셀은 약 30해리에 해당한다. `approach()`는 항구 좌표가 육지 판정일 때 가까운 바다 격자로 옮기지만, 항구 마커와 입항 후 위치는 항구의 lon/lat를 사용한다. 자동 항로가 출발·도착 좌표를 경로에 덧붙이는 구간도 정밀 해안과 대조할 필요가 있다.

위 구조가 제보와 관련될 수 있다. 항구별 실제 어긋남의 위치와 크기는 재현 자료로 확인하고 수리할 좌표를 정한다.

### 4.2 통일할 기준

도시를 설명하는 `city`, 실제 선박이 정박하는 `berth`, 바다에서 접안으로 이어지는 `approachPath`를 구분해 카탈로그에 기록한다. 지도 항구 마커, 자동 항해 목적지, 직접 조종 입항, 정박 선박 좌표는 `berth`를 사용한다. 도시 좌표는 설명과 육상 탐사의 출발 지역에 사용한다.

지형 조각, 판정용 해안 자료와 항구 검증은 같은 고정 원본 버전에서 생성한다. 강과 운하는 지도·이동에 공통 중심선과 폭 정의를 사용한다. 지도 가장자리 연결은 현재 `project`/`unproject`와 동서·남북 감싸기를 공통으로 적용한다.

### 4.3 정밀 판정과 성능

원양 항로 탐색에는 기존 전역 격자를 활용하고, 해안·섬·항구 주변에는 정적 세부 판정 타일을 추가하는 방식을 추천한다. 세부 격자 간격은 0.025도, 위도 방향 약 1.5해리를 초기 목표로 한다. 해안거리 캐시와 `coastAt()`도 같은 해안 기준으로 생성해 연안 항해 한도 판정과 비교한다. 세부 타일은 가까운 영역과 계획 항로에 필요한 부분을 읽고 이웃 타일을 미리 캐시한다.

자동 경로의 각 선분과 출발·접안 연결선을 세부 판정으로 확인하고, 육지와 교차하면 해안 주변 경로를 다시 찾는다. 직접 조종도 같은 판정으로 막는다. 작은 섬, 해협, 강 하구의 예외 통로는 지도에도 같은 수로로 표현한다. 지역 경로 계산이 길어지면 Web Worker에서 수행하고 이동 입력과 지형 이미지 재사용을 이어 간다.

### 4.4 기존 진행과 검증 산출물

78개 주요 항구, 개발 후보, 보존한 과거 항구에 대해 도시·접안점 거리, 실제 수역 여부, 연결 경로의 육지 교차 여부를 표로 남긴다. 강 중심선과 접안 연결도 함께 확인한다.

기존 정박 저장은 같은 항구 ID의 검증된 접안점으로 맞춘다. 기존 해상 위치가 새 판정에서 육지로 바뀌면 이전 이동 구간과 인접 수역을 확인해 연결된 안전 위치와 재계산 항로를 제시한다. 좌표 보정은 발견·방문·보상 판정과 함께 검증한다. 비접속 선박의 공유 위치, 방어 장부, 개인 이동 체크포인트도 같은 navigationVersion으로 맞춘다.

정상 항해와 구조 항로, 저장 복원, 동서·남북 경계, 강과 바다 사이 이동을 검사한다. 정밀 판정 목표와 지도상 해안 표시의 차이는 위치별 허용 오차를 수치로 남긴다.

## 5. 항구 도착 시 자동 보급

입항 한 건에 `arrivalId`를 부여한다. 정상 자동 항해·직접 입항·구조 완료가 중앙 입항 처리로 모인 뒤, 항구 이용 상태와 전투/방어 정산을 확인하고 자동 보급을 한 번 실행한다. 구조의 지원 보급을 정산한 다음 부족분을 보급하는 순서로 추천한다.

목표는 선단 보급 한도다. 현재 보급, 화물·대포·의뢰 화물 무게, 보급 크레딧, 보유 두카트로 충전 가능한 양을 구한다. 돈과 적재 여유가 부족하면 살 수 있는 양만 충전하고 ‘자동 보급 3.2일 · 29 D 사용’처럼 결과를 표시한다. 수량이 0이면 공간·자금·한도 중 해당 이유를 알려준다.

부동소수 수량은 기존 `resupply()` 계산과 같은 기준을 사용한다. 실제 비용은 기존 보급 크레딧을 차감한 뒤 계산한다. 보급과 자금 변경, `autoSupplyReceipts[arrivalId]`를 같은 경제 행동으로 저장한다. 새로고침·재접속·반복 탭은 영수증을 확인한다. 오프라인 상태에서 도착한 기록은 접속 후 입항 정산과 함께 처리한다.

설정을 정박 중 켜면 다음 입항부터 적용한다는 문구와 현재 ‘보급하기’ 행동을 함께 제공한다. 전투 보관금·화물 보관 상태가 해제되는 입항 흐름에서도 같은 적재 계산을 사용한다.

## 6. 최고가 판매처에서 바로 출항

각 검색 결과의 ‘지도에서 보기’ 옆에 ‘항구로 이동’을 둔다. 버튼에는 현재 항구, 미발견, 통행 불가, 구조·전투 중 등의 상태를 표시한다. 이동을 누르면 먼저 목적 항구·현 위치·선박 능력·사용 가능한 운하·통행료·보급으로 새 경로를 검증한다.

후보 경로가 유효하고 필요한 보급과 통행료를 확보한 뒤, 진행 중인 항해를 새 목적지로 전환한다. 검색창을 닫고 자동 항해와 내 배 추적을 시작한다. 검증 중에는 버튼을 처리 중 상태로 두고 연속 탭을 합친다. 실패하면 현재 항해와 검색 결과를 보여주면서 이유를 안내한다.

기존 `autoToPort()`는 진행 중 경로를 먼저 비우므로, 목적지 사전 검증과 확정 단계를 분리해 일반 항구 선택에도 함께 적용한다. 출항 직전 최신 위치와 게임 revision이 바뀌면 다시 검증한다. 최고가 결과에는 검색 시각·가격 변동 안내와 현재 장착 보너스를 표시한다. 실제 판매는 입항 후 현재 견적으로 처리한다.

## 7. 소유 항구의 기본 세수

### 7.1 누적과 수령

기본 세수는 실제 서버 시간과 해당 항구를 소유한 기간으로 계산한다. 일반 1,000 D/시간, 대형 3,000 D/시간, 개발 항구는 완공 단계 500 D/시간·교역소 개설 뒤 1,000 D/시간을 추천한다. 보유 기간의 시작과 마지막 정산 시각, 현재 적용률과 미수령액을 저장한다.

각 항구는 현 소유자에게 발생하는 기본 세수를 72시간분까지 모은다. 거래 세금은 거래 때 발생하는 기존 원장에 누적한다. 기본 세수의 소수 두카트는 내부 잔여값으로 이월하고 수령액은 정수로 확정한다. 수령 횟수를 나눠도 총수입이 같게 한다.

소유 항구 화면은 항구별 기본 세수, 거래 세금, 시간당 수입, 누적 한도, 마지막 정산 시각과 수령 버튼을 표시한다. 목록 조회 때는 예상액을 계산하고 수령 때 확정한다. 소유자별 항구 인덱스로 필요한 항구만 읽는다.

### 7.2 소유권·효과 변경

투자로 소유권이 바뀌는 서버 시각에 전 소유자의 세수를 정산해 해당 UID의 미수령 원장에 넣고 새 소유 기간을 시작한다. 지분이 정확히 50%가 되어 소유자가 없는 기간의 기본 세수는 0으로 추천한다. 전 소유자는 자신에게 귀속된 세금을 소유 항구 목록의 미수령 항목에서 수령할 수 있다.

운영 시설·아이템·부선장으로 세수율이 바뀌면 변경 시각까지 기존 비율로 먼저 정산한다. 항구 세수에 영향을 주는 부선장 효과는 지정 소유 항구 1곳을 대상으로 시작하는 안을 추천한다. 동행 교체 시 해당 항구 원장과 개인 설정을 함께 확정한다.

수령은 항구 원장의 해당 UID 잔액과 개인 두카트를 함께 변경한다. 소유권 변경·수령이 동시에 일어나면 revision을 다시 읽어 재계산한다. 기존 `treasury`에 적립된 거래 세금은 같은 UID로 수령할 수 있게 이관한다. 최초 적용의 기본 세수 시작 시각은 새 기능 활성화 시각과 실제 소유 시작 시각 중 늦은 쪽으로 추천한다.

### 7.3 운영 방식

조회·수령·투자·시설 변경·부선장 변경 같은 관련 행동에서 정산한다. 한도에 찬 시간은 추가 수입으로 이월하지 않고, 수령 뒤 새 기간을 시작한다. 과거 소유권 기록과 매 시간의 저장 대신 현재 구간과 미수령 원장·최근 영수증을 보관한다.

## 8. 항구 조합 의뢰

### 8.1 게시와 수락

항구 화면의 ‘조합’에서 일반 납품, 위탁 수송, 조사 보고, 해적 토벌, 공동 수송 의뢰를 제공한다. 개인 게시판은 항구·현실 날짜·선박 능력에 따른 정적 템플릿으로 구성하고, 수락한 의뢰만 계정에 저장한다. 동시에 최대 3건을 추천한다.

수락 화면에는 출발·완료 장소, 대상 품목과 수량, 예상 항로·거리·보급, 마감 날짜와 시각(KST), 남은 시간, 보수, 성공 명성, 기한 초과 명성 차감을 표시한다. 미발견 목적지나 현재 선단으로 갈 수 없는 경로는 해당 이유와 필요한 준비를 보여준다.

### 8.2 의뢰 종류와 초기 보수

| 종류 | 완료 조건 | 초기 보수 추천 | 기한 추천 |
| --- | --- | --- | --- |
| 인근 일반 납품 | 지정 항구에 일반 상품 5~10상자를 가져가 납품 | 납품 견적액과 추가 보수 150~400 D | 현실 30분 |
| 지역 위탁 수송 | 봉인 화물 5~15상자를 목적 항구 조합에 전달 | 400~1,200 D | 현실 6시간 |
| 장거리 수송 | 선단 보급으로 갈 수 있는 권역의 화물 10~30상자 전달 | 1,500~4,000 D | 현실 24시간 |
| 조사 보고 | 수락 후 해당 흔적·상륙 거점을 실제 조사하고 조합에 보고 | 300~1,200 D, 명성 10~30 | 현실 6시간 |
| 해적 토벌 | 수락 후 지정 NPC 해적을 토벌하고 기록 제출 | 500~1,500 D, 의뢰 명성 10~30 | 현실 24시간 |
| 공동 수송 | 참여 선장들이 목표 수량을 분담해 전달 | 기여 수량 비율에 따른 보수 | 현실 24시간 |

일반 납품은 자신의 상품을 사용한다. 완료 확인 화면에는 납품 전 시세로 전체 수량을 계산한 판매액, 세금, 조합 보수를 따로 표시한다. 기존 판매와 같은 수량 제한과 시장 변동 규칙을 적용해 화물 차감·시세 변동·판매액·보수·완료 기록을 한 번에 저장한다. 위탁 화물은 의뢰 ID와 운반 무게를 갖고, 납품할 때 원장과 함께 소멸한다. 일반 화물과 위탁 화물의 적재량을 합산한다. 위탁 화물의 인도 상태를 경제 행동에 연결해 반복 수락·납품 보상을 검사한다.

### 8.3 마감과 명성

마감은 수락 서버 시각과 의뢰 기한으로 결정한다. 성공은 필요한 행동이 마감까지 확정됐을 때 인정한다. 일반 납품·수송은 목적지에서 ‘납품 완료’가 마감 조건이다. 조사·토벌은 필요한 기록을 기한 안에 만든 뒤 보고하는 방식으로 정의하고, 카드에 ‘행동 완료 마감’과 ‘보고 가능 상태’를 표시한다.

기한을 넘기면 상태를 실패로 확정하고 쉬움 5·보통 15·어려움 30의 명성을 차감한다. 명성은 당시 가진 수치까지 차감하는 안을 추천한다. 실제 차감량과 의뢰 ID를 기록한다. 일반 포기는 같은 실패 정산으로 추천하고, 완료 전에는 포기 후 결과를 미리 안내한다.

성공·실패·포기는 한 번만 확정한다. 기존 발견물·해적 명성에 의뢰 명성과 실제 차감 누계를 더해 총명성을 계산하며 도감의 발견 기록을 보존한다. 랭킹과 선장 상세 정보도 같은 총명성을 사용한다.

서버 시간이 마감을 판단하고 온라인 화면은 남은 시간만 갱신한다. 만료 정산은 다음 접속·의뢰 조회·경제 행동에서 실행하는 안을 추천한다. 오프라인 선장의 공개 랭킹은 최근 확정 저장 시점의 명성을 표시하며, 정산이 이루어지면 새 명성으로 갱신한다. 이 표시 시차를 운영 설명에 남긴다.

### 8.4 공동 의뢰

공동 의뢰는 프로젝트 ID, 전체 목표, UID별 수락량·완료량·보수 수령 영수증을 갖는다. 마지막 납품이 동시에 들어오면 남은 수량까지만 확정하고 개인 화물 차감과 기여량을 함께 저장한다. 완료 보수는 확정 기여 비율로 분배한다. 종료 때 참여자가 자신의 정산을 수령한다.

## 9. 상륙 탐사와 내륙 교역

### 9.1 거점형 육상 지도

입항한 항구 또는 검증된 해변 상륙점에서 ‘상륙 탐사’를 연다. 배가 정박한 출발점을 표시하고, 내륙 마을·산길·유적을 연결한 작은 지도를 제공한다. 이동 간선마다 현실 시간, 탐사 보급, 운반 한도와 예상 보상을 보여준다.

첫 카탈로그는 6개 항해 권역에 2곳씩 총 12개 상륙점, 상륙점별 3~5개 거점을 추천한다. 항구형 탐사를 먼저 연결하고 해변형 탐사를 추가한다. 초기 탐사는 간선 10~30초·전체 왕복 1~3분, 후반 탐사는 간선 30~90초 또는 2~5분·전체 왕복 5~15분을 추천한다. 지도상 진행은 행동 시작·완료 시각으로 계산한다.

선장은 안전한 일반 길, 보급을 더 쓰는 지름길, 단서가 필요한 유적 길 가운데 선택한다. 발견물은 최초 조사 기록을 남기고, 반복 탐사에서는 지역 물품이나 정해진 소규모 보상을 얻는다. 내륙 특산품은 배로 귀환할 때 적재 공간과 매입 원가·획득 경로를 기록한다. 유적 정보와 지리 설명에는 확인한 출처를 붙인다.

### 9.2 탐사와 선박의 상태

항구형 탐사 중 배는 실제 정박 항구에 남는다. 해변형 탐사 중 배는 검증된 수상 정박점에 남고 해상 선박의 피격 규칙을 적용하는 안을 추천한다. 탐사 시작 화면에서 배의 정박 위치와 노출 상태를 안내한다.

탐사 중 배 이동 요청은 먼저 귀환 행동으로 연결한다. 탐사팀의 임시 가방과 선박 화물은 각각 수량과 적재 한도를 갖는다. 임시 가방의 물품은 배로 돌아온 뒤 선박 화물에 옮기며, 공간이 모자라면 항구 창고 보관 또는 일부 운반을 선택한다.

해변 정박 중 배가 패배·구조되면 해당 방어 기록 시각에 탐사를 중단하고 미수령 보상을 정산한다. 초기 추천은 해당 탐사의 미수령 보상을 잃고 선장은 방문 항구로 구조된 배에서 재개하는 방식이다. 사전에 실패 결과를 안내한다. 오프라인 피격이 접속 후 반영될 때도 같은 기록을 기준으로 처리한다.

### 9.3 내륙 교역

내륙 마을은 지역 상품과 한정 공급량을 갖는다. 구매 또는 납품 시 선장 자금, 탐사 가방, 마을 재고를 함께 확정한다. 첫 상품은 기존 일반품 가운데 지역성이 맞는 품목을 활용하고 신규 상품을 추가할 때 기존 화물 ID와 원가를 함께 검증한다. 대표 왕복 거래를 계산해 항구 교역과 내륙 운반의 시간당 수익을 비교한다.

## 10. 바다 활동

활동은 실제 선박 시야 안에서 표식과 큰 행동 버튼으로 알린다. 예상 소요 시간, 얻는 물품 또는 보수, 화물 여유와 보급 소모를 보여준다. ‘활동 지점으로 이동’과 ‘활동 시작’을 제공하고 항로를 계속 가는 행동도 함께 둔다.

| 활동 | 초기 추천 동작 | 재활성·보상 기준 |
| --- | --- | --- |
| 어장 | 정지한 배에서 20초 어획, 식량 또는 어획 상품 획득 | 개인별 지점 30분 간격, 보급 한도·적재 확인 |
| 표류 화물 | 같은 바닷길 20해리 안에서 10초 회수 | 개인별 지점 2시간 간격, 일반품 1~3상자 또는 목록의 소형 보상 |
| 구조 요청 | 20초 구조 후 가까운 방문 항구에 데려가 보수 수령 | 개인별 6시간 간격, 100~400 D와 소규모 명성 |
| 침몰선 조사 | 소문·표식 조건을 갖추고 수상에서 조사 | 최초 도감 보상과 개인별 24시간 반복 회수 보상 |

활동 위치는 권역별 정적 후보에서 고르고 주기와 UID로 활성 여부를 계산한다. 개인별 완료 영수증만 저장하는 방식으로 시작한다. 실제 해적과 같은 전투 목표는 현재 공유·개인 전투 규칙에 맞춰 별도 검증한다.

정상 이동과 활동 완료의 명성·수집을 연결한다. 구조 이동에서는 원래의 발견 제한과 상태 전환을 검증한다. 활동 중 공격받거나 입항·이동을 시작하면 진행 가능 상태를 다시 확인하고, 중단 시 실제 사용한 자원과 수령 여부를 확정한다.

## 11. 공동 보급 거점과 운하

### 11.1 공동 보급 거점

기존 해안 후보 중 실제 수상 접근이 가능한 곳에서 공동 투자로 보급 거점을 개발한다. 초기 6권역 1곳씩 총 6개를 추천한다. 1단계 자재 창고, 2단계 보급소를 두며 총 300,000 D·현실 6시간을 초기 비교값으로 둔다. 기여량과 완료 시각을 공개한다.

보급소는 비축량과 구매 비용을 갖고, 선장은 입항에 준하는 거점 도착 절차 후 보급한다. 건설과 보급 재고는 해당 거점 경로만 읽고 확정한다. 거점의 선박 보호·소유 정책은 기존 항구 개발과 함께 하나의 규칙으로 정한다. 추천은 보급소 완공 후 정식 개발 항구로 등록해 정박 보호·기본 세수·소유권 계산을 연결하는 방식이다.

### 11.2 운하 후보와 초기 사업비

| 후보 | 연결 지리 | 게임 사업비 추천 | 게임 공사 시간 추천 | 지리 근거 |

| 코린토스 지협 | 코린토스만과 사로니코스만 | 1,200,000 D | 현실 6시간 | [운영사 자료](https://corinthcanal.com/images/CORINTHIAN_WEEK.pdf) |

### 11.3 투자·완공·운영

투자는 10,000 D 단위로 시작하고 최종 부족액까지만 받는다. 자금이 모이면 공사 시작·완료 시각을 고정한다. 공사 전 기여금 회수와 공사 개시 뒤 처리 규칙을 화면에서 명시한다. 초기 추천은 공사 전 본인 기여금 회수 가능, 공사 개시 뒤 공동 사업에 사용되는 방식이다. 마지막 투자와 회수 요청이 겹치면 같은 사업 기록의 버전을 검사해 한 요청을 먼저 확정하고, 나머지는 변경된 공사 상태로 다시 판단한다.

운영자는 누적 지분 50% 초과 선장으로 추천한다. 통행료 기본값은 0 D이고 상한은 선박 한 척당 200 D를 비교값으로 둔다. 소유자가 없는 동안 기본 통행료 0을 적용한다. 통행 수입은 투자 비율대로 각 선장 원장에 누적하는 안을 추천한다.

완공은 서버 시각이 완료 시각에 도달하면 조회·출항 시 확정한다. 운하 수로를 지도와 경로 그래프에 같은 버전으로 반영한다. 바다 구간과 여러 운하·강 구간을 잇는 경로 탐색을 지원하고, 운하 구간은 강 속도를 초기 기준으로 쓴다. 현재 두 끝점의 강과 바다를 잇는 `Navigator.route()`를 수로 입구·출구 그래프로 확장하고, 기존 동기 호출의 준비·로딩 상태를 출항 제어와 함께 다룬다.

통행료는 출항 때 예상액을 표시하고 운하 진입 시 한 번 확정한다. 예약한 통행료의 보관금과 영수증을 사용해 같은 횡단에서 중복 청구되지 않게 한다. 출항 후 통행료가 바뀌면 이미 예약된 통행에는 예약 금액을 적용한다. 예약하지 않은 직접 조종 진입은 현재 금액을 안내하고 승인 동작 후 진입한다. 왕복은 각각의 횡단으로 계산한다. 항로 변경·취소·구조 시 아직 진입하지 않은 구간의 예약금은 같은 처리에서 되돌려 준다. 이미 확정된 통행료는 유지한다.

운하·거점 수입은 UID별 수령 원장으로 보관하고 개인 수령 때 두카트와 함께 확정한다. 투자·통행·배당 각각의 operationId를 기록한다. 배당을 두카트 단위로 나눌 때 남은 금액은 원장에 보존해 다음 배당에 합산하며, 총 배당액은 실제 받은 통행료를 넘지 않는다. 공사 중 위치, 불완전한 끝점, 다중 운하 경로, 경계 연결, 통행 취소·재접속을 검증한다.

## 12. 특수 아이템 64종

### 12.1 획득·보관·장착

특수 아이템 64종은 모두 주점 단서와 획득 조건을 갖는다. 주점에서 방법을 들은 뒤 관련 항구에 가서 의뢰·조사·납품·제작 조건을 충족해야 첫 획득이 열린다. 부록 A의 상점·조선소·조합·도감 등은 조건을 확인하고 구매하거나 보상을 받는 장소다. 초기 상점에 연결된 품목에도 지역 활동을 한 번 완료하는 조건을 붙인다.

| 난도 | 첫 획득 조건 추천 |
| --- | --- |
| 일반 특수품 | 소문 1개와 해당 지역의 짧은 의뢰·조사·납품 1건 |
| 지역 특수품 | 소문 1개와 서로 다른 항구 또는 조사 지점 2곳을 잇는 활동 |
| 희귀 특수품 | 여러 지점의 단서를 모은 뒤 고난도 의뢰 또는 유물 회수·제작을 완료 |

예비 노는 주점에서 납품처를 듣고 연안 운송 의뢰를 마쳐야 조선소에서 제작할 수 있다. 강화 돛은 조선소와 직물 공급 항구를 잇는 납품 의뢰로 구매 자격을 얻는다. 해류 지도는 주점 단서에 나온 두 해역의 측량을 마친 뒤 받는다. 항구 기념 주화도 그 지역 주점의 단서를 듣고 현지 조사나 교역 의뢰를 완료해 얻는다. 정확한 활동과 조건을 품목마다 카탈로그에 기록하고 담당자를 만난 뒤 의뢰 화면에 표시한다.

기본 비교 가격은 소모품 100~1,000 D, 일반 장비 2,000~8,000 D, 지역 장비 8,000~20,000 D다. 소모품은 첫 획득 조건을 완료하면 자격을 저장하고, 이후 해당 판매처의 재고·가격 조건 또는 반복 의뢰 보수로 보충한다. 소문과 획득 조건은 달성할 수 있는 고정 경로로 제공한다.

배마다 항해 장비 1칸, 선장에게 교역 1칸·탐사 1칸을 추천한다. ‘내 배 보기’는 배별 장비 이름과 효과, 선단 교역 장비를 표시한다. 아이템 가방은 장착 위치를 표시한다. 사용 증서는 적용 대상과 잔여 횟수·수량을 기록한다. 일지·기념 수집물은 도감에 보관한다. 기본 조작과 자동 보급은 유용한 기능의 계정 설정으로 제공한다. 일지 관련 아이템은 추가 저장 칸·연관 이야기 같은 수집 효과로 설계한다.

출항 중 장착 변경은 다음 입항에서 확정하는 안을 추천한다. 효과로 적재나 보급 한도가 달라지면 해제 전에 공간과 초과 보급 정산을 보여준다. 소모품은 관련 거래·이동·의뢰 확정과 함께 한 번 소비한다. 항해당 사용 제한은 출항부터 다음 실제 정박까지의 sailingId로 관리한다.

### 12.2 효과 계산

같은 종류의 비율 보정은 합산 후 상한을 적용한다. 장비와 부선장 포함 최종 속도 +20%, 세후 판매 보너스 +3%, 명중률 보정 +6%p를 초기 추천 상한으로 둔다. 피해·방어 보정은 각각 +10%·피해 감소 10%를 비교 기준으로 시작한다. 최종 명중률의 상한은 95%를 추천한다.

항해 속도 효과는 각 배에 적용한 뒤 최저 선박 속도를 택한다. 보급 절감, 적재 확장, 강 전용 속도는 별도 항목으로 계산해 출항 견적에 반영한다. 거리 제한 소모품은 실제 항해한 거리만 차감하고 재접속 시 잔여 거리로 이어진다.

판매 보너스는 시작 시세로 전량 계산한 세후 수령액에 더한다. 거래 세금과 시세 압력은 원래 수량·가격으로 계산한다. 보너스의 1 D 미만 잔여분을 계정의 같은 효과 항목에 이월해 거래를 나눠도 총액이 같게 한다. 매입 할인은 판매 보너스와 같은 지역·품목 한도 및 상한을 검토하고 대표 왕복 거래로 검증한다.

최고가 검색은 현재 보너스를 적용한 예상 수령액을 표시한다. 다음 한 번만 쓰는 증서는 적용 대상·상자 한도와 검색 이후 소진 가능성을 알려준다. 실제 거래에서는 유효한 증서와 잔여 한도를 재검사한다.

부록 A의 64종을 전체 범위로 관리한다. 기능 의존성이 있는 아이템은 해당 육상·공동 의뢰·운하 기능이 완성되는 단계에서 획득 경로와 효과를 함께 제공한다.

## 13. 역사 인물 부선장 24명

### 13.1 고용과 성장

관련 주점의 소문 → 인물과 첫 만남 → 인물별 실적과 합류 의뢰 → 고용비 확인 → 명부 등록 → 동행 선택으로 이어진다. 고용비는 일반 5,000 D, 지역 특화 15,000 D, 고난도 의뢰 연계 30,000 D를 비교값으로 둔다. 초기 추천은 일회 고용비 방식이다.

명부에는 후보 24명을 모두 다룬다. 동행은 1명이며 입항 중 교체한다. 숙련도는 1~5단계로 추천하고 실제 항해 거리·의뢰·탐사·전투 성과로 얻는다. 기본 효과의 100/110/120/130/140%를 단계별 비교값으로 두되 전체 보정 상한을 적용한다. 효과가 조건형이면 발동 횟수나 보상 범위로 성장을 설계한다.

인물 카드에는 초상·한국어 및 원어 이름·활동 시대·주요 행적·자료 출처·게임용 능력·고용 조건·비용·숙련도를 표시한다. 활동 해역과 인물별 특수 능력은 부록 B와 원문 자료를 연결한다. 초상 원본의 이용 조건을 확인하고 프로젝트 그림체에 맞는 카드 자산을 준비한다.

### 13.2 첫 만남과 합류 이벤트

부록 B의 24명 모두 일정 항해 경력을 쌓은 뒤 등장한다. 최초 단서는 관련 해역의 주점에서 읽는다. 소문을 얻은 후 이야기에 나온 항구를 찾아가면 첫 만남 장면과 합류 이벤트가 열린다. 합류는 인물별 실적을 충족하고 별도의 마지막 의뢰를 마친 뒤 고용비를 지불하는 순서로 진행한다.

| 후보 구분 | 주점 소문이 등장하는 조건 추천 | 합류 조건 |
| --- | --- | --- |
| 지역형 · 고용비 5,000 D | 기함 7단계 ‘연안 교역선’급 이상, 서로 다른 항구 실제 방문 8곳 | 부록 B의 관련 실적과 지역 합류 의뢰 |
| 전문형 · 고용비 15,000 D | 기함 9단계 ‘쌍돛 연안선’급 이상, 실제 방문 12곳 | 부록 B의 관련 실적과 여러 지점을 잇는 전문 합류 의뢰 |
| 고난도형 · 고용비 30,000 D | 기함 10단계 ‘항해 캐러벨’급 이상, 실제 방문 18곳 | 부록 B의 관련 실적과 인물 전용 고난도 합류 의뢰 |

선박·방문 기준은 해금 시점 검증에 사용할 초기 추천값이다. 해당 권역에 도달할 수 있는 경로가 있는지 확인하고, 인물별 의뢰에 추가 선박·포대·탐사 요건이 있으면 소문에 표시한다. 구조로 이동하거나 주점에서 항구 정보만 얻은 경우는 실제 방문 수에서 제외한다. 읽은 소문과 완료한 실적은 배를 교체해도 저장하고, 실제 의뢰 실행에는 그 의뢰의 항해 조건을 적용한다.

명부에는 만남 이후 합류 의뢰를 시작한 인물을 표시하고, 의뢰 진행·고용 가능·고용 완료 상태를 보여준다. 후보 카드는 현재 단계, 다음에 할 일, 관련 항구로 가는 버튼을 제공한다. 합류 이벤트는 짧은 대화와 기존 항해·교역·탐사·전투 행동으로 구성한다. 방문·수송·토벌 횟수처럼 부록 B가 요구하는 실적은 확인 가능한 기존 기록을 인정하고, 충족한 선장은 그 기록을 바탕으로 합류 장면을 열 수 있다. 기존 기록으로 확인할 수 없는 행동만 현재 진행도로 표시한다. 마지막 장면에서 효과와 고용비를 보여주고, 선장이 고용을 선택하면 명부에 등록한다.

| 인물 | 합류 이벤트 예시 | 플레이 행동 |
| --- | --- | --- |
| 장보고 | 주점에서 ‘끊긴 교역로’ 소문을 듣고 조합에서 만남 | 수송 실적 3건을 채우고 합류 의뢰의 물자를 지정 항구에 인도한다 |
| 이순신 | ‘해협의 봉화’ 의뢰를 통해 만남 | 연안 방어 의뢰 3건을 완료하고 인물 전용 의뢰의 방어 결과를 보고한다 |
| 정성공 | ‘섬 너머의 보급로’ 상륙 의뢰에서 만남 | 상륙 탐사 후 배로 귀환하고 보급로를 보고한다 |
| 정일수 | ‘흩어진 수송선단’ 소문을 통해 만남 | 3척 선단 수송 실적을 확인받고 합류 의뢰로 물자를 전달한다 |

이름과 실제 행적은 인물 카드의 역사 설명에, 합류 장면과 대사는 창작 이야기로 표시한다. 항구 입장 때는 작은 알림으로 소개하고 상세 장면은 선장이 눌러서 연다. 진행을 중단해도 조합이나 명부에서 이어서 볼 수 있다. 이벤트 대화·조건은 게임 파일에 두고, 계정에는 인물별 진행 단계와 완료 기록만 저장한다. 고용 확정 때 보유금과 완료 상태를 확인해 비용 차감과 등록을 함께 처리한다.

### 13.3 전투와 항구 효과

동행 교체 시 적용 전후 속도·보급·수령액·명중·재장전·내구도를 보여준다. 전투 시작 기록에 부선장 ID·숙련도·장비·적용 보정과 적용 버전을 고정한다. 첫 시도·첫 명중·특정 내구도 조건은 같은 전투 sequence에서 판정한다.

자유 공격, 동의 결투, NPC 해적, 오프라인 반격에 같은 효과 계산 함수를 사용한다. 결투의 기존 성능 보정과 부선장 보정을 함께 표기한다. 최대 내구도가 바뀌면 손상 비율을 적용해 현재 내구도를 계산한다. 항구 기본 세수 보정은 지정 항구 1곳과 적용 시작·종료 구간으로 기록한다.

이순신·장보고·최무선·드레이크·콜링우드·정일수·피리 레이스·진린의 8가지 대표 유형으로 계산을 검증한 뒤 24명 전체에 적용한다. 최종 범위의 인원과 효과는 부록 B의 24명이다.

## 14. 서버·저장·비용 설계

### 14.1 기능 데이터와 읽기 범위

| 데이터 | 저장·조회 범위 |
| --- | --- |
| 지도·상륙·활동·아이템·인물 카탈로그 | 버전이 붙은 정적 파일, 현재 화면·해역 중심 캐시 |
| 개인 설정·소문노트·가방·부선장·의뢰·탐사 | 본인 저장과 필요한 개인 원장 |
| 항구 세수·시설·투자 | 선택한 항구와 본인 소유/미수령 인덱스 |
| 운하·공동 거점·공동 의뢰 | 해당 프로젝트 요약과 선택한 상세 |
| 전투 효과 | 실제 교전 기록과 필요한 양쪽 방어 상태 |
| 순위·선장 명부 | 기존 요약 경로와 페이지 단위 조회 |

개인 게임 데이터 v5·저장 봉투 7을 목표로 이관 명세를 작성한다. 현재 파서로 과거 저장을 복원한 뒤 새 필드의 기본값을 채우는 순서다. 신규 경로는 `guild`, `land`, `seaActivities`, `inventory`, `officers`, `usefulFeatures`, `fameLedger` 등 기능별 버전과 함께 설계한다.

접속·경제 행동의 정산 순서는 방어 장부 반영, 의뢰 만료·육상 중단 판정, 입항·지원 보급, 자동 보급, 요청한 행동 확정으로 설계한다.

공유 데이터는 기존 `gameV2/shared/ports/{portId}`에 세수 구간·잔액을 추가하고, 운하·거점·공동 의뢰는 각각 독립된 작은 경로로 둔다. 소유 항구/미수령 원장 인덱스를 사용자별로 유지한다. 전체 DB 다운로드를 평소 기능의 기본 동작으로 만들지 않는다.

### 14.2 경제 행동과 동시 처리

개인 저장, 공유 원장, 관련 인덱스와 영수증을 revision을 확인하는 같은 확정 단위로 변경한다. 현재 `atomicAction()`과 저장 큐를 확장하고, 둘 이상의 관련 공유 원장을 다루는 행동에는 읽은 각 revision의 조건을 붙인다. 한 기능에서 두카트·화물을 먼저 차감한 뒤 다른 원장 저장을 기다리는 처리의 실패·재시도를 검증한다.

수락·납품·실패·보급·고용·소모품·투자·통행·배당마다 operationId를 부여한다. 응답을 잃으면 확인된 저장과 영수증으로 결과를 복원한다. 개인 비공개 JSON은 본인 계정의 저장 경계를 통해 갱신하고, 다른 선장에게 귀속된 금액은 공유 UID별 수령 원장으로 확정한다.

서버 규칙에는 소유자와 수령자, 수량·금액 한도, catalogue ID, 서버 시각·마감, 현재 상태와 다음 상태, 중복 영수증, 개인/공유 revision 연결을 검증한다. 정적 카탈로그에서 검증에 필요한 ID와 수치 표를 생성하는 절차를 둔다.

### 14.3 시간과 운영 비용

현실 시간은 서버 기준 시각과 offset으로 표시하고 정산 시 서버 규칙의 시각 검사를 적용한다. 기기 시계 변경·재접속·백그라운드 복귀를 검사한다. 시간 UI는 화면에서만 갱신하고 DB 변경은 관련 행동에서 실행한다.

위치 전송은 현재 일반 항해 최소 2초, 정지·접속 유지 30초를 기준으로 유지 동작을 검증한다. 대결 전송은 현재 교전 규칙을 기준으로 한다. 아이템/부선장 효과 자체를 위치 패킷마다 다시 저장하지 않는다.

추가 비용 요인은 개인 저장 크기, 새 경제 행동 횟수, 공동 프로젝트 구독이다. 필요한 경로만 읽고 모달 종료·해역 이탈 시 구독을 해제한다. 기능별 읽기 bytes와 저장 횟수를 로컬·에뮬레이터에서 비교해 실행 기록에 남긴다. 정적 이미지와 지리 자료는 기존 GitHub Pages 배포를 활용한다.

## 15. 저장 이관과 복구

1. 현재 개인 저장·항구 투자·미수령 세금·방어 장부·위치 체크포인트의 읽기 백업과 카탈로그 버전을 기록한다.
2. 과거 저장을 복원해 신규 필드 기본값과 navigationVersion을 채운다. 자금·원가·선박·대포·투자·명성의 전후 비교표를 만든다.
3. 기존 소유 항구는 기능 활성화 시각을 기본 세수 시작 기준으로 등록한다. 기존 거래 세금은 UID별 잔액을 이관한다.
4. 위치 보정과 구조·항해 중 저장의 재계산을 기록한다. 방어 장부·공유 선단·개인 위치의 연결을 검증한다.
5. 신규 규칙과 호환 클라이언트의 배포 순서를 정하고, 구버전 저장 요청에는 갱신 안내와 안전한 이어하기를 제공한다.
6. 일부 계정·원장에서 충돌하면 최신 revision을 다시 확인한다. 이미 확정된 신규 자산과 영수증을 포함해 복구할 수 있는 형식을 준비한다.

## 17. 검증 시나리오

- 모바일 상단은 320/360/390/414px와 큰 글자·가로 화면, PC는 작은 창부터 넓은 화면까지 버튼 글자·터치 영역·가로 넘침을 확인한다.
- 모든 항구의 바다·강 접근과 직접 입항, 소형 섬·좁은 해협, 날짜변경선·북남 경계, 항해·구조·재접속 좌표를 확인한다.
- 자동 보급은 자금·보급 크레딧·적재 한도·다척 선단·대포 무게·위탁 화물·구조 후 입항·응답 유실을 조합한다.
- 판매처 바로 이동은 직접/자동 항해 중 선택, 미발견·현재 항구·부족 보급·통행료 변경·전투·실패 시 기존 경로 보존을 확인한다.
- 세수는 0시간·분 단위·72시간 초과·반복 수령·정확히 50% 지분·소유권 교체·과거 소유자 수령·부선장 교체를 확인한다.
- 의뢰는 마감 직전/정확한 경계/직후, 이미 완료한 조사·토벌, 화물 손실·중도 포기·명성 0·중복 지급·오프라인 만료를 확인한다.
- 상륙과 바다 활동은 두 기기 동시 실행·중복 회수·가방 초과·배 피격·구조·완료 시점 재접속을 확인한다.
- 운하는 동시 최종 투자·공사 완료 경계·왕복 통행·가격 변경·취소·다중 운하·직접 진입·공동 수입 수령을 확인한다.
- 아이템·부선장은 전체 ID별 획득 조건과 조건부 효과, 중첩 상한, 소모 횟수, 판매 반올림, 최저 선단 속도, 오프라인 반격까지 비교한다.
- 부선장 24명의 기함·방문 해금 경계, 주점 단서, 기존 실적 인정, 인물별 합류 의뢰, 재접속, 고용비 부족과 두 기기 동시 고용을 검사한다. 특수 아이템 64종의 첫 획득에는 각각 지정된 단서와 활동 조건이 적용되는지 검사한다.
- 소문노트는 기존 탐험 소문 이관, 항해 중 열람, 숨기기·복원, 재접속과 기기 변경을 확인한다. 숨긴 소문을 단서로 쓰는 조사·합류·아이템 획득도 검사한다.
- 구현 단계에서 `npm test`, `npm run test:rules`, `npm run notes:check`를 실행하고 필요한 생성 도구로 정적 자산을 갱신한다. 규칙 변경은 해당 에뮬레이터 시나리오를 추가한다.
- 실제 기기 또는 브라우저 화면 확인과 DOM·계산 검사를 따로 기록한다. 확인하지 못한 화면·과금 사용량·장기 성능은 실행 기록의 제한 사항으로 남긴다.

## 18. 배포 시 결과 전달
