# 바람의 항로 · 다음 업데이트 상세 개발계획

이번 범위는 [개선안](../IMPROVEMENTS.md)에 대기 중인 항해 거리·시간 표시, 검색형 게임 설명서, 초보 선장 보호다. 아래의 초보 졸업 단계와 적용 예외는 추천안이다.

## 1. 항구 찾기와 최고가 판매처에 항로 거리·항해일 표시

### 화면

| 화면 | 표시와 동작 |
| --- | --- |
| 항구 찾기 | 항구명과 해역 아래에 `620해리 · 약 4.2일`. 기본 거리순은 실제 항로 해리 기준. 즐겨찾기와 최근 입항은 기존 순서 |
| 최고가 판매처 | 예상 실수령액 상위 5곳에 가격과 항로 요약을 함께 표시. `실수령 18,400 D` 아래 `620해리 · 약 4.2일 · 수에즈 운하 경유`. 검색의 가격 기준 시각과 ‘지도에서 보기’·‘항구로 이동’을 유지 |
| 정박한 항구 | `정박 중 · 0해리` |
| 항로를 찾았지만 직항 보급이 부족한 항구 | 거리·항해일을 유지하고 `직항 보급 부족 · 필요 18.2일분 / 현재 10일분` 표시 |
| 선단의 항해 가능 범위 밖 | `현재 선단으로 갈 수 있는 항로를 찾지 못했어요`. 항구 찾기의 거리순 하단에 배치 |
| 최고가 결과에 포함된 미개방 항구 | 기존 표시 범위에서 항로 예상치를 보여주고 `항구 정보가 필요해요` 표시. 항구를 개방하는 동작은 기존 방식을 따름 |

1. 검색할 때 내 배 위치, 선단·보급, 운하 체크 상태를 고정해 결과를 비교한다. 항해 중 다시 열거나 ‘현재 위치로 다시 계산’을 누르면 새 기준으로 계산한다. 항해일은 게임 속 시간으로 쓰고, 실제 초는 필요하면 결과 상세에서 확인한다.
2. 현재 출항 경로 계산을 재사용한다. 출항이 선택하는 바닷길, 섬·육지 우회, 강 속도, 선단에서 느린 배와 적용 중인 효과를 반영한다. 보급 소모량과 항해일이 다를 때 각각 표시한다.
3. **운하 이용 체크가 켜져 있으면** 개통·통행 가능한 운하를 후보에 넣는다. 선택된 항로에 운하가 포함되면 운하 이름과 현재 선단 기준 예상 통행료를 보여준다. 체크를 끄거나 운하가 닫혀 있으면 바다 우회 항로로 계산한다. 운하 상태를 확인하지 못하면 `운하 확인 전 · 우회 기준`을 붙이고 재확인 버튼을 둔다. ‘항구로 이동’은 실제 출항 시점에 항로·통행료·잔액·보급·거래 가능 여부를 다시 확인한다.
4. 최고가 검색은 가격 비교를 마친 뒤 상위 5곳의 항로만 계산한다. 제한 항구가 빠져 새 항구가 들어오면 추가된 행만 계산한다. 항구 찾기는 검색에 남은 후보를 나눠 처리하고, 장거리 계산은 기존 작업 스레드를 이용한다. 정렬이 확정되기 전에는 계산 상태를 보여준다.
5. 한 검색 안에서 같은 목적지의 항로를 재사용한다. 위치나 선단 성능, 운하 상태가 바뀌면 새 결과를 만들고, 보급만 달라졌다면 기존 항로로 출항 가능 여부만 다시 계산한다. 운하 정보는 기존 요청을 재사용해 항구마다 서버를 조회하지 않는다. 오래된 검색 결과가 새 화면에 섞이지 않게 요청을 구분한다.

**완료 기준** — 수에즈 통행 가능 상태에서 알렉산드리아→제다를 운하 켜기·끄기로 비교한다. 파나마는 개통 전후를 검증한다. 강 항구, 정박 중, 보급 부족, 도달 불가, 통행료 부족, 미개방·거래 제한과 검색 중 선단 변경을 시험한다. 같은 조건의 검색 거리·항해일이 출항 화면과 일치해야 한다. 모바일에서 여러 항구를 검색하는 동안 입력과 스크롤이 멈추지 않아야 한다.

## 2. 상단 ‘게임 설명서’와 검색 가능한 웹 매뉴얼

### 화면과 탐색

- PC와 모바일 게임 상단에 **게임 설명서** 버튼을 둔다. 로그인 대문에서도 열 수 있다. 홈에는 ‘첫 출항’, ‘보급·구조’, ‘첫 교역’ 바로가기와 검색창을 배치한다. 글에는 목차와 관련 글, PC와 모바일의 실제 메뉴 경로를 넣는다.
- 예를 들어 ‘배가 멈춤’은 보급 소진·자동 구조·조종 일시 정지를, ‘대포 있는데 발사 안 됨’은 항구 장착·사거리·재장전·공격 가능 대상을, ‘부선장 어디서 고용’은 주점 단서·합류 조건·부선장 명부를 보여준다. ‘몇 일 거리’나 ‘운하 이용’으로도 새 검색 기능을 찾을 수 있게 한다.
- 게임 안에서 열었으면 안내에 연결된 메뉴로 이동할 수 있게 한다. 로그인 전이나 메뉴를 사용할 수 없는 상황에서는 필요한 조건과 조작 경로를 보여준다. 검색 결과는 정확한 제목, 별칭·유사어, 본문 순으로 관련도를 판단하고 일치하는 문장을 짧게 표시한다.

- 글은 ‘무엇인가 → 어디서 여나 → 어떻게 쓰나 → 왜 안 되나’ 순으로 작성한다. 전투 방식마다 상대·시작 조건·적용 효과와 손실을 한 표로 비교한다. 유적 발견 좌표, 퀴즈 답, 퀘스트 해답은 안내 범위 밖으로 둔다.
- 변경되는 값은 공통 규칙 파일에서 읽어 문서 빌드 단계에 넣는다. 예를 들어 퀴즈 계수, 선단 한도, 세율 상한, 운송 단계 표를 원문 수치와 대조한다. 정리되지 않은 규칙을 글마다 수기로 복제하지 않는다.

### 유지보수

1. 글 하나를 Markdown 파일 하나로 관리하고 고정 주소(ID), 제목, 별칭, 관련 메뉴 ID, 검토 버전을 지정한다. 제목이나 분류를 바꿔도 공유한 주소가 열리게 한다.
2. GitHub Pages 빌드에서 HTML, 목차, 검색 색인을 생성한다. 작은 검색 색인은 설명서를 열 때 불러오고 검색은 브라우저에서 처리한다. 설명서 열람·검색에 Firebase 요청이 필요 없다.
3. 기존 ‘메뉴 찾기’의 메뉴 ID와 연결한다. 게임에서 경로가 바뀌면 해당 메뉴 연결과 글만 갱신한다. 배포 전 깨진 링크·메뉴 연결·누락된 검색어·규칙 표를 점검한다.

**완료 기준** — 비로그인·로그인 상태, PC와 320·390px 모바일, 키보드 조작에서 상단 버튼·검색창·본문을 확인한다. 초보자가 설명서만 보고 첫 출항·보급·첫 교역을 진행하고, ‘부선장’, ‘대포 발사’, ‘패배 손실’, ‘몇 일 거리’를 검색해 관련 글을 열 수 있어야 한다. 글 한 편의 제목과 본문을 바꾼 뒤 기존 공유 링크가 유지되는지도 확인한다.

## 3. 초보 선장 교역세 면제와 자유 공격 보호

### 보호 기준 추천

- **현재 소유 항구가 0곳이고, 보유 배가 1~2척이며, 보호를 졸업한 이력이 없는 선장**에게 적용한다. 선단에 있는 배와 항구에 맡긴 배를 합산한다. 일반 항구 과반 지분 소유와 직접 개발 항구를 포함한다. 소수 지분만 가진 선장은 그 자체로 소유자로 보지 않는다.
- **최초 항구 소유, 보유 배 3척 도달, 보유 선박 10단계 도달** 가운데 하나라도 달성하면 보호를 졸업하는 안을 추천한다. 10단계는 현재 일반 선박의 원양 제한이 풀리는 지점이다. 배를 팔거나 맡기고 항구를 처분한 뒤에도 졸업 기록을 유지한다. 기간 제한은 첫 버전에 두지 않는다.
- 기존 선장은 현재 진행도와 확인 가능한 최초 소유·선박 성장 기록을 바탕으로 적용한다. 오래된 데이터에 이력이 부족한 계정은 졸업 수치를 추정해 일괄 처리하지 않고, 적용 전 모의 결과로 별도 확인한다. 신규 계정은 보호 상태에서 시작한다.

### 적용 효과와 안내

| 상황 | 처리 초안 |
| --- | --- |
| 항구 교역소 구매·판매 | 선장에게 붙는 항구 교역세 0 D. 가격, 재고, 거래 제한은 현재 항구 정책을 따른다 |
| 연결 항구의 창고 교역·최고가 검색 | 동일한 면세 판정 적용. 견적에 `초보 선장 면세 · 세금 0 D` 표시 |
| 보급·수리·구조·운하 | 기존 이용료 적용 |
| 자유 해상 공격 | 보호 선단은 공격을 받거나 먼저 걸 수 없다. 오프라인에 남은 배에도 같은 판정 적용 |
| 합의 결투·공방 연습 | 상대가 수락하고 두 선장이 준비해 참가하는 방식은 허용하는 안을 추천. 훈련·연습의 결과와 손실 규칙을 시작 전에 표시 |
| NPC 해적 | 선장이 직접 시작하는 토벌은 기존 동작과 피해 규칙 적용 |
| 운영권이 걸린 공개 공방 | 보호 중에는 참가를 제한하는 안을 추천. 참가 조건을 공방 안내에 표시 |

- 내 선장 화면에 `초보 선장 보호 중`, 현재 조건, 졸업 기준을 표시한다. 선박 건조·개량이나 최초 소유 확정 직전에는 해당 행동이 보호를 종료할 경우 결과를 미리 안내한다. 타인에게는 공격 버튼과 보호 여부만 보여주고 계정의 상세 이력은 공개하지 않는다.
- 면세 대상 거래와 최고가 견적이 같은 세율 계산을 사용한다. 방금 졸업하거나 보호 상태가 바뀌어 견적이 달라지면 새 금액을 확인한 뒤 체결한다. 면세된 거래에서는 해당 금액을 항구 세수에도 넣지 않는다.
- 졸업 기록을 소유권·배 추가·개량 확정과 함께 저장한다. 권리와 공유 장부를 쓰는 서버 규칙에서 보호 중인 공격 개시를 거절한다. 공개 명부의 지연된 순위나 브라우저에 남은 상태로 보호를 확정하지 않는다. 저장된 게임 본문이 문자열인 부분은 선박·소유권 변경과 함께 검증할 보호 기록을 별도로 설계한다. 가상 교역 등 같은 세금이 적용되는 거래 경로도 체크한다.
- 기존 전투는 개시 때의 조건으로 정상 종료하도록 하고, 전환 시점에 이미 진행 중인 경기나 공격이 있으면 먼저 정산한 뒤 보호를 적용한다. 보호 상태는 계정당 작은 기록으로 유지하고 평상시 지도 좌표 갱신에 추가 읽기를 붙이지 않는다.

**완료 기준** — 배 2척·미소유의 면세, 항구에 맡긴 3번째 배, 두 사람이 동시에 과반을 바꾸는 거래, 지분을 다시 팔아도 졸업 유지, 10단계 도달, 보호 선장의 온·오프라인 자유 공격 차단, 동의 결투와 NPC 토벌, 변경 직전 견적 재확인을 시험한다. 기존 계정을 초기화하지 않고 계정별 적용 근거를 이관 모의 실행으로 검증한다.

## 구현·검증 순서

1. 공통 출항 계산과 검색용 조회를 연결하고 두 검색 화면을 검증한다.
2. 기존 게임 메뉴를 대조해 설명서 본문을 작성한다. 최신 검색과 초보 보호 규칙은 구현을 확인한 뒤 설명서에 넣는다.
3. 보호 이관을 모의 실행하고 교역·공격 규칙을 테스트 Firebase에서 검증한다. 초보 졸업과 결투 예외는 위 추천안을 기준으로 검토한다.
4. 승인된 구현 범위에서만 공개 업데이트를 진행한다. 운영 배포 시 기존 절차에 따라 대문 공지, 접속 중단, 새 버전 확인, 서버 재개 순서로 확인한다.
