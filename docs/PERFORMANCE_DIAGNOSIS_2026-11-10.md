# 성능 원인 조사 · 2026-11-10

상태: 원인 조사 완료. 아래는 수정 전 조사 결과이며 실제 사용자 기기 프로파일은 수집하지 않았다. 이후 사용자가 선택한 선단·미니맵·항해 시간 개선을 실행했다. [후속 결과](UPDATE_2026-11-10_PERFORMANCE.md)를 참고한다.

## 결론

최근 업데이트로 늘어난 화면 그리기 부하가 가장 유력하다. 특히 정밀 지도와 항상 남는 오프라인 배, 반복 미니맵 계산이 겹친다. 프레임이 낮아지면 항해 경과 시간 일부를 버리는 기존 처리까지 작동해 배의 실제 이동 속도가 떨어질 수 있다. 특정 기기의 기여 비율이나 서버 지연을 실측했다고 주장하지 않는다.

## 확인한 사실

1. 육지 꼭짓점은 5,143 → 152,336개(약 29.6배), 국경은 10,654 → 89,306개(약 8.4배)다. 기준은 업데이트 전 커밋 dad2049와 현재 원본이다. 육지 JSON은 138,160 → 3,184,112 bytes, 국경은 838,726 → 1,899,440 bytes다. 최초 로딩/파싱과 SVG 그리기 모두 부담이 커졌다.
2. 지도 추적 시 applyCamera가 매 프레임 배·주변 선단·미니맵·지명을 다시 처리한다. renderChartLabels는 지명이 달라지지 않아도 text 노드를 지우고 만든다. 지명은 정적 지형과 같은 chart-terrain 안에 있어 배경 재사용을 방해할 수 있다. 경계 연결용 9개 use 참조도 같은 그룹을 사용한다. 9개가 모두 보이거나 모두 GPU로 그려진다고 측정한 것은 아니다.
3. peers.size가 1개라도 있으면 약 80ms마다 renderPeers/renderMinimap을 호출한다. 영구 오프라인 배가 추가되어 정지해 있는 배도 이 경로를 계속 실행한다. 주변 배 표시도 replaceChildren/innerHTML로 도형을 새로 만든다.
4. 지구본은 그릴 때 원 안의 약 3.6만 픽셀마다 투영·시야 계산을 반복한다(최소 90ms 간격). 평면 미니맵은 64,800픽셀을 반복한다(최소 150ms 간격). 미니맵 패널을 접어도 계산을 중지하는 검사가 없다.
5. 전투 타이머는 250ms마다, 선단 타이머는 500ms마다 화면 갱신을 유발한다. 빈 전투 표시나 동일한 명단/랭킹도 다시 처리할 수 있다.
6. tick의 delta는 min(실제 경과 초, 0.1)이다. 100ms보다 오래 걸린 프레임은 초과 시간을 버린다. 예를 들어 매 프레임 200ms가 걸리면 실제 1초 동안 0.5초만 항해해 설정 속도의 약 절반이 된다. 선박 성능 파일 ship-rules.js는 dad2049 이후 바뀌지 않았고 6배 기준/보급 수치를 낮춘 변경은 없다.
7. 일반 위치 전송의 최소 2초·정지 30초 규칙은 유지되어 있다. 최고가 판매처는 검색 버튼 실행 때만 조회한다. 이 조사에서 운영 DB 전체 읽기나 시험 거래·공격을 수행하지 않았다.

## 제한된 CPU 측정

Node + Happy DOM에서 실제 계산 함수를 실행하되 canvas 그리기는 no-op으로 처리했다. 화면 배치/GPU/SVG 실제 페인트·휴대폰 성능은 제외된다. 중앙값/p95는 아래와 같으며 모바일 FPS로 환산하지 않는다.

| 작업 | 중앙값 ms | p95 ms |
| --- | ---: | ---: |
| 지구본 한 번 강제 계산 | 5.22 | 11.2 |
| 평면 미니맵 한 번 강제 계산 | 6.71 | 9.15 |
| 다른 배 9척의 SVG 노드 재생성 | 2.61 | 14.4 |

반복 측정의 CPU 비용만으로도 작업을 매번 실행하지 않는 최적화 가치가 확인된다. 주원인별 실제 기기 비율을 확정하려면 브라우저 프레임/페인트/긴 작업 프로파일이 추가로 필요하다.

## 조사 당시 권장 수정 순서

1. 정지·오프라인 배는 좌표/단계가 바뀔 때만 도형 갱신, 이동 배는 기존 노드의 transform만 변경한다.
2. 미니맵은 배경·안개를 캐시하고 변경 시만 계산하며, 접힌/보이지 않는 패널은 계산을 멈춘다.
3. 정적 지형과 동적 지명을 분리하고 라벨 재배치는 조건 변화/간격 제한으로 줄인다. 지도는 보이는 영역 중심으로 도형을 나누거나 적절히 단순화한다.
4. 빈 전투 화면·변경 없는 명단/랭킹 갱신을 생략한다.
5. 프레임 지연 시 항해 시간은 작은 계산 단계로 나누어 처리한다. 숨겨진 탭/로그아웃의 항해 중지는 그대로 유지한다.
6. 개선 전후 실제 PC/모바일에서 정박·항해·지도 드래그·전투를 같은 조건으로 비교한다.
