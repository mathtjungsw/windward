## 1. 업데이트 후 플레이 흐름

리스본의 작은 연안 교역선으로 시작해 세투발·시네스·라구스·포르투 등을 오가며 돈을 모은다. 다음 항해에 필요한 식량과 식수를 보급하고, 화물과 보급이 같은 공간을 쓰므로 무엇을 얼마나 실을지 선택한다. 선박 개량 뒤 대서양 섬과 아프리카로 항로를 넓히고, 원양선에 이르면 긴 대양 항해를 준비한다.

접속 시간이나 방문 횟수로 지역을 잠그지 않는다. 선박의 연안 운항 성능, 보급 지속력과 항구 사이의 거리가 항해 범위를 결정한다. 기존 고정 배율 해도·지구본·강·시야·접속 선장 명단·채팅·세 가지 랭킹·메뉴 접기는 유지한다.

모바일은 하단 ‘항해 / 항구·보급 / 화물 / 더보기’로 긴 스크롤 없이 이동하고, PC는 지도 옆에서 항구·화물을 비교한다. 처음에는 각 정보창을 펼치고 사용자가 접은 상태만 기억한다. 상단 업데이트 버튼으로 지난 패치를 다시 읽고, 선택한 항구·완료 항로 공유와 주변 선장 인사로 서로 도움을 주고받는다. 공유만으로 항구를 무료 해금하거나 추가 보상을 만들지 않는다. 공동 납품과 자동 동행은 11절의 후속 선택안으로 구분한다.

## 2. 현재 문제와 실제 확인 범위

현재 항구 64개와 구매 상품 8종이 있다. 생산·수입·중계를 구분하지 않으며 같은 상품이 반복된다. 시작 배는 하루 360해리(24시간 평균 15노트), 보급 100에서 하루 0.9씩 소모하므로 계산상 무보급 약 111일·40,000해리를 간다. 모든 단계의 최대 보급은 160이다. 시작 자금 2,400 D로 첫 개량비 1,800 D를 즉시 낼 수 있다.

자동 이동 계수는 1.3, 직접 조종은 0.3으로 실제 이동 시간이 다르고, 강의 이동 감속과 날짜·보급 계산도 함께 정비해야 한다. 구조는 저렴하게 리스본으로 귀환해 장거리 귀항의 의미를 약하게 만든다. `dist/social-core.js`와 Firebase 규칙의 방문 수 상한은 모두 64로 고정되어 있다.

위 수치는 계획을 작성할 때의 기존 코드 기준이다. 새 규칙과 실제 확인 결과는 실행 기록을 참고한다.

## 3. 항구와 상품

### 항구 64 → 88곳

기존 64개 ID와 9개 강·18개 강 항구를 보존하고 해상 항구 24곳을 추가한다. 새로운 강 수계는 이번 범위에 넣지 않는다. 추가 명단·도시 좌표·상품 역할은 콘텐츠 명세를 따른다.

- 이베리아 주변: 세투발·시네스·라구스·파루·카디스·비고·아코루냐·빌바오.
- 서유럽·지중해: 플리머스·사우샘프턴·라로셸·알제·두브로브니크.
- 대서양 섬·북아프리카: 푼샬·라스팔마스·앙그라·히베이라그란드·사피.
- 인도양·동아시아: 호르무즈·캘리컷·모카·테르나테·반다네이라·취안저우.

첫 개방 항구는 기존 리스본·포르투·산루카르·세비야에 세투발·시네스·라구스를 더한 7곳이다. 실제 방문은 리스본 1곳부터 시작한다. 나머지는 기존 접근 발견·주점 정보로 연다. 개방만으로 방문 보상이나 순위가 오르지 않는다.

현재 0.5도 격자는 좁은 만·섬을 생략하므로 도시 좌표와 조작용 부두를 구분한다. 생성된 부두를 그대로 확정하지 않고 육지 반대편 배치·겹침·과도한 입항 반경을 교정한다. 사우샘프턴 등은 검증된 접근 지점을 둔다. 주변 육지를 통째로 지우거나 새 강처럼 표시하지 않는다. 인접 항구 입항 범위가 겹치면 같은 수역의 실제 가까운 부두를 우선하고, 선택 목적지는 동률일 때만 우선한다.

### 구매 상품 8 → 23종

기존 와인·모직물·유리공예·커피·비단·차·설탕 7개 ID를 유지하고, 소금·올리브유·건어물·면직물·도자기·목재·곡물·가죽·대추야자·구리·카카오·양모·후추·정향·계피·육두구를 더한다. 기존 `spice`는 **혼합 향신료(구버전)**라는 판매 전용 호환 품목으로 유지한다. 구매 23종 + 호환 1종이다. 양모와 가공한 모직물을 분리해 목축 항구를 직물 제조 도시처럼 설명하지 않는다.

대표 생산·지역 공급·수입·중계를 구분한다. 생산은 도시 안뿐 아니라 배후 지역의 공급을 포함한다. 베네치아의 유리·인도산 면직물·스리랑카 계피·말루쿠 정향과 육두구를 살리고 말라카는 중계항으로 표시한다. 특산물은 여러 시대의 전통 교역을 포괄한다. 런던의 수입 차, 브라질의 커피, 콜롬보의 차도 허용하며, 실제로 유명해진 시기를 항구 설명에 넣는다. 이런 상품을 전 세계 모든 항구에 무차별 배치하지 않는다.

**2026-11-05 추가 사용자 결정:** 항구와 상품의 역사적 시점이 일치하지 않아도 되며, 근현대의 물품은 제외한다. 항구 설명에 실제 역사를 넣어 학습의 재미를 만든다. 이에 따라 ‘상품 자체가 오래된 전통 교역품이면, 해당 항구에서 유명해진 시기가 후대여도 허용’으로 적용한다. 산업화 이후 기계·자동차·석유 가공품·전자제품·합성수지 같은 물품은 추가하지 않는다. 차·커피·설탕은 항구에서의 대규모 재배가 늦어도 오래된 상품이므로 포함한다.

1522년은 가상 항해의 출발 연도로 유지하고, 여러 시대의 항구와 전통 교역을 모은 게임이라고 첫 안내와 도감에 명시한다. 기존 도시를 삭제하거나 개항 연도로 세계를 봉쇄하지 않는다. 후대 도시·내륙 거점은 당시 실제 개항이라고 소개하지 않는다. 가격·수량·현재 재고는 게임 설정이다. 조사 미확정 배치는 구현 때 근거를 보강하며 확인되지 않으면 역사적 특산품으로 단정하지 않는다.

항구의 기존 설명 영역에 **‘항구와 상품 이야기’**를 추가한다. 지리 1문장 + 대표 상품의 역사 1~2문장 + 생산/수입/중계 구분으로 구성한다. 예: 브라질 커피 도입 1727년, 스리랑카 상업적 차 재배 1867년, 영국 동인도회사의 차 첫 주문 1664년. 이 날짜를 1522년의 사건처럼 표시하지 않는다. 베네치아처럼 오래된 전통도 함께 소개하고, 항구마다 정확한 연도를 억지로 만들지 않는다. 설명은 기존 항구 창 안에 두고 접기 기능을 유지하며 출처는 도감에서 펼쳐 볼 수 있게 한다. 조사 출처는 콘텐츠 명세에 남긴다.

## 4. 선박·보급 기본값

아래는 이번 구현 기본값이며 실제 선박의 역사적 사양을 복원한 수치는 아니다.

| 항목 | 1단계 · 연안 교역선 | 2단계 · 항해 캐러벨 | 3단계 · 원양 교역선 |
| --- | --- | --- | --- |
| 기존 level | 0 | 1 | 2 |
| 총 적재 공간 | 40칸 | 65칸 | 100칸 |
| 해상 하루 이동 | 80해리 | 120해리 | 160해리 |
| 강 하루 이동 | 36해리 | 36해리 | 36해리 |
| 최대 보급 | 10일분 | 20일분 | 65일분 |
| 최대 보급 공간 / 남는 화물 공간 | 5 / 35칸 | 10 / 55칸 | 33 / 67칸 |
| 해상 최대 무보급 거리, 예비량 미포함 | 800해리 | 2,400해리 | 10,400해리 |
| 자동 출항의 도착 예비량 | 0.5일분 | 2일분 | 5일분 |
| 예비량을 남기는 해상 편도 한도 | 760해리 | 2,160해리 | 9,600해리 |
| 외해 운항 | 해안에서 80해리 이내 | 해안 거리 제한 없음 | 해안 거리 제한 없음 |
| 해당 단계로 개량하는 비용 | 시작 배 | 9,000 D | 추가 36,000 D |
| 보급 1일분 가격 | 3 D | 6 D | 12 D |

- 시작 자금 2,400 D 유지, 보급 10일분·빈 화물로 출발. 기존 이용자의 선박 단계는 낮추지 않는다.
- 보급 1일분은 해당 선박 선원들이 하루 쓰는 식량·식수 묶음이다. 선원·물통을 별도 관리하지 않는다. 보급은 판매 불가이며 화물 상품을 보급으로 변환하지 않는다.
- 보급 공간 = `ceil(남은 일수 / 2)`. 총 사용 공간 = 화물 상자 + 보급 공간. 구매 한도는 선박 보급 상한과 남은 적재 공간을 모두 만족해야 한다.
- 게임 속 항해 1일에 보급 1일분을 쓴다. 강에서 느려진 시간도 포함한다. 소수는 보존하고 화면은 소수 1자리로 표시한다. 추정과 실제 차감의 올림 규칙을 달리하지 않는다.
- 정박·항해 정지·일시 정지·숨겨진 탭·로그아웃 중에는 소모하지 않는다. 개량해도 현재 화물과 보급만 유지하고 보급을 무료로 가득 채우지 않는다.
- 보급 +1일 / 가득 채우기와 비용·남는 공간을 표시한다. 정박지에서 보급 내리기도 가능하며 비매매 보급 크레딧으로 보관한다. 환전·자금 생성은 불가하다.

## 5. 연안 제한·시간·출항 판단

### 연안 성능

시작 배의 해안 80해리 제한은 선박 성능의 게임 표현이며 실제 항해 위험 등급이 아니다. 짧은 클릭·목적지 변경·조작 방식 변경으로 통과할 수 없다.

1. 기존 육지 자료에서 해안 거리 보조 자료를 정적으로 생성한다. 위도별 실제 거리와 경도 연결을 반영하고, 격자에서 생략된 섬은 확인된 해안 지점을 보완한다. 강 항로는 유지한다. 북·남쪽 게임 경계는 가상의 육지처럼 취급하지 않는다.
2. 연안선 자동 경로에서는 허용 범위 밖 해역을 제외해 탐색한다. 최단 외해 경로가 막혀도 연안 우회로가 있으면 찾는다. 출발·도착만 해안이라는 이유로 중간 외해를 통과시키지 않는다.
3. 직접 조종은 이동 전체 구간을 검사해 한계 직전의 안전한 위치에 정지한다. 이전 항구로 순간 이동시키지 않는다.
4. 최대 2해리 이하의 구간 단위로 수역·시간·보급·외해를 공통 판정한다. 긴 프레임·대각선·경계 이동도 같다. 정적 자료와 경로 분류를 캐시하고 프레임마다 세계 전체를 검색하지 않는다.

### 게임 날짜와 화면 속 시간

**게임 속 1일 = 실제 활성 항해 2초**를 기본값으로 한다. 사용자 비교에서 선택한 이전 대비 6배 속도다. 자동·직접 조종은 같은 선박·수역에서 같은 속도로 이동한다. 현실서버의 추가 배율은 1배속이며 실제 달력과 같은 속도라고 설명하지 않는다.

`항해 일수 = 해상 거리 / 선박 해상 속도 + 강 거리 / 36`을 추정과 실행에 함께 쓴다. 수역이 섞인 선분을 실제 경계에 따라 나누고 거리가 짧아도 별도 최소 0.25일을 붙이지 않는다.

### 출항과 자원 부족

- 거리·게임 일수·보급 소모·도착 잔량·예비량 충족·외해 적합성을 보여준다. 알려진 항구로 자동 출항할 때는 도착 예비량을 확보해야 한다.
- 바다 좌표 목적지는 도착점부터 **알고 있는 보급항**까지의 연결 경로를 더해 예비량을 검사한다. 미개방 항구를 안전항으로 몰래 이용하거나 공개하지 않는다.
- 귀항 보장이라는 안내는 실제 왕복을 계산한 경우에만 쓴다. 추천 보급항도 해당 선박의 연안 제한·강 연결·필요 보급을 만족해야 한다.
- 직접 조종은 예비량 아래에서도 돌아올 수 있게 조종을 유지하고 경고한다. 보급 0에서는 자동·직접 모두 정확히 그 위치에서 자력 항해를 멈추고 아래 자동 구조로 전환한다. 중간 정지나 새로고침으로 보급·항속이 회복되지 않는다.

## 6. 경제·성장·구조

### 가격과 보상

기준가 × 항구 공급 계수 × 기존 주간 변동을 쓴다. 대표 공급 0.72, 일반 지역 공급 0.90, 수입·중계 재고 1.12, 별도 수요처 1.35가 기본이다. 매입가는 반올림, 판매가는 현지 매입 기준가의 88%를 내림한다. 주간 변동 ±4.5%는 유지한다. 수요처를 생산지처럼 싸게 구매 가능한 곳으로 만들지 않으며, 항구별 구매 재고와 판매만 가능한 품목을 구분한다.

가장 가까운 특산항까지의 거리만으로 가격을 정하는 방식을 역할 기반으로 바꾼다. 모든 품목에 유효한 기준가·공급 역할을 두고 NaN·무한대 가격을 막는다. 같은 항구 즉시 되팔기와 주간 변동만 기다리기로 무위험 이익이 생기지 않는지 확인한다.

첫 의뢰의 리스본 와인 구매·타 항구 판매와 보상 400 D는 유지한다. 방문 120 D·퀴즈 100 D·5항구 의뢰 650 D 등 기존 수령 기록을 보존한다. 새 항구 보상도 첫 실제 입항에 한 번이다. 무역 이익 순위는 기존처럼 판매금−매입원가이며, 화면의 보급비 포함 예상 순이익과 구분한다.

### 경로와 성장 계산

시세 변동 0에서 와인(기준가 48)은 리스본 대표 공급 매입 35 D → 세투발 지역 공급 판매 37 D다. 소금(20)은 세투발 매입 14 D → 리스본 수입 판매 19 D다. 보급 6일분과 화물 37상자로 왕복하면 와인 74 + 소금 185 − 소비한 보급 재구매 약 4 = **약 255 D**다. 초기 보급은 이미 지급된 것으로 계산하고 이후 매 항구에서 소비량을 다시 채운다고 가정했다. 실제 시세·적재량에 따라 달라진다.

첫 방문·퀴즈·첫 거래 의뢰 합계 620 D를 받아도 이 짧은 항로만으로 첫 개량 9,000 D까지 약 24왕복이다. 인근의 다른 상품·신규 방문·5항구 의뢰로 더 빨리 성장하도록 유도한다. **첫 개량 15~30분은 플레이 목표이며 측정값이 아니다.** 대표 다항구 순환 항로와 실제 메뉴 조작을 검증하고 목표에서 크게 벗어나면 개량비·공급/수요 계수를 조정한다. 핵심 보급·연안 제약을 풀어서 보정하지 않는다.

### 구조 · 사용자 수정 반영 (2026-11-05)

**보급 소진 시 구조비를 받고 가장 가까운 항구로 자동 이동한다. 돈이 없거나 부족해도 반드시 구조한다.** 이전의 ‘마지막 입항 항구로 귀환·호출 버튼 실행’ 계획을 이 규칙으로 대체한다.

- 해상·강에서 보급이 0이 되면 자력 항해를 정지하고 별도의 확인 버튼 없이 자동 구조 항해로 전환한다. 화면에 구조 시작·목적지·실제 차감액을 알린다. 정박 상태의 보급 0에는 구조비를 부과하지 않는다.
- 목적지는 전체 항구 중 현재 위치에서 **육지·강 연결을 지키는 항해 경로가 가장 짧은 항구**다. 직선상 가까워도 육지를 넘어야 하는 항구는 실제 경로로 비교한다. 방문·개방 여부로 후보를 제한하지 않는다. 미개방 항구가 선택되면 그 목적지만 안내하고 실제 입항 때 개방·방문을 처리한다.
- 기본 구조비는 `min(1000, max(150, ceil(구조 경로 해리 × 0.5)))` D이며, 실제 차감액은 `min(보유금, 기본 구조비)`다. 보유금 0이면 0 D, 부족하면 가진 돈만 지불한다. 빚·미납금·나중 청구·화물 강제 판매 없이 자동 이동한다.
- 구조선이 견인하는 전용 항해를 사용해 일반 항해 예상 시간의 2배로 이동한다. 자기 배의 보급은 추가 소모하지 않으며 연안선의 외해 한계도 구조선을 막지 않는다. 육지 통과는 허용하지 않는다. 활성 항해 12초/게임 1일과 숨겨진 탭의 정지는 공통 적용한다.
- 구조 중에는 경로를 직접 조종하거나 임의 목적지로 바꾸지 못한다. 이동 상태·목적지·비용 지불 여부를 하나의 저장 상태로 남기고 새로고침·재접속 때 이어간다. 보급 0 감지를 반복하거나 저장을 다시 불러와도 비용을 중복 차감하지 않는다.
- 입항 후 선박·화물은 유지하고 보급을 최소 2일분까지 지원하되 선박 상한을 넘기지 않는다. 과적이면 항구에서 정리 후 출항한다. 지원 보급은 판매 불가다. 미방문 항구의 보상은 기존 첫 입항 규칙에 따라 한 번만 처리한다.
- 연결 가능한 구조 경로를 찾기 전에 돈부터 차감하지 않는다. 경로 계산 실패 시 위치·재산을 보존하고 재시도하며, 88항구의 연결과 바다·강·경계 근처 구조를 구현 검증에 포함한다.

## 7. 기존 저장 이관과 구버전 혼용 방지

기존 `gameV2`와 Google 계정을 유지하며 접속한 **본인 저장 한 건**만 revision·세션 보호 트랜잭션으로 이관한다. 전체 DB 다운로드·기록 삭제·재초기화는 하지 않는다.

1. 게임 `version:2`, 저장 봉투 `schemaVersion:2`를 도입한다. v1 검증→이관→v2 검증 순서다. 불러오기 실패 후 초기값을 만드는 현재 동작을 이관 성공으로 취급하지 않는다. 실패하면 원본을 보존하고 안내한다.
2. 자금·화물 ID/수량/총 매입원가·배 단계·방문/개방/탐험·퀴즈/의뢰 수령·로그를 보존한다. `spice`는 판매 전용으로 유지하고 기존 64항구의 구 특산 배치·가격식을 호환 테이블에 남겨 갑작스러운 가치 증가를 막는다. 신규 항구의 호환 판매는 일반 수입 계수로 정한다.
3. 정박 저장의 기존 보급이 새 상한보다 많으면 초과분은 비매매 `supplyCreditDays`로 남겨 정박 보급 때 먼저 사용한다. 반복 이관으로 크레딧을 중복 생성하지 않는다.
4. 만재 화물+보급이 새 적재 한도를 넘으면 화물을 삭제하지 않는다. 정박 중 판매·보급 내리기로 정리하고 신규 구매·출항만 제한한다.
5. 이미 진행 중인 **구버전 자동 항로 한 건**은 저장된 경로·잔여 보급·기존 속도/소모율로 마치거나, 연결된 방문 항구로 안전 귀환하는 선택을 준다. 예외를 새 목적지·새 항해·수동 조종으로 연장할 수 없다. 새로고침 후에도 동일한 한 항해로 유지하고 입항 때 새 한도와 크레딧으로 전환한다.
6. 구버전 직접 조종·바다 정지는 위치를 유지한다. 새 규칙으로 복귀할 수 있으면 이어가고, 불가능하면 가장 가까운 **항해 경로로 연결된 항구**로 1회 안전 귀환을 선택하게 한다. 이관 때문에 새로 생긴 항해 불능은 무상 전환 지원으로 처리하고, 일반 보급 소진 구조와 중복 실행하지 않는다. 불러오기만으로 순간 이동·차감하지 않는다.
7. 새 캐시 키를 쓰되 이전 v3 미전송본을 먼저 검사한다. 서버 revision과 충돌하면 기존 선택·백업 흐름을 유지한다. 원본 백업은 본인 기기에 남기며 미전송본을 조용히 지우지 않는다.
8. 규칙에 새 봉투 필드를 먼저 허용하고 최종 전환 때 쓰기에 schemaVersion 2를 요구한다. 기존 v1 기록은 계속 본인이 읽고 새 코드로 이관할 수 있다. 구버전의 덮어쓰기는 거부한다. 첫 생성·세션 인계·자동 저장·로그아웃 등 모든 쓰기가 새 필드를 포함하는지 확인한다.
9. 구버전의 거부 메시지 동작도 확인한다. 이미 배포된 구버전은 전용 업데이트 안내가 없으므로 일반 저장 오류가 뜰 수 있으며, 새 버전 공지와 새로고침 안내를 제공한다. ‘구버전 모두가 전용 메시지를 표시한다’고 보장하지 않는다.
10. v1 미전송·서버 v2·중복 탭·이관 재시도를 검증한다. 롤백도 v2 읽기·저장을 유지한 호환 수정으로 한다. 이전 Google 초기화 계획의 삭제 명령은 실행하지 않는다.

전환 시 새 봉투 필드를 받아들이는 규칙을 먼저 배포하고 Pages 새 클라이언트의 성공과 공개 산출물을 확인한 뒤 schema 2 쓰기를 강제한다. 미접속 이용자의 v1 저장도 나중에 이관할 수 있어야 한다. 전환 전후 소유권·revision 보호를 유지한다. 운영 이용자의 돈·보급·화물을 시험 조작하지 않는다.

## 10. 서버·비용·사용자 결정

기존 Spark와 GitHub Pages로 구현한다. 항구·상품·가격·해안 거리는 정적 자료와 브라우저 계산을 쓰고 항구 88개를 Firebase에서 실시간 구독하지 않는다. 주변 해역 구독·채팅 50개·상위 5명·변경 순위만 쓰기·기존 저장 간격을 유지한다.

정적 파일·개인 저장의 탐색 필드와 채팅 카드 메타데이터만큼 전송량이 늘 수 있다. 패치노트와 화면 설정에 추가 실시간 구독을 만들지 않는다. 실제 비용 0원을 보장하지 않으며 이번에 운영 사용량을 실측한 것은 아니다. 새 유료 서버·Cloud Functions·AI API·요금제 변경은 기본안 A/B에 필요하지 않다.

기존 항해 개편과 부속 명세 A/B는 위 기본값으로 구현할 수 있다. 지역 설정을 포함한 기존 세계지도를 유지한다. 완전한 1522년 역사 지도·새 전투/질병/선원 급여·확률적 침몰·새 강 추가는 이번에 도입하지 않는다. **‘업데이트해줘’ 지시를 받은 뒤 통합 기본안의 구현·검증·승인 범위 배포를 진행한다.** C/D의 채택은 기본안과 별도다.
