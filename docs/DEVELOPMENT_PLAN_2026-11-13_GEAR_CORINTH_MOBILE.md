# 바람의 항로 · 장비 확장, 코린토스 운하 정리, 모바일 알림

2026-11-13 상세계획. 새 개발 항목은 장비 장착 확대, 코린토스 운하 정리, 모바일 알림 잘림 수정이다. 살랄라 항해 오류는 로컬 수정이 완료되어 배포 전 재확인 항목으로 둔다. 기존 계획에 남은 명단·전투 화면 갱신 최적화도 아래에 범위를 정리했다.

## 1. 교역 장비와 탐사 장비

- **확정** — 선단 단위로 교역 3칸, 탐사 3칸을 둔다. 두 장비 종류를 합쳐 최대 6개다. 기존 배별 장비와 동행 부선장은 각각 현재의 1개·1명 규칙을 적용한다.
- **장착 제안** — 항구에서 보유한 장비를 빈 칸에 넣는다. 3칸이 찼으면 교체할 장비를 고른다. 같은 장비 ID는 한 번만 장착한다. 해제와 교체 후 적재 한도가 이미 실은 화물과 보급보다 낮으면 행동을 거절하고 필요한 여유를 표시한다.
- **효과 제안** — 서로 다른 효과를 함께 적용한다. 같은 수치 효과는 더하고 기존 상한을 적용한다. 예를 들어 해협 상인의 인장 2%와 상인 인장 1%를 함께 쓰면 말라카·자카르타에서는 적격 판매액에 최대 3%, 그 밖의 항구에서는 상인 인장의 1%가 적용된다. 부선장 보너스도 현재의 세후 판매 수령액 3% 상한을 공유한다. 항구·지역·상품 제한은 장비마다 먼저 판정한다.
- 탐사 지도 표시·지름길·활동 조건은 장착품 중 하나라도 해당 조건을 만족하면 활성화한다. 흔적 확인 거리와 해상 활동 인지 거리는 각각의 용도에 적용하고, 조사 가능 거리와 일반 시야는 기존 규칙을 사용한다. 내륙 장터 운반 한도는 기존 최대 7상자를 적용한다. 기존 상한이 없는 같은 수치 효과는 현재 장비 목록을 대조해 조합별 예상치를 확인한 뒤 상한 필요성을 판단한다.
- **화면과 저장** — 특수 아이템 가방과 내 배 보기의 장비 화면에 `교역 2/3`, `탐사 3/3`과 장착품·실제 효과를 표시한다. 이전 저장의 단일 장착품은 해당 종류의 첫 칸으로 옮긴다. 보유 수량과 획득 이력은 보존하고, 계정 저장에서 유효한 보유품만 허용한다. 새 형식 저장을 구버전이 덮어쓰지 않도록 배포 때 저장 호환성을 확인한다.
- **통과 기준** — 두 종류 동시 3개, 중복 차단, 네 번째 장비 교체, 적재 초과 방지, 재접속과 저장 이관을 확인한다. 교역 견적·실제 수령액·최고가 검색에서 같은 조합을 적용한다. 탐사 장비는 흔적 표시와 실제 접근 동작, 상륙 이동·해상 활동·장비 요구 조건을 함께 확인한다.

## 2. 코린토스 운하 정리와 환급

- **확정** — 코린토스 운하를 삭제하고 모든 투자자에게 각자 투자금의 **1.2배**를 돌려준다. 수에즈·파나마 운하는 기존 자동 이용 설정과 통행료를 유지한다.
- **확정 정산** — 장부의 각 투자자가 실제 낸 원금에 1.2배를 적용한다. 원금 700,000·300,000·200,000 D의 지급액은 840,000·360,000·240,000 D로 총 1,440,000 D다. 미수령 배당은 점검 전 장부 조회에서 0 D였다. 환급 기록은 본인만 조회하고 다음 접속 시 잔액과 함께 저장한다.
- **운영 순서** — 점검 전 투자 장부의 개별 항목과 환급 합계를 읽기 전용으로 대조한다. 점검 중 코린토스 신규 투자·통행을 서버에서 차단하고 지도·사업 목록·자동 항로·통행권 지정에서 제거한다. 기존 장부는 정산 근거로 보존한다. 환급은 계정별 지급 기록과 잔액 반영을 함께 확정해 같은 건을 한 번만 지급한다. 오프라인 선장에게도 다음 접속 시 받을 수 있는 정산 기록을 남기고 게임 내 수령 내역을 표시한다.
- **기존 항해와 통행권** — 운하에 들어가기 전인 경우 미사용 코린토스 통행료와 소비된 예약용 통행권을 한 번만 반환하고, 안전한 바닷길을 다시 계산한다. 이미 운하 안에 있는 배는 해당 구간의 안전한 출구까지 기존 통과를 마친 뒤 일반 항로로 전환한다. 통과 완료분은 기존 정산을 사용한다. 우회 보급이 모자라면 기존 보급·구조 규칙에 따라 안내한다. 코린토스로 지정된 통행권은 지정만 풀고 남은 아이템을 보존한다.
- **통과 기준** — 단독·공동·무소유 장부, 미수령 배당, 오프라인 지급, 중복 실행, 이전 화면의 통행 요청, 미진입·통과 중·통과 완료 항로를 각각 검증한다. 환급 전후의 총액과 개별 기록이 일치하는지 확인한다.

## 3. 모바일 출항 알림 잘림

- 출항 알림이 화면 왼쪽으로 벗어나 문장 앞부분이 잘린 제보를 기준으로 재현한다. 실제 모바일 표시 영역의 좌우 여백과 안전 영역을 기준으로 알림 상자를 배치한다. 긴 문구는 상자 안에서 줄바꿈하며 출항·도착·보급 안내가 같은 배치 규칙을 쓴다.
- 하단 메뉴와 직접 조종 버튼 위쪽에 두고, 내용만큼만 높이를 차지하게 한다. 반복되는 같은 경고는 기존처럼 한 장으로 갱신한다.
- **통과 기준** — 좁은 모바일 세로·가로 화면, 확대, 하단 안전 영역 변화에서 알림 본문과 테두리가 모두 보이고 가로 스크롤이 생기지 않는다. 직접 조종 버튼과 하단 메뉴의 조작을 가리지 않는지 브라우저로 확인한다.

## 4. 살랄라 항해 오류 배포 확인

- 개발 항구에 빠져 있던 특산물 정보를 보완한 로컬 수정과 기존 검증을 다음 배포에 포함한다. 살랄라를 이미 발견한 저장으로 지도 진입 후 직접 조종과 해역 지정 자동 항해가 움직이는지 재확인한다.
- 같은 수정이 적용된 개발 후보 12곳의 특산물 표시를 점검한다. 운영 계정의 위치나 재산을 변경하는 방식의 복구는 필요하지 않다.

## 5. 명단·전투 화면 갱신 최적화

- 기존 성능 개선안에 남은 후속 항목이다. 접속자 이름·상태·온라인 여부가 이전 표시와 같으면 명단 DOM을 다시 만들지 않는다. 시간 경과로 오프라인 전환이나 접속 경과 표시가 바뀌는 경우는 정상 갱신한다.
- 전투 화면은 배치·내구도·선택 대상·전투 결과 등 표시 값이 바뀔 때 해당 부분만 갱신한다. 재장전 카운트와 포격 효과는 필요한 시점에 업데이트한다. 기존 서버 전송 주기는 유지한다.
- 접속·종료, 상태 변경, 시야 이동, 공격 결과·재장전 표시가 빠지지 않는지 확인하고, 정지 상태에서 화면 다시 그리는 횟수를 비교한다.

## 구현 순서와 배포 기준

1. 살랄라 회귀 검증과 모바일 알림 수정을 진행한다.
2. 장비 저장 형식, 효과 계산, 장착 화면 순으로 연결한다.
3. 점검 중 코린토스 장부를 다시 대조하고 환급을 예약한다.
4. 명단·전투 최적화 전후를 비교한다. 모바일 조작과 장비 저장, 운하 정산의 검증 결과를 모은 뒤 운영 배포 범위를 정한다.

장비와 알림은 기존 저장과 정적 파일로 처리한다. 운하 환급에는 점검 시 장부 확인과 계정별 1회 정산이 필요하다. 배포 시 공개 점검 안내 게시, 접속 중단, 새 버전과 필요한 규칙 반영, 접속 재개 확인의 기존 운영 절차를 따른다.
