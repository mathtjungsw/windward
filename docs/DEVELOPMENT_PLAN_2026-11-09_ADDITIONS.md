# 바람의 항로 추가 상세 개발계획 · 탐험·선단·항구와 활동

작성: 2026-11-09 / 상태: **계획 작성 완료 · 구현·배포 대기**

최신 검토 결정 반영: 일반 항해 2초·정지/접속 유지 30초, 항구 취득/개발 비용 10배, 기본 세율 0%, 중립 보장은 리스본·포르투만, 일반 항구 투자 지분 50% 초과 소유, 해안 약탈 실패의 선박 파손·재산 손실, 대포 종류·품질 확장. 기존 시안 이미지의 비용·기본 세율·5종×3품질 표시는 이전안이며 본문을 우선한다.

## 1. 범위와 기존 계획의 관계

이번 요청은 새 개선안을 구체적인 계획으로 작성하는 단계다. 게임 코드·운영 DB·배포는 이 단계에서 변경하지 않는다. 부족한 지역의 항구 추가도 아래 콘텐츠 확장 범위에 포함한다. 유물·발견물의 지역 편중도 함께 보완한다.

- [기존 공동 시장·대포 전투 계획](../DEVELOPMENT_PLAN.md)과 [시장 명세](SHARED_MARKET_PLAN_2026-11-06.md)는 원문을 보존한다. 대포 종류·품질·탑재 허용은 후속 요청을 반영한 본문 19절을 우선한다. 세 전투 모드·패배 손실은 유지한다.
- 본 문서는 이후 결정된 **판매 전량 동일 단가**, **탐험 거리·팝업**, **혼합 선단 속도**, **일반 항해/대결 전송 주기**를 보완한다. 후속 사용자 요청에 따른 항구 투자 지분과 대포 8종×품질 5등급 추천안도 기존 관련 표보다 우선한다.
- 6배 항해 체감, 시작 뗏목과 10일 보급, 최대 5척, Google 로그인과 현실서버, 기존 진행 보존을 출발점으로 삼는다.

## 2. 현재 코드에서 확인한 출발점

2026-11-09 로컬 카탈로그 기준이다. 대륙은 게임의 권역 분류이며 하와이·태평양 섬은 오세아니아로 분류한다.

| 권역 | 항구 | 발견물 | 항구 추가안 | 추가 후 항구 |

| 유럽 | 14 | 6 | 0 | 14 |

현재 선단은 `shipTier` 하나와 `fleetCount`로 동일 단계의 여러 배를 표현한다. 지도 동행선은 항로 뒤쪽에 표시하지만 개별 선박 단계·속도는 없다. 조사 안내는 항해 조작 창 내부에 있다. `FleetPresence`는 1.5초마다 확인하며, 위치가 계속 달라지면 30초 조건이 최소 전송 간격으로 작동하지 않는다.

## 3. 발견 거리와 소문

| 항목 | 현재 | 새 기본안 |
| --- | --- | --- |
| 항구 정보 발견 | 40해리 | 80해리 |
| 발견물 흔적 | 난도별 40/30/20/12해리 | 모든 난도 100해리 |
| 조사·수집 | 난도별 12/10/8/6해리 | 모든 난도 60해리 |
| 소문 | 난도 3에 1개·난도 4에 2개 | 기존 조건 유지 |

1. 소문 메뉴·내용·획득 기록과 `hasClues` 조건을 유지한다. 소문 미충족 발견물의 정확한 이름·정답 위치·그림을 가까이 왔다는 이유로 공개하지 않는다.
2. 자동·직접 이동 모두 **이전 위치~새 위치 구간**에서 흔적 반경 진입을 검사한다. 프레임 끝 위치만 검사해 빠른 배가 놓치는 문제를 막는다. 육지·다른 수로 너머의 조사는 허용하지 않는다.
3. 조사 거리와 입항 거리는 별개다. 항구 정보를 80해리에서 얻어도 실제 입항·거래·방문 보상 판정을 확대하지 않는다.
4. 구조·안전 귀환 중에는 탐험 안개·항구 발견·흔적·조사·보상을 차단한다. 정상 항해 후에만 재개한다.
5. 새 항구 주점에도 소문을 배치하되 기존 제공 항구를 삭제하지 않는다. 난도 4의 두 단서를 한 항구의 같은 버튼 두 번으로 충족시키지 않는다.

## 4. PC·모바일 조사 팝업

- 조건을 충족한 새로운 흔적이 탐지되면 **PC는 지도 위 중앙, 모바일은 화면 안**에 같은 발견 대화상자를 연다. 제목은 ‘유물의 흔적을 발견했어요’처럼 종류를 안내하고 실제 명칭은 수집 후 공개한다.
- 이동 구간 중 흔적 범위에 처음 들어오는 위치에서 움직임을 끝내고 실제 이동한 거리만큼 시간·보급을 반영한다. 범위를 지나친 끝 위치에서 오래된 버튼만 띄우거나 배를 과거 위치로 순간이동시키지 않는다.
- 버튼은 **조사하기 / 조사 지점으로 이동 / 닫기**다. 조사 가능 거리는 현재 거리와 함께 표시한다. 60해리 밖이거나 수로가 막히면 조사 버튼 비활성 사유를 설명한다.
- 추천 폭은 PC 최대 480px, 모바일 `화면 폭−32px`, 높이는 내용에 맞추고 최대 `80dvh`다. 행동 버튼 높이는 최소 48px, 모바일 두 주요 버튼은 세로 배치한다. 긴 설명만 내부 스크롤한다.
- 새 팝업을 열 때 자동 항해와 직접 조종을 정지하고 누른 키·터치 조종을 해제한다. 닫았다고 자동 재출항하지 않고 ‘항해 계속’으로 재개한다. 직접 조종은 다음 키/클릭부터 다시 움직인다.
- 이동 버튼은 원래 목적지를 보관하고 접근 가능한 조사 수역까지 실제 항로를 만든다. 도착 후 조사 팝업을 다시 열며, 수집 후 ‘원래 항로 계속’ 또는 현재 위치 유지 중 선택한다.
- 동시에 여러 흔적을 감지하면 하나의 팝업 안 목록으로 보여준다. 가까운 순서, 동점은 ID 순서다. 다른 거래·전투 대화상자를 덮지 않고 발견 ID를 대기 목록에 둔다. 대결 중에는 안전한 전투 종료 뒤에 안내한다.
- 닫은 흔적은 같은 접근에서 반복 자동 표시하지 않는다. 지도 위 ‘주변 흔적 N’ 버튼으로 다시 연다. 재탐지 자동 표시는 120해리 밖으로 나갔다 재진입하고 5분 이상 지난 경우에만 허용하는 기본안이다.
- 닫기·Esc·초점 이동과 복귀, 채팅 입력 중 배 이동 방지, 재접속·중복 클릭의 단일 수집을 검증한다. 기존 사이드 안내는 팝업 재열기 보조 역할로 둔다.

## 5. 미니맵 보기 전환과 지도 경계

### 5.1 두 가지 보기

미니맵 이름을 ‘세계지도’로 바꾸고 **지구본 / 평면지도** 선택 버튼을 둔다. 기본은 현재 지구본, 마지막 선택은 기기 설정에 저장한다. DB 쓰기를 추가하지 않는다.

- 지구본: 기존 회전, 선택 지점의 메인 해도 보기, ‘내 배’ 복귀를 유지한다.
- 평면: 전 세계 개요를 가로형으로 표시하고 현재 해도 범위를 사각 테두리로 그린다. 클릭/탭은 **카메라 이동만** 한다. 배 이동·출항·미발견 항구 해금은 일어나지 않는다.
- 두 보기의 내 배·알려진 항구·안개·시야 180해리 안 다른 배 조건을 공통 함수로 계산한다. 투영 변경으로 정보 노출 조건이 달라지지 않는다.
- 선택한 캔버스만 그린다. 지도 자산과 항구 정보를 재사용하고 전환 때문에 서버를 다시 읽지 않는다. PC·모바일 모두 접기와 선택 상태를 표시한다.

### 5.2 북쪽·남쪽 경계 오류

현재 메인 해도는 **북위 80도~남위 60도**를 연결한다. 사용자가 이전에 요청한 북쪽 끝→남쪽 등장 규칙은 유지하며, 실제 지구의 극점 통과라고 설명하지 않는다. 남극 전체 항로를 이번 작업에서 새로 만들지 않는다.

점검 대상은 좌표 정규화, 동서/남북 경계 분할, 카메라, 미니맵 테두리, 꼬리 대형, 안개 점수, 항로 길이와 보급이다. 경계 전후 두 구간으로 처리해 세계 전체를 가로지르는 선·과도한 발견·순간 보급 소모가 발생하지 않게 한다. 아직 오류 재현을 완료한 것은 아니므로 구현 시 원인을 확인한 뒤 영향 파일만 수정한다.

## 6. 배별 선박과 꼬리 대형

### 6.1 저장과 성장 기본안

추천안은 `fleetShips: [{id, tier}]`와 `flagshipId`를 도입해 선박별 단계를 표현하는 것이다. 기존 n척은 **같은 현재 단계 n척**으로 이관한다. 돈·화물·보급량·개량 이력·뗏목 전환 표식은 보존한다.

- 개별 개량과 ‘같은 단계 선박 한꺼번에 개량’을 제공한다. 기존 선단 전체 개량의 비용 할인은 일괄 개량에만 유지한다. 이관 자체에는 비용을 청구하지 않는다.
- 배 추가 기본안은 현재 기함과 같은 단계의 배를 기존 추가선 가격식으로 구입하는 것이다. 개별 개량 이후 선종 차이가 생겨도 다른 배를 무료로 따라 개량하지 않는다. 구입 미리보기에 선단 속도·보급·가격 변화와 병목 선박을 표시한다.
- 최대 5척과 6/10/14/18단계의 대수 해금을 유지한다. 대수 상한은 가장 높은 보유 단계로 판단하되 이미 보유한 배를 삭제하지 않는다. 배 판매·해체는 이번 기본안에 추가하지 않는다.
- 혼합 선단 적재는 `floor(가장 큰 한 척 적재 + 나머지 각 적재×0.6)`를 추천한다. 동일 선종만 있으면 기존 식과 일치한다. 보급 공간은 기존 `ceil(항해 가능 일수×척수/2)`를 유지한다.
- 보급 최대 일수는 모든 배 중 최솟값, 한 선단 일일 보급 구입가는 각 배의 일일 가격 합계로 계산한다. 이관 시 기존 보급 일수·총량이 바뀌지 않는다.
- 외해 허용도는 가장 낮은 배를 기준으로 한다. 빠른 고급 배 한 척만 추가해 뗏목을 원양으로 끌고 가는 우회를 막는다.

### 6.2 속도와 표현

`선단 해상 속도 = min(각 배의 해상 속도)`, 강 속도도 동일하게 최솟값을 쓴다. 자동 항해·직접 조종·예상 도착·항로별 보급·복귀 가능성 검사에 같은 함수를 쓴다. ‘속도 제한: ○○호’와 개량 시 달라질 선단 속도를 내 배 창에 표시한다.

기함을 조종하면 나머지는 **기함의 실제 이동 궤적**에서 순서대로 뒤따른다. 간격 기본안은 화면상 선체 길이의 1.5~2배이며 간격을 별도 항해 거리로 청구하지 않는다. 회전 시 각 선박의 접선 방향을 적용한다. 정박·출항 직후에는 배가 겹치지 않게 부두 표시로 묶고, 충분한 궤적이 생긴 뒤 대형을 편다. 강·육지·경계를 가로질러 직선으로 배를 배치하지 않는다.

기함 위치와 선박 단계/순서만 동기화하고 동행선마다 별도 접속·고빈도 좌표를 만들지 않는다. 다른 이용자의 꼬리 대형도 시야 안에서 동일하게 계산하되 오래된 위치를 무한 예측하지 않는다. 개별 대포 허용 종류·무게는 기존 전투 계획의 선박 단계별 표를 각 배에 적용한다.

기존 전투의 한 척 HP 공식은 보존하되 혼합 선단 HP는 각 배 HP의 합으로 계산한다. 수리비·구조비 평가액도 각 배의 실제 단계 합계로 계산해 기함 단계만으로 과대/과소 산정하지 않는다.

| 개인 저장·랭킹 | 기존 저장 절차 | 위치 프레임/조준 틱마다 저장하지 않음 |

위치 변화 여부와 무관하게 최소 2초를 먼저 검사한다. 입출항·연결 복구는 최신 위치/상태 한 건을 우선 전송하며 구역 이동과 쓰기를 합친다. 구역 전환을 최소 간격 우회 통로로 쓰지 않도록 일반 이동은 계속 2초를 지킨다. 이동 도중 1.5초마다 계속 전송되는 현 조건을 해소한다.

현재 1.5초 확인 타이머를 그대로 두고 2초 제한만 추가하면 실제 전송이 3초마다 될 수 있으므로 스케줄러도 함께 바꾼다. 다음 전송 시각 예약 또는 짧은 로컬 확인 주기로 2초 간격을 맞추며, 확인할 때마다 DB에 쓰지 않는다. 브라우저 백그라운드 타이머 지연은 허용하되 복귀 때 오래된 위치 큐를 한꺼번에 재생하지 않는다.

일반 선박은 수신 위치와 항로/진행 방향으로 부드럽게 표시하되 예측은 최대 다음 전송 간격까지만 한다. 예측 좌표로 공격 명중·항구 방문·발견·보급을 확정하지 않는다. 빠른 배의 시야 판정 지연을 실제 6배 속도로 확인한다.

대결 정보는 `battles/{battleId}`의 참가자 전용 경로에 둔다. 대결 종료·화면 이탈·연결 종료 후 구독과 표시 상태 전송을 해제한다. 체력/재장전은 변화 때만 보내고 별도 0.25초 타이머로 같은 값을 계속 저장하지 않는다. 발사 순번·revision·최종 처리 시각으로 중복/역순을 차단한다. 기존 대포 계획의 절대시간·정산·손실과 동의 결투 중 항해 정지 규칙을 유지한다. 이 계획은 새로운 이동/수동 조준 전투를 추가하는 지시가 아니다.

검토 의견: 현재 1.5초는 확인 타이머이며 이동 중 변화가 계속되면 그 간격으로 전송할 수 있다. 2초로 바꾸면 이동 전송의 이론상 최대 빈도는 분당 40→30회, 약 25% 감소한다. 전체 월 다운로드의 25% 감소를 뜻하지는 않는다. 초반 약 40해리/초의 속도에서는 수신 사이 이동 거리가 약 60→80해리로 늘어, 앞선 5초안의 약 200해리보다 시야 180해리 안 움직임을 따라가기 좋다. 고급 선박·직접 급회전은 별도 확인하고 예측 위치로 피해를 확정하지 않는다. 대결 시작 시 실제 위치·상태를 새로 확인한다.

2초는 조작감과 절감을 함께 고려한 타협안으로 적절하나, 큰 폭의 전송량 절감은 정지 중 불필요한 쓰기 제거·변경분만 전달·필요 구역만 구독하는 작업도 함께 해야 한다. 대결 4Hz는 변경이 있는 경우의 상한이고 두 명·대결 중으로만 제한한다. 발사 결과는 즉시 전달한다. 기존 Spark를 사용하며 유료 요금제 변경을 포함하지 않는다.

## 8. 판매 전량 동일 단가: 기존 시장 계획의 변경분

판매 견적 시각의 회복된 시세로 한 번 단가를 계산한다. `판매 총액 = floor(기준가×시장 계수×0.88) × 수량`. 한 판매 건의 모든 상자는 같은 단가다. 그 거래의 압력은 정산 뒤 `판매 수량×−0.1%p`만큼 반영하고 ±30% 제한, 분당 1.5%p 회복, 서버 절대시간을 유지한다.

단가 100 D에서 100상자는 10,000 D, 50상자는 5,000 D다. 동일 초기 상태에서 100상자 판매의 하락 폭은 10%p, 50상자는 5%p다. 가격 하한에서는 차이가 포화된다. 50상자 두 번 판매는 두 번째 거래가 새 시세이므로 한 번에 100상자와 수령액이 같을 필요가 없다. 최종 압력은 동일 시간·다른 거래 없음 조건에서 같아야 한다.

기존 상자별 한계가격 합산·대량/분할 총액 일치 검증은 **판매에 한해** 위 기준으로 대체한다. 구매는 기존 계획대로 상자별 가격을 합산한다. 견적 유효 5초·revision 충돌 시 재견적·개인 저장과 시장 원자 반영·재시도 중복 차단은 기존 명세를 그대로 사용한다. 세금이 도입되면 고정 판매 단가는 그대로 표시하고 세금과 순수령액을 별도 표시한다.

## 11. 항구 소유·세금·블랙리스트 추천안

최신 사용자 결정은 일반 항구의 **누적 투자 지분으로 소유자를 정하는 방식**이다. 중립 보장은 리스본·포르투 두 곳뿐이며 이번에 추가하는 8개 항구도 그 외 일반 항구와 같은 투자 대상이다. 전투로 항구를 빼앗는 규칙은 별도 결정 사항이다.

- 일반 항구 최초 투자 개방 기준은 **1,000,000 D**, 대형 항구는 **3,000,000 D**다. 앞선 100,000/300,000 D의 10배로 사용자 지정했다. 첫 투자자는 이 기준 이상을 납입하고, 이후 다른 선장의 추가 투자도 허용한다. 후속 최소 투자 단위는 10,000 D를 추천한다. 매 추가 투자마다 최초 기준액을 다시 낼 필요는 없다.
- `지분=본인 누적 투자금/항구 전체 누적 투자금`. `2×본인 투자금 > 전체 투자금`을 만족하는 선장만 소유자다. 표시 반올림으로 50% 초과 여부를 판단하지 않는다. 정확히 50%인 선장이나 지분 1위가 50% 이하인 선장은 소유자가 아니다. 과반이 없으면 ‘공동 투자·소유자 없음’으로 표시한다.
- 예: A 100만 D 투자 시 A 100% 소유 → B가 100만 D 추가 시 각 50%·소유자 없음 → B가 10만 D 더 투자하면 B 110/210만=약 52.38%로 소유자가 된다. A의 투자금은 남아 있고 돈을 다시 받아가는 것은 아니다.
- 본인 잔액 차감·투자 지분·전체 자본금·소유자·revision을 같은 거래로 확정한다. 여러 선장의 동시 투자도 누락 없이 순서대로 반영하고 재시도로 중복 납입하지 않는다. 이때 투자 원금을 과거 소유자의 개인 돈으로 지급하지 않고 항구 투자 장부에 귀속한다.
- 최초안의 ‘선장당 최대 3곳’은 지분에 따른 소유 자동 판정과 충돌하므로 적용하지 않는 추천안으로 바꾼다. 투자금 인출·지분 매매·배당은 별도 결정 전에는 제공하지 않으며, 투자 전 환급되지 않는 누적 항구 투자임을 표시한다.
- **기본 세율은 0%**로 한다. 소유자가 직접 설정할 때만 일반/선장별 0~10% 범위에서 부과한다. 구입에는 상품 금액 외 세금, 판매에는 총 판매액에서 세금을 공제한다. `세금=floor(상품 총액×세율/100)`이며 소유자 본인 0%다. 보급·구조·입항·소문에는 세금을 부과하지 않는다.
- 세금은 발생 시점 소유자의 항구별 수령 장부에 적립한다. 소유권이 바뀌어도 이미 적립된 전 소유자의 세금을 새 소유자가 가져가지 않는다. 소유자 없음 상태는 0%·제한 해제로 운영하며 소유권 변경 시 새 세율도 0%·블랙리스트 비움으로 시작하는 안을 추천한다. 장부 인출도 중복 처리하지 않는다.
- 블랙리스트 최대 20명, UID로 기록한다. 추천 기본은 **교역·카지노·선박 서비스 제한**이며 입항·필수 보급·자동 구조는 허용한다. 이름 변경·오프라인으로 목록 대상이 바뀌지 않는다.
- 세율/블랙리스트 변경은 다음 거래 견적부터 반영하고 진행 중 확정 견적을 조용히 바꾸지 않는다. 항구 정보에 소유자·내 세율·이용 제한·중립 보장 기능을 표시한다.

투자 지분 50% 초과 소유, 비용 10배, 기본 세율 0%, 중립 항구 두 곳은 사용자 결정이다. 후속 투자 단위·소유 개수 상한 해제·무소유 상태 운영·원금 인출/배당 제외는 이를 구체화하는 추천안이다. 소유자 변경과 기존 인프라·방문 기록은 분리하며, 투자 경쟁 때문에 항구를 삭제하거나 이름/개발 단계를 초기화하지 않는다.

## 12. 새 항구 개발 추천안

첫 범위는 무제한 자유 좌표 건설 대신 **사전에 수로 검증한 개발 후보지 12곳**을 제시한다. 이번 공공 항구 8곳과 별개이며, 후보 목록·실제 지명·공공 항구와 250해리 이상 간격을 검증한 뒤 콘텐츠 표로 확정한다.

- 사용자 지시에 따라 개발 관련 비용도 10배로 한다. **개척비 2,000,000 D, 교역소 확장 1,000,000 D, 조선 서비스 확장 1,500,000 D**다. 개척 완료 시부터 개발 선장이 소유한다. 일반 항구와 달리 개발 항구의 지분 공개 투자/소유권 경쟁은 아직 요청되지 않았으므로 첫 범위에 자동 도입하지 않는다. 기본은 입항·보급·주점, 확장 뒤 정해진 상품의 교역·선박 서비스를 연다.
- 현재 위치에서 후보지를 선택하고 실제 접근해 결제한다. 개발 상태/소유권·비용은 같은 revision으로 저장한다. 시간 경과 건설 타이머나 추가 상시 작업은 첫 범위에 필요하지 않다.
- 실제 지명 추천을 기본 이름으로 주고 개발 선장이 표시 이름 2~16자로 지정할 수 있게 한다. 고정 ID·실제 지명 부제는 유지한다. 운영자도 이름을 수정할 수 있으나 플레이어 과거 기록의 ID는 바꾸지 않는다.
- 임의 상품 생산지 생성은 허용하지 않고 지역별 사전 지정 경제표를 사용한다. 소유자 변경·개발 확장으로 가격 차익을 무한 생성하지 않게 한다.
- 배경 정적 후보 좌표만 배포하고 개척 상태·이름·소유권만 작은 공용 경로에서 읽는다. 미개발 후보지를 일반 방문 항구 총수로 계산하지 않는다.

후보지 12곳의 최종 명단은 공공 8개 항구의 부두·항로가 확정된 뒤 선정한다. 이 선정이 끝나기 전 개발 항구 기능을 완료로 판정하지 않는다.

## 13. 비항구 해안 정박·활동 추천안

접근 가능한 연안 활동 지점 12곳부터 시작한다. 아무 육지 클릭을 상륙으로 바꾸지 않고, 지점 앞 수역 10해리 안에서 ‘해안 정박’을 선택한다. 항구 방문·시장·자동 구조 목적지로 계산하지 않는다.

- 보급: 지점당 현실 24시간에 한 번, 최대 2일분, 항구 보급가의 1.5배, 선단 적재·보급 한도 적용. 항구가 드문 구간의 보조 수단으로 둔다.
- 약탈: 창작 해적의 방치 보급품을 대상으로 한다. 기존 실제 도시·유적·다른 선장의 저장을 임의로 약탈하는 기능으로 확대하지 않는다. 기본안은 시도 시 보급 0.2일 소모, 성공 70%에 200 D, 선장당 하루 최대 3회다. 사용자 요청대로 실패에는 **선박 파손과 재산 손실**을 함께 적용한다.
- 실패 손실 추천안: 선단 최대 내구도(HP)의 15% 피해, 현금 5%·최대 500 D, 교역품 수량 5% 내림·최대 3상자 손실. 화물 선택 순서는 상품 ID 고정 순서다. 기존 ‘실패 시 추가 보급 0.5일’은 이 파손·재산 손실안으로 대체한다. 구체 비율은 사용자 확정값이 아니다.
- 파손은 항해/대포 전투와 같은 지속 HP를 사용해 새로고침으로 사라지지 않게 한다. 배를 영구 삭제하지 않는다. HP 0이면 이미 방문한 항구로 자동 구조하고 발견·안개 개방을 차단한다. 실패 손실과 구조 정산 ID를 연결해 전투 패배 약탈을 다시 중복 적용하지 않는다. 수리비는 별도 안내하며 돈이 없어도 구조한다.
- HP가 남으면 손상 상태를 표시하고 항구 수리를 제공한다. 추천 수리비는 `ceil(기존 전투 계획의 완전 수리 기준액×손상 비율)`, 최소 1 D다. 약탈 전 예상 피해·금품 최대 손실·행동 횟수 제한을 확인시킨다.
- 파손이 추가되면 기존 성공 보상 200 D와의 균형을 다시 검사한다. 고급 선단의 수리비·고가 화물 손실 때문에 항상 손해인 선택이 되면 지점 난도별 보상 또는 손실 상한을 조정한다. 피해 적용 결정과 위 추천 수치를 구분하고, 기존 대포 전투 보상까지 임의로 올리지 않는다.
- 약탈 대상 해석·보상·확률은 추천 설정이다. 기존 대포 전투의 실제 선장 약탈과 다른 활동 ID/정산을 쓴다. 서버 절대시간으로 재사용 제한을 저장하며 새로고침으로 보상 재수령을 막는다.
- 보급 소진으로 구조가 이미 시작됐으면 활동으로 구조를 취소하지 않는다. 정박 중 전투·자동 항해·중복 활동을 동시에 실행하지 않는다.

## 14. 카지노 추천안

마카오·베네치아의 **게임용 주사위장**을 첫 후보로 둔다. 도시의 특정 시대 카지노 역사를 재현한다고 표시하지 않고 장소 선정과 실제 역사 설명을 구분한다.

- 게임 내 두카트만 사용하고 현실 결제·환전은 없다. 홀짝 하나 선택, 1~6 주사위 한 번, 각 결과 확률 1/6, 맞히면 베팅액 포함 1.9배를 내림 지급하는 기본안이다. 기대 환급은 95%다.
- 10~500 D, 10 D 단위, 현실 5초 간격을 추천한다. 굴리기 전에 비용·승리 시 총 지급·실패 시 손실을 표시한다. 잔액 부족/결과 확인 중에는 반복 실행을 잠근다.
- 한 회차 ID에 베팅 차감·결과·지급을 연결한다. 재접속 뒤 결과를 복원하고 애니메이션 취소로 결과를 다시 뽑지 않는다. 도박 획득금은 무역 이익에 포함하지 않는다.
- 현재 클라이언트 계산 중심 구조로 변조에 강한 공정성을 보장한다고 설명하지 않는다. 친구 게임 신뢰 모델과 회차 일관성은 구분하고, 권한 있는 판정 서버가 필요해지면 구성·비용을 별도로 구체화한다.

## 16. 저장·동기화·비용과 이관

기존 계정의 revision·세션 잠금·저장 확인 후 공개 요약 발행을 유지한다. 새 필드는 개인의 선박 목록·활동 회차/시간과 공용의 항구 소유/금고·고급 재고·진행 중 대결 변경분이다. 이미지·전체 지도·전체 이용자 저장을 DB에 넣지 않는다.

시장 계획의 원자 거래·쓰기 대기열·보류 영수증을 공용 기반으로 사용한다. 항구 취득·개발·세금·금고 인출·베팅·해안 보상도 같은 계정 동시 쓰기 대기열에 연결하고, 돈 차감과 권리/보상을 따로 확정하지 않는다. 규칙은 참가자·소유자 권한·revision·수량/잔액·중복 회차를 검사한다. 현재 JSON 개인 저장만으로 모든 경제 계산을 서버 규칙에서 엄격하게 증명할 수 있다는 보장은 하지 않는다.

버전은 기존 `schemaVersion=4`, 게임 저장 v3에서 **계획 통합 시 공통 버전**으로 한 번 올린다. 시장 계획의 v5 봉투·v4 게임 저장 제안을 공통 초안으로 사용하고 별도 기능마다 제각각 이관하지 않는다. 알 수 없는 미래 버전·실패한 읽기는 초기화하지 않고 기록을 보존하며 안내한다.

새 유료 서비스 가입·Blaze 전환은 계획에 포함하지 않는다. 소유권/세금/재고는 거래 때만, 명부는 페이지 단위, 랭킹은 선택한 탭 상위 5명만 읽는다. 고빈도 대결 경로를 전체 접속자에게 구독시키지 않는다. 지난 사용량 조회는 2026-11-07 관측이므로 현재 이용량으로 둔갑시키지 않는다. 구현 전후 동일 조건 전송량을 비교하되 무료량 검증을 모든 개발의 필수 승인 절차로 만들지 않는다.

## 19. 대포 확장 개정안 · 8종 × 품질 5등급

사용자는 대포 종류와 품질을 더 다양하게 요청했다. 구체 수는 추천안으로 **기존 5종×3품질을 8종×5품질, 총 40조합**으로 늘린다. 실제 역사적 포제의 정확한 복원표가 아니라 게임용 이름·성능이다. 새로운 공격 대상이나 포탄 상태이상은 추가하지 않는다.

허용 품질은 1~3단계 없음, 4~7 I, 8~11 II, 12~15 III, 16~18 IV, 19~20 V로 바꾼다. 위 종류의 시작 단계와 품질 조건을 **모두** 만족해야 장착한다. 예를 들어 7단계는 속사포 I가 가능하지만 속사포 II는 불가하다.

기존 20단계별 포대 수·총 무게 한도는 유지한다. 종류 해금이 늘어도 장착 수나 무게를 무료로 늘리지 않는다. 20단계 5척 최대 40포대는 그대로이며 한 선단이 대포 종류×품질 40조합을 모두 가질 수 있다는 뜻과 구분한다.

명중률은 품질/결투 보정 후 5~95% 제한, 피해 반올림·최소 1, 재장전은 0.1초 단위 올림을 유지한다. 결투 강화는 기존 피해 ×1.5·명중 +10%p·재장전 ×0.7이다. 최대 품질 정밀 장포도 100% 명중하지 않는다. 예: 일반 속사포 10피해·72%·4초 → 명장 속사포 20피해·84%·2.6초, 명장 속사포의 결투 재장전은 1.9초다.

속사포 때문에 전투 정보 전체를 매 프레임 저장하지 않는다. 한 번의 일제사격 요청에서 실제 준비 포대들의 명중·HP·readyAt을 묶어 확정한다. 기존 보관 상한 100포대, 품질 개량은 가격 차액, 매각 60%, 별도 포탄 재고 없음은 유지한다.

검증 기준: 40조합의 표시/계산, 경계 단계 7/8·11/12·15/16·18/19, 95% 명중 상한, 결투 재장전 반올림, 혼합 선박별 장착 제한, 최대 포대의 동시 발사 중복 방지와 전송량을 확인한다. 각 종류가 비슷한 가격대에서 역할을 갖는지 기대 피해/재장전과 명중을 비교해 밸런스를 조정한다.

추가 검증: 항구 투자에서 50% 미만·정확히 50%·초과를 정수 비교하고 동시 투자/소유권 교체/세금 귀속을 확인한다. 약탈 실패의 HP·현금·화물 손실은 단일 회차로 저장하고 HP 0 구조에 손실이 중복되지 않는지 확인한다.
