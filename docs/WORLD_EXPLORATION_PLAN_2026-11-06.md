# 주요 항구 70곳·섬 거점·발견물 32종 상세 명세

- 작성일: 2026-11-06. **계획안이며 미구현·미배포다.**
- 상위 계획: [통합 개발계획](../DEVELOPMENT_PLAN.md).
- 항구 이름·ID·권역의 기준안이다. 신설 항구의 정확한 도시 좌표·조작 부두와 발견물 관찰 지점은 구현 때 공식 지리 자료와 해도 항로를 대조해 확정한다. 현재 존재하지 않는 부두의 입항까지 검증했다고 취급하지 않는다.

## 1. 밀집을 줄이는 항구 구성

현재 88곳 중 **54곳 유지·34곳 현역에서 제외·16곳 신설 = 현역 70곳**을 기본안으로 한다. ‘현역 제외’는 지도·새 목적지·신규 입항 대상에서 빼는 것이며, 과거 이용자 기록을 지우는 작업이 아니다.

## 3. 간격·섬·초반 항해의 검증 기준

- 항구 수를 맞추기보다 밀집 해소와 항로 연결을 우선한다. 문제가 발견된 후보는 같은 권역의 더 나은 거점으로 교체할 수 있지만, 88곳 이상으로 다시 늘려 해결하지 않는다.
- 해상 항구 사이 **실제 항해 거리 180해리 미만**은 밀집 검토 대상으로 자동 보고한다. 직선거리와 실제 경로를 함께 표시한다. 주요 국가 거점·강 항구·서로 다른 섬 역할의 예외는 이유를 문서로 남긴다.
- 시작 배의 해상 속도에서 180해리는 약 4.5초다. 이것만 최소 재미를 보장하는 수치로 삼지 않고 항구 선택·입항 판정까지 포함해 체험한다. 새로운 소항구를 더 넣어 초기 교역을 해결하지 않는다.
- 새 시작의 개방 항구는 리스본·포르투·세비야 3곳이다. 주점의 기존 정보 획득·40해리 접근 발견은 유지한다. 첫 의뢰 안내는 세투발 대신 포르투로 바꾼다.
- **읽기 전용 현재 코드 계산(2026-11-06):** 리스본→포르투 198.6해리·2.48게임일·약 5.0초, 리스본→세비야 323.4해리·5.40게임일·약 10.8초. 모두 현재 보급 10일과 예비량 0.5일 내에서 가능하다. 현재 80해리 연안 제한으로 리스본→푼샬/앙그라의 항로는 나오지 않았다. 이는 기존 항로 계산 결과이며 신설 16항구의 검증 결과가 아니다.
- 리스본/포르투는 와인과 건어물 등 지역 공급 차이로 왕복 이익을 확인한다. 두 곳 모두 와인 공급지라는 설명을 지우고 인위적으로 한쪽을 와인 원산지로만 만드는 식으로 역사와 가격을 혼동하지 않는다. 가격 역할·식량비·15칸 시작 화물로 계산한 거래 사례를 구현 결과에 남긴다.
- 앙그라·푼샬·카나리아·카보베르데는 대서양 단계 확장의 거점이다. 앙그라의 옛 기항 역할은 [UNESCO 자료](https://whc.unesco.org/en/list/206/), 히베이라그란드의 위치·옛 도시는 [UNESCO 자료](https://whc.unesco.org/en/list/1310/)를 참고한다. 두 자료만으로 모든 상품이나 게임 항로 성능을 검증했다고 하지 않는다.
- 서인도양은 잔지바르·마다가스카르·모리셔스·콜롬보, 태평양은 마닐라/뉴기니·피지/사모아·타히티·하와이·라파누이를 서로 다른 방향의 목적지로 둔다.
- 8/10/16/20단계별 실제 항로·필요 보급·예비량을 계산한다. 모든 섬을 중간 단계부터 갈 수 있게 만들 필요는 없지만, 도감에서 보이는 최종 목적지는 최종 선박의 정상 항해로 방문할 수 있어야 한다. 특히 북미↔하와이, 남미↔라파누이, 타히티↔라파누이, 아프리카↔인도양 섬을 확인한다.
- 작은 섬이 현재 육지 격자에서 빠졌으면 확인한 섬 윤곽/접근 지점을 정적 자료로 보완한다. 섬 부근의 육지를 넓게 지우거나 바다 건너 입항시키지 않는다. 도시 좌표와 부두 좌표를 구분한다.

## 4. 보물찾기 32종의 기본 구성

**유적 8·유물 8·희귀 동물 8·보물 8**, 각 분류 안에서 난도 1/2/3/4를 두 개씩 둔다. 분류 합계로 난도별 8개, 명성 총점 **12,800점**이다. 모든 선장이 각자의 도감으로 수집하며 선착순 독점·랜덤 소멸은 없다.

## 5. 발견 동작과 단서

| 난도 | 명성 | 미발견 징후가 보이는 거리 | 조사 가능 거리 | 조건 |
| --- | ---: | ---: | ---: | --- |
| 1 · 쉬움 | 50 | 40해리 | 12해리 | 일반 항해로 접근 |
| 2 · 보통 | 150 | 30해리 | 10해리 | 일반 항해로 접근 |
| 3 · 어려움 | 400 | 20해리 | 8해리 | 해당 권역의 단서 1개 확인 |
| 4 · 매우 어려움 | 1,000 | 12해리 | 6해리 | 해당 발견물의 단서 2개 확인 |

- 단서는 정박 항구의 주점 ‘탐험 소문’에서 무료로 읽는다. 주점의 기존 100 D 항구 정보 구매와 버튼·설명을 분리한다. 단서 ID는 정적 콘텐츠에 정하고 개인 읽음 상태만 저장한다. 반복해서 읽어도 점수가 없고, 발견하지 않은 항구를 자동 해금하지 않는다.
- 단서 두 개는 두 번 무작정 클릭하는 조건이 아니라 서로 다른 내용/출처 항구를 가진 항목이다. 32개 카탈로그를 확정할 때 단서 제공 항구 ID와 선박 접근 성능을 함께 기록한다. 해당 항구가 제외/미접근 상태여서 영원히 수집 불가능해지는 항목을 배포하지 않는다.
- 단서가 없는 어려운 발견물은 가까이 지나도 정답 이름·그림을 공개하지 않는다. 도감에는 해당 권역에서 소문을 찾아보라는 안내를 둔다. 비싼 새 장비 구매나 무작위 등장 대기는 요구하지 않는다.
- 후보 징후는 작은 물음표와 비차단 안내로 표시한다. 자동으로 큰 팝업을 띄우지 않는다. 가까이에서 ‘조사하기’를 누르면 정지 후 발견 처리한다. 자동 항해 중이면 기존 항로를 보관하고 사용자가 재개할 수 있게 한다.
- 빠른 배가 지나칠 경우 징후 안내에서 ‘조사 지점으로 이동’을 선택할 수 있다. 이 선택 때만 실제 항로를 찾아 접근하며 순간이동하지 않는다. 직접 조종 중에는 누르기 전 자동으로 방향을 빼앗지 않는다.
- 판정은 실제 수로·육지 가림·거리·단서·구조 상태를 공통 검사한다. 육지 반대편·다른 강·서로 먼 해도 경계를 직선 연결해 조사하지 않는다.
- 같은 ID는 계정당 한 번만 수집한다. `발견 명성 = 수집한 유효 ID의 명성 합계`로 계산해 독립적인 점수 누적 오류를 막는다. 수집 당시에 적용된 카탈로그 버전을 남긴다.
- 구조·안전 전환 중에는 징후 표시·조사 버튼·수집·명성·단서 진행을 중지한다. 항구 목록이나 도감 창을 열었다는 이유만으로 판정을 실행하지 않는다.
- 정적 카탈로그가 브라우저에 포함되므로 소스 분석까지 숨기는 보안 기능은 제공하지 않는다. 게임 화면에서 정답을 먼저 노출하지 않는 수준으로 설계한다.

## 6. 수집 이미지 제작

- 32종에 각각 구분되는 이미지 1장과 작은 썸네일을 둔다. 밝은 항해 수첩·손그림 카드 분위기로 맞추고 모든 카드의 비율은 4:3으로 통일한다.
- 권장 원본은 640×480, 작은 표시는 160×120의 WebP/PNG 또는 적합한 SVG다. 본문·이름·점수는 이미지에 굽지 않고 한국어 텍스트로 표시한다.
- 발견 후 그림·이름·명성·설명·발견 날짜·출처/창작 구분을 보여준다. 미발견은 실루엣과 분류만 보여주며 개별 고해상도 이미지를 미리 내려받지 않는다.
- 이미지는 개발 때 제작하고 정적 파일로 배포한다. 이용자가 발견할 때 생성 서비스를 호출하지 않는다. 도감 목록은 지연 로드하며 캐시를 재사용한다. 전체 이미지 최초 전송량 3 MB 이하를 우선 목표로 압축하되, 실제 산출물 용량을 측정해 보고한다.
- 실제 동물·유적 그림은 설명과 식별 가능한 특징을 대조한다. 외부 게임 그림이나 저작권이 불분명한 사진을 복제하지 않는다. 이번 계획 단계에서는 이미지를 생성하지 않는다.
