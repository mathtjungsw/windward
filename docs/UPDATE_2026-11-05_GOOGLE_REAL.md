# Google 로그인과 현실서버 업데이트 실행 기록

## 완료

- Google 로그인, 첫 선장 이름 설정, 현실서버 1배속 자동 입장과 함께 항해 자동 연결을 구현했다.
- 혼자 항해, 6자리 로그인, 서버 선택과 기존 기록 가져오기 화면을 제거했다.
- 새 저장은 `gameV2` 아래에 분리했다. 공개 주소에서 업데이트를 열면 이전 바람의 항로 캐시 키만 정리한다.
- GitHub Pages 배포 커밋은 `3cbcd9972f625e765f6576b0351d9e4ab2bd919a`다. Actions 실행 `41997713639`이 성공했고 공개 파일을 소스와 대조했다.
- Firebase `windward-voyage`에서 Google 제공자와 `mathtjungsw.github.io` 허용 도메인을 설정했다. Google 제공자 활성화 시 기존 소유자 주소를 지원 이메일로 지정했다.
- 최종 규칙을 운영 DB에 배포했다. 새 경로는 Google 인증만 허용하고, 이전 `accounts`, `privateSaves`, `worlds`, `fleet/v1`, `chat/v1` 경로의 클라이언트 접근은 차단했다.

## 검증

- 게임 테스트 46개 통과.
- Firebase 에뮬레이터에서 최근 채팅 50개, 전송 충돌, 개인 저장 소유권, Google 인증 제한, 새 기록 보존과 기존 기록 삭제·재생성 방지 검증 통과.
- 브라우저와 Auth/Database 에뮬레이터에서 선장 이름 설정, 리스본 첫 입장, 접속 명단·채팅 연결, 와인 구매, 새로고침 뒤 화물 복원, 로그아웃을 확인했다. 이 검증은 가상 Google 계정으로 수행했다.
- 운영 DB에서 이전 6자리 검증 계정의 구버전 저장과 새 경로 접근이 모두 거부되는 것을 확인했다.

## 대기

- 공개 사이트의 실제 Google OAuth 로그인 확인. 현재 Work 설정에서 로컬 브라우저 사용이 꺼져 있어 사용자에게 공개 주소에서 입장 확인을 요청했다.
- 실제 입장이 확인되면 승인된 기존 경로 `accounts`, `privateSaves`, `worlds/peace`, `worlds/real`, `fleet/v1`, `chat/v1`만 원자 삭제하고 각 경로가 비었는지 확인한다. `gameV2`의 새 항해는 삭제 대상에서 제외한다.
- Firebase Authentication 계정 자체는 삭제 범위에서 구분한다. 별도 주소와 오프라인 파일의 기기 저장은 해당 저장 공간에서만 정리할 수 있다.
