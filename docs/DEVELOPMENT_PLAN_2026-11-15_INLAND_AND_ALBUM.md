# 내륙 도시·육상 운송과 발견 도감·일일 퀴즈

대상은 [최근 개선안](../IMPROVEMENTS.md)의 두 항목이다. 아래 시간·가격·보상은 게임에서 시험할 제안값이다. 현행 배포판의 찾기·교역·보급·상륙 화면과 저장 흐름을 활용한다.

## 1. 내륙 도시와 육상 운송

### 첫 지도와 도시

실제 내륙 도시를 고정된 위치에 표시한다. 연결 항구에 배를 정박한 뒤 도시를 선택하면 육로를 따라 자동 이동한다. 첫 버전은 항구와 도시 사이의 왕복을 지원한다. 도시는 교역소·주점·조합과 육상 운송 메뉴를 제공한다.

| 정박항 → 도시 | 초안 편도 시간 · 봇짐 기준 | 시범 교역품 |
|---|---:|---|
| 세비야 → 코르도바 | 60초 | 가죽·올리브유 |
| 마르세유 → 아비뇽 | 70초 | 모직물·와인 |
| 베라크루스 → 푸에블라 | 120초 | 직물·도자기 |

품목은 게임 경제 배치안이다. 실제 도시 위치는 [코르도바](https://whc.unesco.org/en/list/313/), [아비뇽](https://whc.unesco.org/en/list/228/), [푸에블라](https://whc.unesco.org/en/list/416/)를 기준으로 확인한다. 다른 곳에서 도시를 누르면 연결 정박항과 경로를 표시한다. 도시 방문 중 선단은 출발 항구의 정박 상태를 유지한다. 귀환하면 원래 배에서 이어간다. 선박 수리·조선·선단 관리는 정박항에서 이용한다. 조합에서는 도시와 정박항 사이의 화물 운반 의뢰를 수락한다. 수락 화면에 수량·경로·기한·보수를 표시하고 완료 시 한 번 정산한다.

### 20단계 운송 수단

[개선안의 20단계 적재량 표](../IMPROVEMENTS.md)를 적용한다. 1단계 봇짐 10상자, 5단계 짐나귀 40상자, 10단계 대형 우차 145상자, 15단계 2대 마차 행렬 390상자, 20단계 대형 상단 1,000상자다. 운송 메뉴에서 보유 단계와 다음 단계의 적재량, 필요한 운송 횟수와 시간, 업그레이드 가격을 비교한다.

- **가격 초안** — 무료 봇짐으로 시작한다. 5·10·15·20단계까지의 누적 비용 목표는 각각 2,000·20,000·120,000·500,000두카트다. 구간별 중간 단계 가격은 각 목표 사이에 배분한다.
- **노선별 속도** — 모든 단계가 기본 노선을 이용한다. 짐동물은 고갯길에서, 수레와 마차 행렬은 큰길에서 속도 이점을 가진다. 시범 노선의 최저 편도 시간은 30초로 잡는다. 대량 운송 시간 차이는 주로 적재량과 왕복 횟수에서 생긴다.
- **업그레이드 적용** — 진행 중인 운송은 예약 시 수단의 적재량과 시간으로 끝낸다. 다음 운송 예약부터 새 단계가 적용된다. 배와 육상 수단의 적재 한도는 각각 표시한다.

### 한 번에 거래하고 창고에서 운송 예약

각 도시와 연결 항구에 선장 개인 창고를 둔다. 시범 용량은 지점마다 2,000상자다. 화면에는 배·항구 창고·도시 창고의 재고와 예약량, 판매 가능 수량을 표시한다. 선단의 적재 한도는 배에 화물을 옮길 때 적용하고, 남는 화물은 창고에 보관한다.

구매·판매 모두 시장과 수량을 선택하고 **시장 시세를 전량에 한 번 적용**한다. 상자당 50두카트에 100상자를 확정하면 세전 5,000두카트다. 세금과 총액은 확인 화면에 표시하고, 체결 뒤 두카트·시장 재고·시세에는 100상자를 한 번 반영한다. 확정 직전 시세가 달라지면 바뀐 견적을 표시한다.

구입분은 구매한 곳의 창고에 들어간다. 구매 완료 화면에서 그 수량을 그대로 운송에 예약할 수 있다. 도착지에서 판매할 때는 현지 창고에 입고된 수량으로 거래를 확정한다. 대기·운송 중인 화물은 다른 운송이나 판매에 중복 사용되지 않도록 예약한다. 자금·재고·공간 부족 시 가능한 최대 수량을 표시한다.

### 화면을 닫아도 진행하는 자동 왕복

1. **예약** — 출발지·도착지·상품·총수량을 한 번 지정한다. 적재 이동 횟수는 총수량을 적재량으로 나눠 올림하고 빈 수레 복귀는 한 번 적다. 봇짐 100상자는 적재 이동 10회와 빈 복귀 9회다. 20단계 1,000상자는 적재 이동 1회다. 예정 횟수·도착 예정 시각·보급비를 표시한다.
2. **운송** — 출발지 화물과 도착지 공간을 예약한다. 각 구간 출발 시 보급비를 부담하며, 비용이 부족하면 다음 구간을 멈춘다. 화물이 도착할 때마다 예약을 실제 재고로 바꾼다.
3. **정산** — 시작 시각, 편도 시간, 마지막으로 처리한 구간을 저장한다. 접속·운송 화면 열기·창고 거래 전에 경과 시간을 확인해 끝난 여러 구간을 한꺼번에 반영한다. 진행 표시는 기기에서 계산한다. 화물 수량·원가·비용·진행 구간을 같은 저장 작업에 묶고, 첫 버전은 선장당 진행 중인 운송 한 건을 지원한다.
4. **정지와 재개** — 수동 중지를 누르면 이미 출발한 화물을 하역한 뒤 멈춘다. 남은 예약 물량과 공간을 풀고, 아직 시작하지 않은 구간의 보급비는 청구하지 않는다. 다시 시작하면 남은 수량을 예약한다. 보급이나 공간 문제로 정지한 경우 사유와 이어가기 버튼을 표시한다.

지도에는 육상 이동 수단과 남은 시간을 작게 표시한다. 운송 메뉴의 진행 예시는 ‘40 / 100상자 도착’이다. 각 회차의 하역은 진행 표시로 확인하고, 완료·중지 시 알림을 한 번 띄운다.

## 2. 발견 도감 30종과 오늘의 퀴즈

### 발견과 상세 화면

[후보 30종과 출처](../IMPROVEMENTS.md)에 적은 책·기록물 14종과 항해 도구·유물·유적·자연지형 16종을 적용 범위로 둔다. 책까지 기존 유적·유물과 동일하게 **흔적 포착 → 접근 → 조사하기 → 도감 등록**으로 얻는다. 기존 탐험 소문과 난도에 맞춰 배치하고 내륙 도시 여부와 별도로 진행할 수 있게 한다.

- 항목마다 고유 ID, 분야, 발견 직후의 짧은 설명, 상세 해설, 대표 페이지나 삽화, 실제 자료 출처와 게임 내 조사 위치를 붙인다. 저술 시기와 현존 자료 제작 시기가 다르면 둘을 표시한다. 조사 위치는 내 도감에서 확인한다. 다른 선장의 도감에는 조사 위치와 퀴즈 단서를 공개하지 않는다.
- 해안에서 접근 가능한 조사 지점을 배치한다. 실제 내륙 유물은 해안·상륙 조사에서 확인하는 사본이나 관찰 기록으로 구성한다. 쉬운 항목은 자주 쓰는 항로에 두고 어려운 항목은 원양·우회 항로에 분산한다. 도감에 ‘책·기록’과 ‘자연’ 필터를 추가한다.
- 기존 72종의 ID와 발견 기록을 보존한다. 신규 30종 적용 시 총 102종이다. 수집 카드와 랭킹의 상한을 도감과 함께 갱신하고, 72종을 넘긴 뒤에도 교역 랭킹이 저장되는지 확인한다.

최종 조사점은 항로 계산을 거쳐 정한다. 기존 흔적과 동시에 팝업이 몰리는 구간은 조사 위치나 난도를 조정하고, 바닷길로 접근이 막힌 후보는 같은 소재로 접근 가능한 바다·강 관찰 지점을 지정한다. 저난도·고난도별 최소 한 건은 실제 탐험 흐름 전체를 수동으로 확인한다.

### 일일 5지선다와 난도별 보상

퀴즈는 ‘전체 도감’과 도감의 실제 분류마다 제공한다. 현재 분류는 **유적·유물·동물·보물**이다. 신규 ‘책·기록’과 ‘자연’ 분류가 열리면 각 분류에도 퀴즈를 추가한다. 선장마다 종류별로 하루 한 번씩 풀 수 있고, 한국 시간 자정에 기회가 갱신된다. 제출한 종류만 그날 기회를 사용한다.

전체 도감 퀴즈는 내 발견 목록 전체에서, 분류별 퀴즈는 해당 분류에 속하는 내 발견 목록에서 무작위로 한 항목을 뽑는다. 해당 범위에 발견 항목이 없으면 첫 발견 후 열리는 것을 안내한다. 문제는 대상 이름이 빠진 설명과 보기 다섯 개로 구성한다. 같은 날 발견물이 늘거나 기기·탭을 바꿔도 이미 열린 문제와 난도를 유지한다. 난도와 정답 보상 구간은 모든 종류에서 전체 발견 수를 기준으로 계산한다.

정답 보상은 출제 시점의 전체 발견 수에 **95.5 D를 곱한 뒤 100 D 단위로 올림**한다. 최소 정답 보상은 1,000 D다. 모든 퀴즈에 같은 계산식을 적용한다.

| 전체 발견 수 예시 | 퀴즈 한 문제당 정답 보상 |
|---:|---:|
| 1종 | 1,000 D |
| 24종 | 2,300 D |
| 37종 | 3,600 D |
| 60종 | 5,800 D |
| 84종 | 8,100 D |
| 102종 | 9,800 D |

문제 보기는 난도에 따라 같은 분류·지역·형태의 후보 비중을 높인다. 정답 보상은 난도 구간과 별개로 계산한다.

오답 보기는 정답과 같은 도감 분류의 내 발견 항목을 우선하고, 부족하면 전체 도감의 이름만 가져온다. 보기들은 서로 달라야 하며 설명에는 정답을 구별할 단서를 넣는다. 오답도 해설을 볼 수 있다. 일일 문제·제출 결과·보상 지급을 서버 날짜로 판정한다. 자정을 넘긴 옛 문제는 그날 문제를 다시 열도록 안내한다. 두 기기의 중복 제출과 재시도를 검사하고, 보상 수령 기록과 지급액을 한 번에 저장한다.

| 화면 | 표시와 행동 |
|---|---|
| 도감 첫 화면 | 전체·분류별 퀴즈에 참여 가능·완료·발견 필요 상태와 정답 보상 표시 |
| 풀이 화면 | 설명 한 단락, 이름 보기 5개, 보기 하나를 선택하면 제출 가능 |
| 정답 제출 후 | 지급 두카트, 구별 단서, 도감 상세 열기 |
| 오답 제출 후 | 고른 보기와 실제 정답을 표시하고 결정 단서 설명 |
| 이미 완료 | 같은 날 결과 다시 보기와 다음 문제까지 남은 시간 |

문제 자료에는 분야·시대·형태 태그와 난도별 설명을 작성한다. 후보가 충분하면 같은 날 다른 퀴즈에 나온 정답과 해당 종류에서 최근 3일간 나온 정답을 피한다. 서버에서 계정·한국 날짜·퀴즈 종류에 묶인 출제 ID와 제출 여부를 확인하고, 세션 변경·새로고침·재시도에도 문제와 보상을 유지한다. 지급액은 출제 때의 전체 발견 수에서 계산한다. 정답 판정 경계를 구현할 때는 현재 Firebase 저장 구조로 검증할 수 있는 부분과 별도의 서버 검증이 필요한 부분을 확인한다. 운영비를 늘리는 별도 실행 경로가 필요할 경우 구현안에 비용과 호출량을 명시한다.

## 개발 순서와 완료 기준

1. **도시와 시장** — 이전 저장에서 창고·이동 상태를 초기화하는 방법을 검증한다. 시범 3곳의 정박→육로→교역·의뢰→귀환과 창고↔선단 화물 이전을 확인한다.
2. **자동 운송** — 100상자 전량 체결, 봇짐 10회·빈 복귀 9회, 1,000상자 1회, 마지막 일부 적재, 보급 부족·창고 포화·중지·재접속·두 기기 동시 처리에서 중복 결제나 화물 유실이 없는지 확인한다.
3. **도감과 퀴즈** — 새 자료의 조사 지점에 항해로 접근하는지, 명성이 한 번만 반영되는지, 기존 72종과 102종 도감에서 랭킹이 갱신되는지 검증한다. 발견 0종·1종·75종 이상, 해당 분류의 발견물이 없을 때, 전체와 분류별 퀴즈를 같은 날 풀 때, 자정·오답·같은 종류의 동시 제출·서로 다른 종류의 동시 제출·응답 유실 재시도와 공개 도감의 위치 숨김을 확인한다.
4. **화면과 운영** — 모바일과 PC에서 이동·거래·운송을 시험한다. 도시 경로·도감 이미지·문제 자료는 정적 파일에 두고, 필요한 시장과 개인 진행만 읽는다. 운영 배포에는 점검 공지, 접속 중단, 새 버전 확인, 서버 재개 순서를 적용한다.
