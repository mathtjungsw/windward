## 1. 주점 소문과 소문노트

주점은 현재 정박한 항구에서 들을 수 있는 소문과 그 항구의 인물만 보여준다. ‘소문 1’을 누르면 선택한 이야기 하나를 열고 읽은 기록을 저장한다. 다른 항구가 선택되어 있거나 입항 전이면 해당 주점의 이용 조건을 안내한다. PC·모바일 모두 주점 옆 **소문노트** 탭에서 여러 항구의 읽은 소문을 모아 본다. 항구명, 다시 보기, 숨기기, 숨긴 목록에서 복원을 제공한다.

특수 아이템을 처음 획득하거나 부선장을 처음 고용하면 연결된 소문에 **✓ 완료**를 표시한다. 완료 표시는 일반·숨긴 목록 양쪽에서 보이며, 미완료 소문과 완료 소문에는 같은 형식의 제목과 본문을 사용한다. 소문을 여는 것과 의뢰의 납품 완료는 획득 완료와 별개로 처리한다. 완료 표시에는 보상 이름이나 소문의 종류를 표시하지 않는다.

현재 보유한 아이템, 고용 명부와 획득을 입증할 수 있는 기존 기록은 첫 적용 때 반영한다. 이미 사용해 보유량이 0이고 획득을 확인할 기록도 없는 소모품은 완료를 추정하지 않는다. 이후에는 구입·고용 성공을 저장할 때 최초 획득 식별자를 함께 기록해, 소모하거나 동행을 해제해도 완료가 유지되게 한다. 이 기록을 특수 아이템 수집 순위에도 사용한다.

**검증**은 두 항구의 소문을 읽고 주점 상세와 소문노트에 각각 무엇이 표시되는지 확인한다. 획득 직후, 전량 사용 후, 재접속, 숨기기·복원과 기존 저장 복원도 확인한다.

## 2. 하고 싶은 일로 메뉴 찾기

PC에서는 상단 도움말 가까이에, 모바일에서는 하단 **더보기**에 **메뉴 찾기**를 둔다. 정식 이름과 일상 표현, 띄어쓰기 차이를 연결한 검색 목록을 게임 파일로 제공한다. 한글 입력이 완성되면 메뉴 이름 일치, 동의어 일치, 일부 일치 순으로 결과를 표시한다. 각 결과에는 현재 기기에 맞는 메뉴 경로, 한 줄 사용법, 이용 조건과 **메뉴 열기** 버튼을 둔다.

| 검색어 예시 | 결과와 이동 |
| --- | --- |
| 특산품 거래, 물건 사기 | 교역소를 열고 정박 중인 항구에서 상품을 살 수 있다고 안내 |
| 물건 팔기, 최고가 | 화물을 열고 판매와 최고가 판매처 찾기를 각각 안내 |
| 식량 채우기, 보급 | 선박·보급을 열고 입항 후 보급할 수 있다고 안내 |
| 읽은 소문, 도감, 부선장 | 소문노트, 발견 도감, 부선장 명부의 입구를 각각 열기 |
| 조합 의뢰, 내 항구, 대포 수리 | 해당 메뉴 열기와 필요한 정박 또는 해금 조건 안내 |

메뉴 이동은 기존 화면 열기 동작을 사용한다. 거래 확정, 출항, 장비 구입 등은 해당 화면에서 플레이어가 직접 선택한다. 검색 범위는 메뉴와 기본 사용법으로 제한하고, 미발견 위치·숨겨진 소문 해답·다른 선장의 기록은 검색 목록에 넣지 않는다. 검색어는 브라우저에서 처리하며 버튼 통계에도 검색어 원문을 담지 않는다.

**검증**은 PC와 모바일에서 예시 검색어, 동의어, 검색 결과 없음, 정박 여부에 따른 안내, 키보드 이동과 뒤로 닫기를 확인한다. 메뉴 열기로 자금이나 항해 상태가 바뀌지 않아야 한다.

## 3. 소유 항구 목록과 지도 이름표

PC에서 항구 이름, 소유 선장, 지분 또는 개발 항구 유형, 기본 세율을 한 행에 담고 우측에 **지도에서 보기**를 둔다. 모바일은 항구 이름과 소유 정보를 기본 두 줄에 담고 긴 이름에는 줄바꿈을 허용한다. 버튼은 아이콘을 사용할 수 있으며 접근성 이름에는 ‘지도에서 보기’를 남기고 약 44px 터치 영역을 확보한다. 기존 안내는 짧게 줄여 새로고침 옆에 둔다.

기존 소유 목록과 공동 보급항 요약을 그대로 이용한다. 지도 버튼은 지도를 해당 위치로 이동하는 기능만 수행한다. 행 크기 변경을 위해 새로운 서버 조회를 추가할 필요가 없다.

메인 지도에서 이름표가 표시되는 소유 항구는 **마닐라(해솔 선장)** 형식으로 표기한다. 무소유·중립 항구는 항구명만 표시한다. 내 항구, 다른 선장의 항구, 개발 항구와 소유자가 있는 공동 보급항에 같은 형식을 적용한다. 소유권 자료는 소유 항구 목록과 지도에서 공유하고, 화면에 보이는 항구를 그릴 때 캐시를 사용한다. 첫 입장과 지도 이용 중 60초 간격 이내의 필요한 갱신에서만 읽고, 내 투자·개발 성공 직후에는 관련 행을 갱신한다. 지도를 움직일 때마다 서버를 조회할 필요가 없다. 긴 이름은 항구명과 소유자가 읽히도록 위치를 조정하고, 화면이 좁아 줄임표가 필요한 경우 항구 상세에서 전체 이름을 표시한다. 지도에 표시할 수 있는 항구는 기존 발견·표시 조건을 적용한다.

**검증**은 360px·390px 모바일과 PC에서 소유 항구 10곳, 긴 항구·선장 이름, 지분 100%, 개발 항구, 공동 보급항을 표시한다. 소유권 변경·무소유 전환·중립 항구, 지도에서 이름표가 겹칠 때의 배치, 지도 이동 중 요청 횟수도 확인한다.

## 4. 다른 선장의 발견 도감과 부선장 카드

**선장 목록 → 선장 상세 → 발견 도감 / 부선장**에서 볼 수 있다. 발견 도감에는 그 선장이 발견한 항목의 이름과 삽화를, 부선장에는 고용한 인물의 이름·초상화·게임 능력을 표시한다. 카드 상세에서 정확한 기본 수치와 적용 조건을 보여준다. 예를 들어 이순신 카드에는 ‘해적전 명중률 +2%p’와 ‘연안 해적전에서 반격 피해 5% 감소’를 표시한다. 능력은 게임에 포함된 인물 자료에서 읽는다. 두 화면 모두 선장 상세로 돌아가는 버튼을 둔다. 오프라인 선장은 마지막으로 확인된 저장을 사용한다. 공개 카드에는 발견 좌표·조사 지점·고용 조건·소문 해답을 담지 않는다.

개인 저장이 확정된 뒤 바뀐 발견물·부선장 식별자만 공개 수집 기록에 쓴다. 최대 발견물 60개·부선장 24개와 저장 버전, 갱신 시각을 보관한다. 본인만 자기 요약을 갱신하도록 하고, 로그인한 선장은 지정한 선장 한 명의 요약을 읽을 수 있게 한다. 명부와 개별 순위 응답에 전체 카드 목록을 싣지 않는다. 초기에는 기존 공개 요약을 만든 도구의 운영 절차를 참고해 실제 기존 저장에서 검증한 식별자로 채운다. 이관 기록이 없을 때는 ‘기록 준비 중’, 저장된 수집이 비어 있을 때는 ‘아직 모은 카드가 없어요’를 표시한다.

**검증**은 오프라인 선장, 이미 발견한 항목, 잘못된 식별자, 다른 선장에게 연속 이동했을 때 이전 응답이 늦게 도착하는 경우, 권한 위반을 확인한다. 개인 저장 전체나 위치가 카드 조회에 포함되면 실패다.

## 5. 발견물과 아이템 삽화

발견물 60종과 특수 아이템 64종을 수집 카드용 삽화로 제작한다. 유적에는 건축과 주변 풍경, 보물·유물에는 재질과 문양, 동물에는 서식지와 특징, 아이템에는 알아보기 쉬운 형태와 쓰임새를 담는다. **내 아이템** 카드에는 아이템의 효과, 적용 조건, 제한 횟수나 해리, 소모·장착 방식과 현재 적용 상태를 보여준다. 효과 문구는 실제 적용에 쓰는 기존 아이템 자료를 사용한다. 실제 문화유산과 창작 수집품은 기존 도감의 설명을 따른다. 파일은 기존 항목 식별자로 연결한다.

목록 그림은 약 192px·8~12KB, 상세 그림은 약 640px·30~60KB의 WebP를 목표로 한다. 상세 그림은 카드를 열 때만 요청하고 목록은 화면 근처 그림을 차례로 받는다. 미발견 슬롯과 항해 중 알림에는 가벼운 그림을 사용한다. 내 도감과 공개 도감은 같은 파일을 캐시한다. 124종 두 크기의 합계는 약 5~9MB로 추정하며, 목록 20장과 상세 3장의 목표 전송량은 약 0.42MB 이하다. 이미지는 GitHub Pages 파일로 제공하고 Firebase에 이미지나 이미지 데이터는 저장하지 않는다. [GitHub Pages 공식 한도](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)

**검증**은 먼저 대표 카드 8장으로 작은 화면 가독성·그림 품질·압축 크기를 확인한 뒤 124종에 적용한다. 느린 네트워크에서 항해 첫 화면이 상세 삽화를 요청하는지, 카드 재방문에 캐시를 쓰는지, 누락된 그림의 대체 표시와 실제 전송량을 확인한다.

## 6. 개별 랭킹 확대와 종합 랭킹

| 분야 | 기존 항목 | 추가 항목 |
| --- | --- | --- |
| 교역 | 무역 이익, 지금 가진 돈, 교역품 수집, 최고의 한 거래 | |
| 탐험 | 방문 도시, 지도 탐험, 명성, 도감 수집, 섬 탐험 | 상륙 탐사 완료, 희귀 발견물 |
| 선단·경영 | 선단 성장, 항구 경영 | 부선장 고용, 특수 아이템 수집 |
| 전투 | 해적 토벌, 선단 격파, 결투 승리 | |
| 협력 | | 조합 의뢰 완료, 공동 수송 완료, 해상 구조 |

상륙은 조사 후 귀환 완료 건, 희귀 발견물은 3~4단계에서 발견한 고유 항목, 부선장·아이템은 최초 획득한 고유 식별자를 센다. 조합 의뢰는 개인 의뢰 보수를 수령한 건, 공동 수송은 해당 회차에 기여하고 보수를 수령한 건, 해상 구조는 구조 선원을 항구에 인도한 건이다. 같은 정산이나 발견이 재시도될 때 한 번만 반영한다. 기존 저장의 상륙·조합·공동 수송·해상 인도 카운터와 확인 가능한 수집 기록을 초기값으로 쓴다.

**종합 계산 초기안**은 항목별 유효 실적이 있는 선장 수를 N으로 놓고, 점수를 `100 × (N - 순위 + 1) ÷ N`으로 계산한다. 10명 중 3위면 80점이다. 동점은 공동 순위와 같은 점수를 받는다. 해당 기록이 0이거나 아직 확인되지 않으면 0점이다. 시작할 때 받은 돈·방문 도시·뗏목만 있는 선장은 해당 항목의 종합 집계에서 기본값을 제외한다. 등록 선장 중 실적을 남긴 오프라인 선장도 포함한다.

각 분야는 해당 분야 개별 점수의 평균을 내고, 종합점수는 다섯 분야 평균을 각각 20%씩 반영해 계산한다. 분야의 모든 항목이 아직 전원 0점이면 그 분야는 0점이다. 공개 화면은 종합점수 소수 둘째 자리와 집계 시각을 표시하고, ‘내 순위’에서 분야와 개별 항목별 점수를 펼친다. 종합과 개별 화면에는 최대 5명을 표시한다. 5명 경계에서 동점이면 화면 순서에만 고정된 정렬 기준을 사용하며, 내 순위에는 공동 순위를 표시한다.

운영 권한을 쓰는 집계 도구가 개인 저장 대신 랭킹용 공개 요약과 소유 항구 순위 값을 읽고 결과를 만든다. 종합 상위 5명과 선장별 점수 내역을 한 번에 갱신하고, 클라이언트는 상위 5명이나 내 결과만 읽는다. 한국 시각 09:17·21:17 집계를 초기안으로 두고, 배포 때 최초 집계를 실행한다. 자동 실행은 별도 GitHub Actions 작업에 제한된 운영 자격으로 연결하는 안을 검증한다. 집계가 지연되면 직전 결과와 시각을 표시하며, 같은 도구로 수동 갱신할 수 있게 한다. [GitHub Actions 예약 실행](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)

**검증**은 공동 1위, 5위 경계, 실적이 한 명인 항목, 전원 0점, 오프라인 선장, 분야별 항목 수가 다른 경우와 실행이 끊겼다가 재시도되는 경우를 포함한다. 공개 점수 경로의 일반 선장 쓰기를 막고, 게임 클라이언트에서 전 선장 저장을 반복 조회하는 경로가 없는지 확인한다.

## 7. 모든 버튼 사용 통계

게임 버튼과 탭에 기능별 고정 식별자를 부여한다. 반복되는 항구·상품 행은 ‘항구 선택’, ‘상품 구매’처럼 같은 행동으로 모은다. 화면에 실제 나타나 활성화된 때 노출을 세고, 같은 화면을 다시 그리거나 보급 숫자가 바뀌어도 중복 노출로 세지 않는다. 키보드와 마우스·터치로 버튼을 실제 실행하면 클릭에 포함한다. 방향 패드를 길게 누르는 동작은 누르기 시작할 때 한 번만 센다. 거래·출항·의뢰처럼 완료를 확인할 수 있는 동작은 게임에서 결과가 확정된 때 완료 횟수를 남긴다.

통계에는 버튼 식별자, 노출·클릭·완료 횟수, PC/모바일 화면 구분과 집계 날짜를 사용한다. 이름·이메일·채팅·검색어나 입력 내용은 기록하지 않는다. 브라우저 저장소에 횟수를 모으고, 한국 시각 00–06·06–12·12–18·18–24시 각 구간에서 게임이 열린 상태일 때만 브라우저당 전송을 한 번 시도한다. 미전송 묶음은 다음 연결 때 우선 보내고 최근 7일분을 보관한다. 늦게 도착한 묶음의 발생일은 바꾸지 않는다.

여러 탭은 IndexedDB 트랜잭션으로 전송 구간과 묶음 식별자를 공유한다. 서버는 처음 받은 묶음을 고정하고, 전송 확인을 잃어 다시 보낼 때 같은 식별자와 내용으로 확인하도록 한다. Firebase는 로그인한 이용자의 해당 쓰기 경로, 허용한 버튼 식별자, 정수 범위와 묶음 크기를 확인한다. 사용자는 자신의 묶음 확인에 필요한 최소 경로를 읽을 수 있고, 전체 조회와 기간별 집계는 운영 권한으로 제한한다. 저장·조종·거래는 통계 응답을 기다리지 않는다. [Firebase 저장 규칙 안내](https://firebase.google.com/docs/database/security/rules-conditions)

수집한 통계는 Firebase의 게임 데이터와 구분된 경로에 저장하며, 운영 권한이 있는 환경에서 필요한 기간만 조회해 분석한다. 게임에는 통계 열람 탭이나 화면을 두지 않는다. 건당 최대 8KiB를 목표로 하고, 묶음은 서버에 30일, 일별 합계는 90일 보관하는 안을 적용 전 검증한다. 예시로 15개 브라우저가 30일 동안 매일 최대 4번 보낼 경우 묶음 최대 1,800건, 본문 약 14MiB다. 이 수치는 최대 크기를 모두 채웠을 때의 예시다.

**검증**은 게임 버튼 목록과 계측 목록의 일치, 모바일 방향 버튼 길게 누르기, 여러 탭, 날짜 경계, 브라우저 종료, 오프라인, 응답 유실, 반복 렌더링을 포함한다. 적용 전후 항해 반응과 모바일 전송량을 비교한다. 11월 10일 성능 조사에서 남은 명부·전투 화면은 같은 내용이 들어왔을 때 화면 갱신을 줄일 수 있는지 함께 측정하고, 상태 변경이나 버튼 반응을 늦추지 않는 범위에서 반영한다.

## 8. 역사 선박 9종과 해금 조건

뗏목부터 20단계까지의 기본 성장에 선종 선택을 추가한다. 각 새 선종은 표의 **최소 선박 단계와 활동 조건을 모두 달성**한 뒤 지정 조선소에서 건조할 수 있게 한다. 해금은 선장 기록에 남으며, 건조 시에는 보유 선박 한도와 비용도 확인한다. 표의 단계·횟수·효과는 초기 테스트 값이며 실제 역사적 선박의 성능으로 소개하지 않는다. [역사 자료와 선박 후보](../IMPROVEMENTS.md)

조선 의뢰 초기안은 부산에서 수락한 뒤 부산 조선소에 목재 20상자와 구리 10상자를 납품하고 지정 연안 해적 토벌 보고 1건을 마치는 흐름이다. 푸젠계 상선의 도자기 거래와 연안 해적 실적처럼 기존 저장으로 횟수를 확인하기 어려운 조건은 새 기록부터 센다. 기존 방문·의뢰·공동 수송 중 검증 가능한 실적은 자동 반영한다. 구조로 이동한 항구나 지도에서 본 항구는 정상 방문 조건에 포함하지 않는다.

조선소에 역할, 해금 진척, 건조비, 선단 편입 전후 속도·적재·보급·대포 한도를 표시한다. 가격 초기안은 같은 단계 기본선 견적의 110~130%, 거북선 145%다. 첫 도입에서는 플라위트·펠루카·판옥선·와카 호루아로 역할 차이를 비교하고, 같은 개발 범위 안에서 나머지 5종을 검증한다. 거북선은 소문부터 건조까지 전용 흐름을 확인한다. 9종 모두 선박 카드와 항해 지도에서 고유 외형을 사용한다.

선단 속도는 환경별 성능을 계산한 뒤 가장 느린 배를 기준으로 한다. 원양 제한도 선단에서 가장 좁은 한도를 항로에 적용하고, 구입 전 제한을 표시한다. 적재·보급은 기존 선단 산식을 재사용해 선종별 기여를 반영한다. 탐사 보너스와 거북선의 첫 피해 감소는 기함 한 척의 효과를 적용하며, 거북선 효과는 해당 해적전에서 한 번만 소모되도록 저장한다. 다른 대전이나 재접속에서 소모 기록이 풀리지 않도록 한다. 상세 구현에서는 미리보기·자동항해·직접 조종·해전이 같은 성능 계산을 사용하도록 연결한다.

기존 배에는 기본 선종을 부여한다. 건조·기함 변경·매각과 진행 중 의뢰 저장에 선종 식별자를 반영한다. 매각 후 화물·보급이 남은 선단 한도를 넘거나 대포 장착 제한에 걸리는 경우 기존 정리 흐름을 이용한다. 지도에서 상대 선종을 그릴 때는 허용한 선종 식별자만 기존 선단 요약에 추가한다.

**검증**은 9종의 조건 미달·달성, 의뢰 납품 중복, 기존 저장·다른 기기 재접속, 기함과 동행선 조합, 강과 원양 경로, 구입 견적과 실제 속도, 매각·장비 한도, 해적전 재접속을 포함한다. 거북선 등 건조지가 바다에서 접근 가능한지 확인한다.

## 9. 배포에 포함할 로컬 수정

- **동행선 외형.** 기함 뒤를 항적대로 줄지어 따르면서 돛대가 똑바로 보인다. 자동 항해·직접 조종과 주변 선단 동행선을 확인한다.
- **아카풀코.** 새 해안 인근 입항 좌표를 지도 표식과 항로에 함께 사용한다. 이미 아카풀코로 항해 중인 선장은 기존 진행 거리를 유지한 채 새 입항 지점까지 이어진다. 입항 판정과 저장 재개를 최종 통합 검증에 포함한다.

## 10. 작업 순서와 운영 반영

1. 주점과 소문노트, 메뉴 찾기, 소유 항구 목록을 작업하고 PC·모바일에서 클릭 흐름을 확인한다.
2. 최초 수집 기록과 공개 카드 자료, 새 랭킹의 저장·조회·종합 집계를 연결한다. 기존 기록의 이관 결과와 권한을 격리 환경에서 검증한다.
3. 선박 성능과 조건을 구현하고, 대표 삽화로 용량을 확인한 뒤 전체 카드와 선종 외형을 제작한다. 저장·거래·항해·전투 통합 테스트를 진행한다.
4. 버튼 통계 수집과 서버 보관을 연결하고, 모바일 로딩·조작 반응과 Firebase 읽기·쓰기 사용량을 비교한다. 네트워크 끊김이 게임 조작과 저장에 영향을 주는지 확인한다.
5. 운영 배포 단계에서는 공개 대문에 점검 안내와 개선 기능을 먼저 게시한다. 안내를 확인한 뒤 서버 접속을 닫고 배포와 필요한 이관을 진행한다. 새 버전과 데이터 적용을 확인한 뒤 서버를 다시 열고 입장 화면과 접속 가능 상태를 확인한다. [운영 업데이트 점검 절차](../README.md#운영-업데이트-점검-절차)
