# 새 항구 개발과 공동보급항 승격 상세계획

2026-11-17 · 개선 제안 2건 검토 결과

## 1. 첫 개척 확인창 오류 수정

- 미개발 후보지에서 확인창을 그릴 때 정의되지 않은 `s`를 초보 보호 안내에 사용한다. 이 때문에 첫 개척은 확인창과 결제 요청 전에 중단된다. 공개 버전과 같은 코드로 공동보급항이 없는 세인트존스와 공동보급항이 열린 레이캬비크 양쪽에서 재현했다.
- 확인창을 열 때 현재 선장 상태를 올바르게 읽고, 항구 조회나 화면 표시가 실패하면 후보 목록 안에서 이유를 알려준다. 첫 개척의 초보 보호 종료 안내는 해당 선장에게만 표시한다.
- 기존 기본 비용은 개척 40만 D, 교역소 확장 20만 D, 조선 확장 30만 D다. 확인창에 단계별 기본 비용, 적용할 할인, 실제 결제액을 표시한다. 확정 때 위치·정지 여부·물길·소유자·개발 단계·잔액을 다시 검사한다. 견적이나 단계가 바뀌면 갱신된 조건을 보여주고 재확정하게 한다.
- 두카트 차감, 개발 단계 변경, 항구 등록은 기존 원자 저장을 사용한다. 저장 확인 뒤 성공으로 표시하고, 첫 개척 후 새 항구의 지도 위치와 입항 방법을 보여준다. 서버 응답이 끊겼을 때는 실제 저장 결과를 확인할 수 있게 하고 재시도로 비용이 두 번 나가지 않게 한다.

## 2. 후보지 접근과 화면 안내

- 후보 목록에 `레이캬비크 정식 항구 후보지`와 `레이캬비크 공동보급항`처럼 시설 종류를 함께 표시한다. 현재 위치에서 정식 항구 후보지까지의 거리와 개발 범위 10해리를 보여주고 `지도에서 보기`를 제공한다. 예를 들어 14.2해리 거리라면 `개발 범위까지 4.2해리`를 표시한다. 거리 표시의 반올림과 활성화 판정이 상충할 때는 정확한 판정 결과를 우선한다.
- 항해 중이면 정지, 육지나 다른 물길이 막고 있으면 후보지 앞 수역으로 접근하도록 안내한다. 범위·정지·물길 검사는 목록과 확인 단계에서 공유한다. 소유자·잔액처럼 최신 조회가 필요한 조건은 확인창에서 구체적으로 안내한다.
- 공동보급항 화면에 `정식 항구 후보지 보기`를 추가해 정박 중에도 위치를 확인할 수 있게 한다. 지도 보기만으로 배가 이동하거나 비용이 차감되지는 않는다. 현재 대응 후보 6쌍은 약 14~21해리 떨어져 있다.
- PC와 모바일에서 버튼으로 접근할 수 있게 하고, 좁은 화면에서는 시설 상태와 이용 가능한 행동을 같은 행에서 읽을 수 있게 한다. 위치·거리 표시는 지도 데이터와 현재 좌표를 사용한다. 후보마다 서버를 반복 조회하지 않는다.

## 3. 공동보급항을 정식 항구로 승격하는 추천안

| 항목 | 추천 규칙 |
| --- | --- |
| 승격 대상 | 대응하는 정식 항구가 아직 개발되지 않은 완공 공동보급항. 두 시설이 이미 운영 중이면 각각 계속 운영한다. |
| 위치와 항구 ID | 기존 공동보급항의 부두와 항구 ID를 유지한다. 같은 도시의 별도 후보지는 승격 확정 시 개발 대상에서 제외한다. |
| 동의 | 기존 현금 투자 지분의 50%를 초과하는 동의가 필요하다. 과반 투자자가 한 명이면 그 선장이 확정할 수 있다. 과반 투자자가 없으면 여러 투자자의 동의를 합산한다. 지분 기준은 기존 공동보급항 원장과 동일하게 적용한다. |
| 승격비 | 기본 추천 10만 D. 공동보급항 기본 건설비 30만 D와 신규 개척비 40만 D의 차액을 적용한다. 확정 선장이 납부하며 이 비용으로 지분율을 바꾸지 않는다. 기존 할인과의 중복 적용은 초기 범위에서 제외한다. |
| 개항 단계 | 승격 즉시 개발 1단계를 적용한다. 기존 공동보급 서비스는 계속 제공하며 교역소는 2단계, 조선은 3단계에서 연다. 기존 공동 납품으로 이미 해금한 상품은 유지한다. |
| 지분과 정산 | 기존 투자 원장, 투자자 몫, 창고 재고, 납품 실적, 미수령 수익을 보존한다. 승격 후 새 시설에서 발생한 배분 대상 세수도 기존 지분 비율을 사용한다. 기존 공동 보급 수익과 새 교역 세수를 구분해 같은 수입이 중복 지급되지 않게 한다. |

- 공동보급항 화면에 `정식 항구 승격`을 두고, 승격 조건·동의 지분율·납부액·열릴 서비스를 확인한 뒤 확정한다. 납부는 한 번에 하며, 확정 직전에 동의 지분과 비용, 별도 후보지의 개척 여부를 다시 확인한다.
- 승격 뒤 2·3단계 공사는 같은 과반 지분 동의 절차와 해당 단계의 개발 비용을 사용한다. 이미 승격한 항구의 공동보급 잔액과 수익 수령 메뉴는 계속 접근할 수 있게 한다. 수동 징수와 세금 징수선이 같은 몫을 중복 지급하지 않는지 확인한다.
- 항해 중인 목적지와 현재 정박 상태, 방문·발견·즐겨찾기·항해 일지는 기존 항구 ID로 이어간다. 아직 별도 후보지에 도착하지 않은 자동 항로가 승격 중 영향을 받으면 현재 상태를 보존하며 새 목적지를 확인하도록 안내한다. 승격으로 방문도시 수나 발견 보상을 다시 지급하지 않는다.
- 운영 서버에서 확인한 첫 적용 검증 대상은 레이캬비크와 모가디슈다. 기존 항구를 읽은 로컬 테스트 사본에서 여러 투자자·미수령 수익·남은 재고를 확인한다. 실제 항구 승격은 게임 안의 동의와 결제로 진행한다.

## 4. 구현 순서와 검증 기준

1. **오류 수정과 접근 안내.** 일반 후보지와 공동보급항 인근 후보지에서 첫 확인창이 열리는지 확인한다. 10해리 경계, 육지 사이, 이동 중, 잔액 부족, 타인 소유에서 정확한 이유를 표시한다. 첫 개발, 기존 항구 확장, 초보 보호 안내, 결제 재시도와 새로고침 뒤 결과를 검증한다.
2. **승격 상태와 저장.** 기존 프로젝트 원장을 지분·공동보급의 기준으로 유지하고, 정식 항구의 단계와 기능만 연결한다. 일반 개척과 승격이 동시에 같은 도시에서 시작되면 하나만 확정되도록 한다. 지분 동의·납부·개발 상태·지도 등록을 한 단위로 저장하고, 테스트용 Firebase에서 권한 없는 요청, 동시 요청, 네트워크 응답 유실과 양쪽 정산을 검증한다.
3. **기존 기록 호환.** 과반 없음, 정확히 50%, 50% 초과, 여러 선장 동의, 별도 항구가 이미 개발된 상태를 확인한다. 승격 전후에 재고, 지분, 납품 진행도, 미수령 수익, 현재 정박·항로를 대조한다. 운영 데이터 전체를 다시 쓰는 방식은 피한다.
4. **화면과 배포.** PC·모바일 테스트 뒤 게임 설명서와 업데이트 안내를 갱신한다. 배포 시 대문에 점검 및 변경 내용을 안내하고, 서버를 잠시 닫아 적용한 뒤 입장 허용 상태를 확인한다. 제보 글은 오류 수정과 승격 기능의 실제 적용 범위에 맞춰 완료 처리한다.

반영 버전 `2026.11.17-harbor-development`에는 과반 동의, 승격비 10만 D, 확정 선장 납부 방식을 적용했다. 이미 운영 중인 공동보급항은 게임에서 투자자 동의와 정박 후 결제를 거쳐 승격한다.
